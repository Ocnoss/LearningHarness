# 模型作答（按钮名「AI模型作答」）· 接入设计

- **状态**：设计已定，**未实施**
- **日期**：2026-10-14
- **作者决定**：按钮名「AI模型作答」；插件名 `@lh/model-attempts`；**作为独立插件**；**采用新开会话**
- **依据**：ADR-004/005（提示词是愿望、钩子是保证）· ADR-009（注解是一等资源）· ADR-012/014（唯一事实源、可派生的不进日志）· ADR-017/018（题目=资源、作答=事件、按 source 分组不混算）· ADR-035/037（判断归 agent、机械动作归界面）· ADR-038（部分正确、作答者型号）

## 0. 命名与既定决定

| 项 | 决定 | 为什么 |
|---|---|---|
| 按钮 | **「AI模型作答」** | 面向外行的说法；「模型作答」对外行也偏术语 |
| 功能/文档 | **「模型作答」** | **不叫"模拟"**——不存在"模拟事件"这种东西：模型作答是**真发生**的（真花钱、真模型、真时刻），只是**作答者**不是学习者 |
| 插件 | **`@lh/model-attempts`** | 与 `@lh/question-bank`、`@lh/practice` 同形；作答的领域词就是 attempt |
| 执行 | **新开会话**（一次模型作答 = 一个会话） | 作者 2026-10-14 决定 |
| 标记 | **不给作答打 `simulated`** | 既然没有"模拟事件"，就没有"标记它是模拟"的必要；产生它的**指令**是**请求**上的元数据 |

> 这一条命名决定**删掉了一个概念**，而不是换了个说法：面板那一列已经叫**「作答者」**（取值「用户」或某个型号），于是"模型作答"= 把作答者换成模型的**同一件事**。

## 1. 接入方式（三层，能力与动线分离）

```
@lh/question-bank-ui   勾选题目 → 写一条请求 → 显示进度与结果
   （只读 + 机械动作）   永不获得 spawn / 模型调用能力（最小权限）
        ↓  data/model-attempts-request.json（原子替换）
@lh/model-attempts     读请求 → 用**指定模型新开会话** → 逐题/批量作答
   （新包，可拆装）      落盘复用 @lh/question-bank 的同一份 recordAttempt
        ↓  lh/user/attempt（source: llm + model）
@lh/question-bank-ui   照旧只读显示（作答者列显示型号）
```

**为什么面板不能自己执行**（两条，缺一不可）：

1. **技术上不通**：`subagents.start(request)` 要 `parent: Agent`，而 `ctx.agents.currentInitiator()` 只在 **agent 发起的异步链**里有效——插件在 HTTP 路由或定时器里没有发起者 Agent。
2. **权限上不该**：面板现在只需要 `['webServer', 'sessionProjections']`。给它 spawn 能力 = 让一个**只读查看器**能生成事实。那么"这个面板显示的数据里，有一部分是它自己造的"就解释不清了——这是**可信度**问题，不只是结构问题。

**接口就是请求文件**：与 `@lh/practice` 用 `practice-signal.json` 协调"对话 ↔ 面板"是同一种形态（项目已有先例）。接口模块（纯函数）放新插件，面板只 `import` 它来拼请求——**import 纯函数不带来任何能力**。

## 2. 已核实的宿主契约（2026-10-14 只读查证，非推测）

**能力存在，且项目内已有先例**：`plugins/lh-question-bank/index.js` 写着
`export const inject = ['tools', 'subagents']`，注释注明"dsh-base 无 isolate 地挂了 subagent 注册表，故 root realm 全局可 inject（已核源码）"，`import_questions_from_source` 就是这么 spawn 子 agent 的；取用方式是 `ctx.subagents ?? ctx.get('subagents')`（带降级）。

| 契约 | 原文要点 | 对设计的意义 |
|---|---|---|
| `AgentOptions` | `{ provider?, model?, reasoningEffort?, maxTokens? }` | **选模型就是这里** |
| `SubagentStartRequest` | `{ prompt, parent, agentOptions?, outputSchema?, toolFilter?, persona?, maxDepth?, label?, signal }` | **一轮**模式：`prompt` + `outputSchema`；`toolFilter` 可以只给它 `record_attempt` |
| `SubagentResult` | `{ output, structured?, diagnostic?, stopReason }` | 一轮的结构化结果在 `structured` |
| `startContinuable(spec)` | → `{ childId, messageId }` | **多轮**模式：可继续的子会话 |
| `subagents.prompt`（@Remote） | 投递一条消息给 continuable 子会话 | 面板/插件可**追问**、可分批推进 |
| `listChildren` / `listDescendants` | 列出子会话（不加载 Agent） | 能看到"跑到哪了" |
| `SubagentCapabilities.agentOptions` | `boolean` | 支不支持指定模型**取决于 provider 的能力位**（要查，不要假设） |
| `agents.create(options)` / `agentLoop.create(id, options, meta)` | 造独立 Agent，`AgentOptions` 带 model | **新开会话**的正路（不需要父 Agent） |

## 3. 实施难点（8 条，都带"怎么知道的 / 失效信号"）

1. **上下文不是靠"编排"解决的，是靠"不塞"解决的。**
   做题最小闭环是「拿一题 → 答 → 记」；题库**从来不进提示词**（题干是**工具返回**，可分页、也能被宿主 `toolResultPruner` 修剪）。
   真正的窗口杀手是**揭示了答案与解析的工具返回**：每题几百字，做完 100 题就是十万字级的累积。

2. **真正的轴是「一轮 vs 多轮」，不是「盲答 vs 揭示」。**
   - 一轮（`start` + `outputSchema`）：1 次调用、结构化返回、**便宜**、**天然无污染**（上一题的答案根本不在上下文里）；约束是"一批 N 道题干之和"。
   - 多轮（`startContinuable`）：N 次往返、可追问/可中断/有过程；代价是上下文累积（宿主有 `compaction` + `toolResultPruner` 兜着）。
   - **两者都该有，名字要分开**：一轮 = 测水平/批量出数据；多轮 = 模拟一个真实学习者慢慢做。

3. **"盲答 vs 揭示"只在多轮里存在。** 一轮模式下压根没有揭示这回事（答案是一次性输出），所以这个纠结自动降级成一个**参数**。

4. **批次大小是同一个旋钮**（既管窗口、也管成本）。硬上限建议默认 **20 题**；并且**在执行前就把成本摆在按钮上**——宿主有 `tokenMeter.estimateMessage`，可以显示"约 N 次模型调用 / 约 X tokens"。

5. **选题策略必须"说出来能解释"**（做题数 < 题库数时，不能是"随机抽"）：

   | 策略 | 用途 |
   |---|---|
   | 手选（筛选 + 勾选） | 单选与全选**同一机制**：筛选即选择；「选中本页」/「选中当前筛选结果」 |
   | 错题优先（最近一次错） | 最高价值（现状 9 道错题、8 道最近仍错） |
   | 未作答优先 | 摸底 |
   | 最久未碰（间隔重复） | 复习排期，真实的学习节奏 |
   | 知识点覆盖（每知识点抽 N） | 测广度而不是运气 |
   | 顺序 / 随机（可复现 seed） | 回归夹具 |

   ⚠ **不要另写一套**：`start_practice` 已有 `selection` 参数，模型作答要用**同一份代码**，否则"模拟"测不出真实刷题体验。策略**必须显示出来**（"这 20 道按「错题优先」选"），否则那批数据事后没人能解释。

6. **指令是愿望，不是保证**（ADR-004/005）。
   "要求写备注""要求解释原因"基本可靠；**"要求错 8 道"模型可能为了满足它而故意答错**——那批数据不再是"模型水平"，而是"按指令表演"。这不是错，但**指令原文必须跟着数据留着**（进上下文 + 面板显示），否则将来没人知道它是怎么来的。
   要**确定**的错题数，只能靠脚本构造（不调模型），那是另一条路。

7. **复合题（大题多小题）是 schema 问题，不是 UI 问题。**
   材料必须**只出现一次**（否则重复 N 遍）；**选择单位应是「题组」（材料 + 小题）**，勾了一道小题却不给材料等于没给。现在题库 schema **没有 group/material 字段** → **留概念（选择集里存组 id）、不做实现**。

8. **面板不能自己执行**（见 §1 两条：技术上不通 + 权限上不该）。

## 4. 实施细节（给实现时的手册）

**请求字段**（`data/model-attempts-request.json`，原子替换；未发生的意图**不进事件日志**，ADR-014）：

```
{ bank_name, count, selection: {strategy, ids?}, mode: 'one-shot'|'multi-turn',
  model: { provider, model }, instruction, requested_by, requested_at }
```

**作答落盘**：调 `@lh/question-bank` 的**同一份** `recordAttempt`，`source: 'llm'`、`model` 填真实型号、`note` 填当场思路 → **与真实作答完全同形**（形状一致是这件事的全部意义：否则"模拟"测不到真实链路）。

**备注 = 定制化输出通道**：标准化输出由工具 schema 兜住（作答内容/对错/分数/型号），定制要求落在 `note`。
例如"做对这些题，并选出你认为**最容易被错选**的答案写在备注里、解释原因"——**不需要新功能**，它就是一句指令 + 一个 `note` 字段。这也是先做"答题时写备注"的回报。

**界面**：按钮「AI模型作答」长在**题库管理面板**（动线不分离），能力在新插件（职责分离）。面板只写请求 + 显示进度。

**命名**（一次性清干净，趁旧名零提交）：

| 旧（WIP，已 stash） | 新 |
|---|---|
| 「模拟做题」/「模拟作答器」 | 「模型作答」 |
| 按钮「让模型做一遍…」 | **「AI模型作答」** |
| `data/sim-request.json` | `data/model-attempts-request.json` |
| 工具 `clear_sim_request` | `clear_model_attempt_request` |
| 上下文 `lh:sim-request` | `lh:model-attempt-request` |
| `plugins/lh-question-bank/sim.js` | `plugins/lh-model-attempts/request.js`（两插件共用接口） |

> ADR-038 里"留着与'模拟作答器'一起做"那句是**历史记录，不改**（项目纪律：ADR 不改写）；新文档一律叫「模型作答」。
