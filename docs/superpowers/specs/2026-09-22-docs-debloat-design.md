# 文档瘦身整治设计（2026-09-22）

## 背景

项目开发中由 agent 依据 WORKFLOW/ARCHITECTURE 等元文档新建了大量补充文档，未经作者严格审查。结果：文档通胀、重复甚至矛盾，协作效率随项目规模下降，agent 开始输出作者看不懂的行话。

## 目标

- 文档体系只保留「活文档」：会被未来 agent 实际加载、且作者能读懂。
- 其余全部归档不删，agent 不加载。
- 把整治中得到的 agent coding 经验写回 WORKFLOW.md，防止通胀复发。

## 决定

### 1. 目标结构

```
docs/
├── ARCHITECTURE.md       ← 活文档，重写瘦身
├── WORKFLOW.md           ← 活文档，重写瘦身 + 防通胀条款
├── COLLABORATOR_MODEL.md ← 活文档，重写瘦身
└── archive/              ← 只归档，不删除，agent 不加载
    ├── decisions/        ← 34 条 ADR 原样移入
    ├── experience/       ← 14 篇经验原样移入
    ├── PLUGIN_CONTRACT.md    ← 契约归宿主（dsh/cordis），注明出处后归档
    └── HANDOFF-lh-practice启动事故.md
```

- `skills-draft/` 不动（草稿，非通胀来源）。
- PLUGIN_CONTRACT.md 不归作者约定，归档并在 ARCHITECTURE 中注明契约出处。

### 2. 活文档重写验收标准

每份按同一标准重写：**一个不具备本项目上下文的 agent 读完能直接干活，且作者能读懂。**

- 砍重复：三份之间重叠内容只在一处说，其余改一句话引用；
- 解矛盾：以「代码现状 + 冻结 ADR」为准，矛盾处显式写明谁赢；
- 压篇幅：每份目标 100 行以内（当前 225 / 249 / 229 行）；
- 灭行话：术语集中放 ARCHITECTURE 开头一处，正文不再发明新词。

### 3. WORKFLOW.md 防通胀新条款

- **ADR 触发条件收窄**：只有「推翻/修订一条已冻结决策」或「改变活文档里已写下的承诺」才写 ADR；其余承重决策直接改活文档对应段落，不再单独立档。
- **新建文档需自证**：agent 新建任何文档前必须先回答「这份信息为什么不能并进现有文档」；答不出就默认不该建。

### 4. 执行方式

- 归档移动直接执行（git mv，可回滚）。
- 三份活文档的重写：子代理通读全部 ADR 与 experience 提取仍然成立的结论作为素材，起草重写稿；**最终定稿由作者过目**（「你能读懂」只有作者能验收）。

## 不做的事（YAGNI）

- 不删除任何现有文档（只归档）。
- 不改代码、不改 skills-draft/。
- 不为 archive/ 建索引或 README（git 与文件名即索引）。

## 失效信号

- 整治后一个月内 agent 又新建了未被作者要求的文档；
- 三份活文档任一份被作者评价为「读不懂」或「没变薄」。
