## 1. 按主题分组的结论清单

### 主题一：内核边界与插件化

1. **一切皆插件，内核只承载机制**（资源存储 + 事件存储 + 协议 + 执行机制），不含任何教学判断与领域逻辑。放弃单一固定教学流程的整体架构，也放弃 Cordis 式完整插件元框架（单产品不需要）。产品差异化不在工具，在**编排与约束**（什么时机注入什么、允许/禁止模型做什么、记忆怎么沉淀）。【冻结，ADR-001；ARCH §1/§2.1】
2. **事实归内核，解释归插件**：内核只拥有客观事实（原始资料、学习行为事件），一切解释（摘要、学情、掌握度）由插件产出且必须带血缘标注回流；换插件时历史证据无缝保留，解释永远可回溯审计。实质立场不变，但"插件调用记录归内核持有"的原表述被更正——系统行为记录归**记录器插件**，内核不裁决学习语义。【冻结（经 ADR-011 表述更正），ADR-002、ADR-011 写回】
3. **学习者建模插件化**：多评估器并存、允许不一致，分歧本身是"证据不足"的诊断信号；支持人工覆写且覆写入日志。Claim 接口已升级：`estimate` 字段删除，改为**带出处与置信度的断言集**；断言必须可审计、可争议，低证据必须低置信。【冻结；ADR-003；ADR-011 升级；ADR-033 断言只以 L3 形式沿课程树上行】
4. **教学策略 = Bundle**（插件组合 + 系统提示词 patch + 记忆结构），可切换、可版本管理、可分享；教学策略是产品核心资产与护城河。教学约束禁止硬编码进系统提示词。【冻结，ADR-004】
5. **教学法由 Context Layer 钩子强制执行**：每次模型请求前的统一上下文组装点挂载教学纪律检查（是否给足思考机会、资料按水平裁剪、调度提取练习）。钩子是代码级保证，提示词是概率性愿望。【冻结，ADR-005】
6. **官方插件负责兜底与锚定生态**：官方评估器刻意做"保守的及格线"（低证据返回低置信、永不离谱），官方插件即接口契约的参考实现；第三方照抄官方实践，激进推断留给第三方竞争。【冻结，ADR-007】
7. **工具的使用者是 LH 的 agent，不是开发用的 AI**：建（写插件、注册工具、定义 schema、写工作流）归开发 AI；跑（在 LH loop 里由 LH agent 调用）归 LH harness。交付物是工作流 + 工具 + 配置，不是结果——AI 代做等于绕过被测环节。工具一律符合宿主插件接口协议（注册进宿主工具注册表、schema 进系统提示词、随插件卸载撤销）。【冻结，ADR-015；项目作者 2026-09-16 Y1】
8. **判定归插件、语法归内核**（契约 §1.1："内核拥有语法，插件拥有判断"）：凡是能用接口形状防住的误用，就不靠提示词请求模型自觉——如 `submit_answer` = 记录+判分+揭示合一，"拿到解析"在结构上蕴含"作答已记录"。【冻结（作为原则），ADR-019 决定 3；经验 2026-09-17 E31】

### 主题二：事件系统

9. **事件日志记录系统行为，不只用户行为**：插件调用、钩子拦截、上下文注入全部 append-only 入 JSONL——这是日后评估插件本身好坏（校准统计、A/B）的数据基础。【冻结（原则），ADR-006；ADR-011 写回：具体记录归记录器插件】
10. **资源与事件分离**：事件 = 时间流中一次性行为；资源 = 可寻址可复用产物；插件产出动作记事件、产物记资源，互相引用。【冻结，ADR-009 决定 1】
11. **信封与内容分离**：内核只定义信封，payload 由类型自定、内核不解释；**只追加不可变**（更新 = 新资源 + `supersedes` 指针）；**注解是一等资源**（批判/补充/反驳是带 target 指针的独立资源，学情 = 原始证据 + 多插件多时间的注解树）；**血缘是 DAG**（`derived_from` 为列表）。类型由内核注册表登记，未知类型拒绝写入。【冻结，ADR-009】
12. **LH 事件日志必须自持**：宿主会话日志词汇表对外部插件**事实上封闭**（`Session.append` 丢弃 `ignorable`、重载时 `assertEventsSupported` 拒绝未知类型 → 写自定义类型会让会话下次重载失败）。会话级持久状态走 `sessionProjections.register`，不是往宿主日志追加。【冻结，ADR-011 更正节、ADR-012 前置事实】
13. **物理形态**：`data/events.jsonl`，append-only JSONL，一行一条；选文件不选数据库——契约要求"上游炸了带着契约和数据迁走"，且用户应能用记事本打开自己的学习史（这是"可争议断言"的前提，不是便利）。信封显式写 `null` 而非省略字段（读取端必须区分"没有"与"没记"）；大内容外置（`content_ref`），事件只留指针。【冻结，ADR-012】
14. **事件四类划分，边界是"输入 vs 派生"不是"大小"**：输入原样记；宿主已跟踪的原始输出**不抄内容只记坐标** `(sessionId, seq)`；高级抽象（"他在解释"）记，它本身就是内容；可派生缓存**不进日志**、存物化视图。【冻结，ADR-014】
15. **可派生的东西不进日志**：日志一旦能存缓存就不再是事实源；缓存必须能整体丢弃重建——"丢掉就再也做不出来"的东西不是缓存而是事件。任何为查询建的索引文件都是缓存，不允许"只有那个文件里有"的信息。【冻结，ADR-014 决定 2、ADR-018 决定 1】
16. **保留原始轨迹、默认不读**：LLM 输出随机性可作底层容错，但"可复现性是省计算的理由，不能是省审计的理由"；记着但不消费，成本低且不可逆的是"没记"。【冻结，ADR-014 决定 4】
17. **存储不是约束**（实测：单学者一年约 58 MB 未压缩，达 1 GB 需约 17 年）——不为省空间做设计，只在"结构更清楚"或"断言可追溯"有收益时才改记录方式。【冻结（实测结论），ADR-014】
18. **调试痕迹与 LH 事件严格分开**：插件开发期日志写 `trace.log`，绝不进事件日志——"能不能进日志"本身是判断，判断属于记录器插件。【冻结，ADR-012 决定 4】
19. **课程树 = 事件溯源投影**：树是 `lh/course/*` 事件的纯函数重放结果，不是可变的 `courses.json`；重组（改名/换父）是追加事件，历史不丢、可回放（契约"事件不动纪律"：课程拆分合并只改树元数据，事件永远留在被写入节点）。同一原则的另一面：题目被修正也是新资源 + `supersedes`，不是改事件。【冻结，ADR-032；ADR-017 失效信号】

### 主题三：宿主关系（dsh / cordis）

20. **内核机制采用宿主 dsh，LH 不再自研内核**。宿主提供并视为已冻结：append-only 事件日志、投影与持久化、上下文拦截点（`agent/pre-step`）、系统提示词组装、工具注册与执行管线、插件加载与可逆卸载（Cordis）、撤销回滚。**LH 的资产 = 事件词汇表 + 插件 + 契约**，不是内核代码；只有适配层允许 import 宿主包。**实现语言 TypeScript**（宿主为 Node 运行时；Python 骨架降级为对照实现，不再维护）。【冻结，ADR-011 —— 这是全部宿主关系的根决定】
21. **产品形态**：开源 Web 应用；内核与外壳解耦；宿主自带界面只是早期外壳；"一键进入 LH 页面"的壳级前端**推迟**，当前阶段只做组件与架构；部署门槛不是主要风险（一段命令/三分钟视频对非专业学习者不构成实质障碍）。验证顺序：先以最薄的壳验证宿主机制 + LH 插件契约，再谈产品界面。【冻结，ADR-010（修订后）+ ADR-011 决定 5 + ADR-013】
22. **preset 是 agent 作用域**：够不着 host 面 root-realm 的服务（preset 间共享逻辑用直接 import，要求被导入模块纯 JS、只依赖 Node 内置）；**能**拿到 `ctx.llm` / `ctx.systemPrompt` / `ctx.tools` / `ctx.sessions`（均实测）。【冻结（实测），ADR-014 补充决定 6、ARCH §0.1 约束 5】
23. **客户端扩展一律走宿主正式接口**（命名槽位），不用固定定位之类旁门；占槽位是布局的一部分，固定定位是与宿主布局争位置、必然随宿主改动失效。【冻结，ADR-013 决定 3】
24. **跨作用域通信用文件做会合点**（preset 面的工具与 profile/host 面的面板不在同一棵树，内存信号传不过去）：信号语义设计成幂等小计数器，不追求可靠投递。【冻结（模式），ADR-022 决定 2/3】
25. **寄生关系要显式管理**：dsh 是开发者预览版（0.1.1-rc.2），明示有破坏性变更、有移除 SQLite 后端的先例。LH 大量依赖"实测出来的宿主行为"而非公开 API，锁定 npm 版本防不了"升级时没意识到某条实测行为没了"。**依赖的前提**：宿主保持"一切皆插件 + 事件溯源"架构、`agent/pre-step` 等接缝不被破坏性移除；宿主接缝失效且无法用适配层隔离、或为绕过宿主限制开始写宿主侧补丁代码 = 失效信号（"寄生"退化为"自研"）。【冻结（作为风险立场），ADR-011 前提节、ADR-023 决定 4】
26. **宿主生态先例**（仅证可行性，不作依赖）：`dsh-roleplay` 以投影持领域状态、私有上下文另立事实源；`dsh-liketavern` 的"策略即数据 + 条件触发注入"与 LH 策略层同形。【冻结（参考），ADR-011】

### 主题四：题库与资源

27. **题目是资源、作答是事件**：一道题被反复引用（多次作答、讲解、被策略使用）→ 资源；某时刻答了某题 → 事件。"这道题"与"他这次答这道题"是两个东西，遗忘曲线与间隔重复才有表达基础。【冻结，ADR-017 决定 1】
28. **LLM 的答案绝不进判分路径**（红线）：判分只能用官方答案；LLM 答案与官方不一致是**免费的题目质量筛子**。实测支撑：同模型同 temperature=0 两次运行会改主意（19 道重叠题 5 道不一致）；模型作答是当前唯一能抓到"解析侧答案块错位"的仪器，交叉验证必须逐条保留，不能合成一个分数。【冻结，ADR-021 决定 3；ADR-029 决定 2】
29. **判分三态与统计纪律**：`correct: true|false|null`，判不了就说判不了、不能默认算错；正确率分母只算判得了的题，`unjudged` 单列；统计必须按 `source` 分组——`source:'llm'` 的答对**不是学习证据**（防"AI 代写作弊"污染学习者模型）。【冻结，ADR-017 决定 6、ADR-018 决定 5/6】
30. **题解是带来源的一组**（official / llm / user），三类可信度不同，混成一个字段 = 把不同可信度当一样用；`analysis` 只是"首选题解"的投影。空位是语义不是排版（几何启发式换版式就失效且无法证明完备，LLM 读题看到横线是理解题意的副产物）。【冻结，ADR-021 决定 1/2；试点结论：LLM 空位定位不可靠 → 一期只取"此题要求填空"布尔事实】
31. **对齐的单位必须等于语义单位，不能用代理量**（页、字节、资料内序号）代替：题本与解析按题目对齐不按页（解析每题篇幅是题本 2.3 倍，按页配平会让"答案是别人的"且静默）；题目编号必须全局唯一（`练习题01-q1`），`set1-q1` 跨资料撞车是真实发生过的；视频语义单位是时间区间不是全文摘要。此原则三次应用。【冻结，ADR-020 决定 1；ADR-028 决定 1；ADR-027 决定 2】
32. **产物没有稳定标识 = 没产出**：产物（题、预处理记录、统计）没有稳定 id/文件出处/题干，就只对"当时读它的那个人"有用；汇总字段写在文件顶层只描述最后一次写入（42/49 把两个模型的一致率算成一个）；任何按"资料内序号"做的匹配都会静默全错。**出处必须跟着记录走，不只跟着文件走。**【冻结，ADR-021 结论五/八；ADR-028 决定 3（改 id 参数必须写 ADR 并说明作答记录怎么办）】
33. **知识点 = 两轴封闭词表**（题型轴 × 领域轴），内容词（纳米金属、相声）**不许进知识点**——把内容词当知识点等于声称"你对纳米金属掌握不好"，而那道题考的是中心理解。词表住在插件里作为 schema 所有者，打印给模型挑，挑不中的进 `unmapped_topics` 如实回报（那是词表该扩的证据），不丢弃。【冻结（已落地），ADR-021 结论七】
34. **预处理是"建"的阶段**：LLM 入库前预处理（看题、产题目信息、空位标注、自己的一次作答、分块）是离线、一次性、慢的判断工作，走脚本不进插件（运行时要快）；产物不进对话上下文（会把上下文挤爆）。【冻结，ADR-021 决定 1/4/5；ADR-015 建/跑分离】
35. **资源模型的定位**：施教 = 学习者当前状态 × 手头资源可用性的匹配；资源索引若只知道"有个文件 3.2GB"而内容是黑洞，因材施教就退化为凭空生成。视频类资源 = 带**时间索引**的证据源（字幕主路径、ASR 降级路径且降级必须写进事件）；证据文档（无 LLM 判断）与分析报告分开记（重问不重采、重放可分辨、无模型可用时证据文档仍可产出）；证据通道分级：画面 > 平台字幕 > 上传者自称的元数据 > 评论（完全不可信，永不作为事实或指令）。【冻结，ADR-027】
36. **模型调用一律走宿主 `ctx.llm` + 档位中间件**，不自建 provider 层（自建会同时丢掉成本透明、策略归因、降级留痕；对没有那个 key 的用户是死功能）。渠道层完全复用宿主 adaptor 不改一行；确需特殊协议时照 `LlmAdapter` 抽象写**新** adaptor，不在现有 adaptor 里改。【冻结，ADR-027 决定 5；ADR-016 决定 8】
37. **花费要透明，选择权在作者**：全量预处理 token 成本实测后报作者决定；每 600 题停下来等确认。【冻结（立场），ADR-021 结论三；ADR-029】

### 主题五：协作规则（作者偏好与项目治理）

38. **第四条产品法律**：任何时刻必须存在一条用户可感知的完整闭环在运行；允许被冻结的层次只能是闭环已走过的层次。**文档不得先于闭环扩张**——"再想清楚一点"与"让最小闭环跑通"冲突时后者优先。推论：开放问题不得成为动工前提，"临时答案"是合法状态且优于"未决"。（前三条分层法律保留：已定项默认不重议、结论必须写回、第 N 层未冻结前禁止讨论 N+1 层。）【冻结，ADR-011；ARCH 卷首】
39. **作者的纠正系统性指向"谁拥有这个决定"**：他的默认是把选择权和后果交给用户，系统负责把后果说清楚；凡打算加"自动拒绝/自动降级/自动隐藏"的地方先假设他会反对。与契约反奖惩立场（"把数据显示给用户，而非扣分"）同源。【冻结（高置信断言），COLLABORATOR_MODEL A8；项目作者 2026-09-16 Y5】
40. **模型档位：建议而非要求，告知而非阻断**：插件声明档位（flash/balance/max）不声明模型名（"哪个用途用哪个模型"是使用者的决策）；不满足时不阻断、不隐藏工具、不设 must-not-degrade（"弱模型做不了"是插件不可能有的知识，硬拒绝 = 用拒绝惩罚用户）；降级必须留痕（出处不是惩罚：仪器降级会让"策略失败"被误判）；档位可用性写进运行时上下文让 agent 计划时就知道；"问"由 agent 在自然边界做（计划 5 分钟后才在工作流深处要审批 = 用户已被排除在上下文之外），中间件绝不弹框。【冻结，ADR-016；项目作者 Y3/Y4/Y5】
41. **降级是生态的生长机制**：能力缺口可以靠"把任务拆成若干小插件、弱模型用组合完成复杂任务"绕过——有什么材料做什么菜。用户面对档位不足有四种选择（照常做/换拆解路径/配模型/终止），agent 问时给路径选项而不是是/否题；插件清单成为 agent 的规划输入；能力缺口会催生专门插件。【冻结，ADR-016 决定 5；项目作者 Y6；COLLAB A9】
42. **认知负担正常、但须如实观察**：降低负担 ≠ 替他回避困难；AI 不许拿技术细节占用注意力，但保留反向义务——主动指出"这件事你不懂、而后不懂会有大麻烦"。原理层解释可省略，实践层（改哪个文件、跑什么命令、看到什么算成功）必须给足。【冻结，项目作者 Y1；COLLAB A4/A6】
43. **不排斥选项，排斥"看不懂或无法预期的选项"**：选项必须带后果与推荐；无法说明后果的选项不许端出来。【冻结，项目作者 Y2；COLLAB B7】
44. **产出 = 合作的默契程度，不是文档数量**：记录的价值在于改变 AI 的行为，不在于被人阅读；文档类工作直接执行，汇报只在有需要他决策/知悉的事项时给。【冻结，项目作者 Y3/Y9；COLLAB A7/B11】
45. **用"预期"替代"期限"**：分段依据是任务的客观难度（不是时间长短/对话次数/反馈）；每阶段必须有可立刻判断成没成的中间结果；不设时间上限；评估错了就更新评估。【冻结，项目作者 Y4；WORKFLOW】
46. **他用"类比一个已见过的产品形态"描述期望**（如"像网页端 AI 点对话里的链接右侧弹报告"）——先复述理解、让他确认，再动手；"功能可达"不等于"形态正确"，他关心入口是否匹配意图的时效性。【冻结，COLLAB B16/C19】
47. **插件主要由 agent 写**：设计插件接口时优化"agent 能否一次写对"而非"人写起来方便"；声明的复杂度上限是"agent 能机械填对"，超过就把判断挪到中间件。【冻结（设计前提），项目作者 Y7；COLLAB B13】
48. **他会给出"顺序"而不只是"目标"**（"先搭对象和接口，再对行为分类"——分类器的动词取决于名词）；短指令先拆出约束再动手，若认为顺序该改，说理由而不是默默改。【冻结，COLLAB B14/D6；ADR-017 背景】
49. **恶性 bug 不会让他放弃项目，但会让他去改架构**："这种问题都是常有的，发现问题解决问题就好"——他要的是把它变成系统能力（闸门、lh-plugin-development），不是保证不犯；他会提出架构级对策（克隆 dsh 做隔离、哨兵回退插件化）。【冻结，COLLAB B17/B18】
50. **反复重启可以接受**，不必为它中断开发或改变优先级；但重启是稀缺资源——凡能在重启前验完的都要验完（他不会因"多验一轮"不耐烦，会因"重启之后才发现问题"不耐烦）。【冻结，项目作者 Y8；COLLAB D7】
51. **第一个用户是作者本人**：验收标准 = 连续自用两周后，能判断系统对自己的断言是否准确、是否可反驳；两周内未曾主动打开使用 = 产品形态或场景选择错误。【冻结，ADR-011】
52. **ADR 记录方法论**：没有失效信号的决策不是决策是信念；弱依据必须标在正文里并写清"什么证据能解除它"；验收标准是陌生读者/其他模型能重建合理解释；归因必须区分"行为"与"产物"（仓库里的代码不自动等于作者的能力）。【冻结，决策记录者 D1–D4】
53. **经验记录的门槛**：默认不记，够得上"会复发/反直觉/代价高"才记；写在代码旁边 > 写进经验文档；人被问烦了是最高优先级的接口变更。【冻结（作为纪律），experience/README】

### 主题六：开发纪律

54. **装载期不许抛错**：配置缺失、目录解析不出、服务没就绪都不能在 `apply()` 里抛——装载照常完成，响亮发生在"用的时候"（路由 503 + 修法、工具返回错误 + 修法、stderr 一行）。理由不是优雅降级，是失败半径：`apply()` 抛错 = 整棵插件树加载失败 = dsh 起不来 = 学习者失去入口，而"该改哪一行"的说明恰好被自己弄没了。网络不可达等也不许在装载期探测——那等于把网络变成启动依赖。【冻结，ADR-025 决定 2；ADR-027 前提 5】
55. **运行时路径在安装期写下**：`lh-install.json`（仓库根 + 工作区），解析顺序 = 环境变量 → `lh-install.json` → 包标记 → 用的时候报错。不用"只靠环境变量"（每次启动都要记得设 = 不是能交付的默认值；忘了设的代价是起不来且学习者无法自救）；不运行时猜（猜错 = 静默读错目录）。【冻结，ADR-025 决定 1；ADR-024 决定 1】
56. **插件不许写死任何绝对路径**：数据目录从插件自身位置推导或由安装配置给出；工作区路径必须来自请求上下文或显式配置，不许有"默认指向某人工作区"的常量。写死路径在别人机器上是**静默错误**，比崩溃更难发现。【冻结（规则），ADR-024 决定 1】
57. **环境变量必须惰性求值**：模块级常量会在 import 时固化，"把它指到别处"的调用方（如离线测试）被静默忽略——实测后果是测试把假数据写进真实学习史。【冻结，ARCH 约束 9；经验 2026-09-17 E23；ADR-034 护栏③】
58. **开发隔离：DSH_HOME 迁进工作区**（`<仓库>/.dsh`，启动器 `lh-dev.mjs` 设置）。搬：preset、profile 配置、settings.yaml、lh-install.json；不搬：sessions/attachments（学习记录与上传物）、node_modules、`.credentials.yaml`。**凭据绝不进仓库**（安全 + 密钥是用户级配置跟着人走）；代价：不经 dsh 的 IDE/CLI 里开发要自己导出 `*_API_KEY`。老 `~/.dsh` 保留作退路。"两个家并存"是最危险状态——脚本 A 看新家、脚本 B 看旧家而两边都给结果；启动器与闸门都必须打印 DSH_HOME，原来写死 `USERPROFILE/.dsh` 的闸门改为按 `DSH_HOME` 找。【冻结（已验证），ADR-031；commit 621581c】
59. **按"爆炸半径"而不是"踩过几次"分配防范力度**：preset 行坏 = 该 preset 所有会话不可用；profile 行导入失败/客户端 apply 失败 = **整棵插件树加载失败、dsh 完全起不来**。进入一个新的加载层/作用域之前，先把那一层的规则问清。【冻结，经验 2026-09-18-0100 E2/E8】
60. **闸门哲学**（反复验证的元规则）：① 能导致启动失败的改动，必须先有一道跑在**生产路径**上的检查（import 的是 profile 副本、apply 用记账式假 ctx 真跑）；② 写闸门时先让它在**已知坏的状态上红一次**——没在坏状态上验证过的闸门只是一个希望；③ 闸门自己要有测试，"永远红"与"永远绿"同样没用；④ 满屏误报的检查器等于没有检查器；⑤ 检查器有**漏报（静默，伪装成全绿）**这一类失败——为消误报做的净化可能同时消掉真信号；⑥ 一个修复如果让某道闸门变绿，必须确认绿是因为事情对了，还是因为报警器被一起修掉了；⑦ 清单驱动的检查对"清单本身漏项"必然绿——凡"用 A 描述 B、再用 A 校验 B"都要单独问"A 自己错了谁发现"，补一条不读 A 的检查；⑧ 闸门要区分"应然红"与"不该红"。【冻结，经验 2026-09-18-2100、2026-09-19-0400、2026-09-19-1400 E19/E20】
61. **保护机制不能依赖被保护对象能运行**：哨兵/回退机制必须在进程之外（启动包装器预检），因为"插件树加载失败时树里的任何东西都没运行，包括哨兵插件自己"——"一个和病人绑在一起的心脏除颤器，在病人心脏停跳时也一起停了"。预检红时不自动改配置只报告；改配置只做一件事且改前备份；它自己坏了 `npx dsh web` 仍可用（退路一直在）。【冻结（原则；包装器实现状态见矛盾清单 #5），ADR-023 决定 3；经验 2026-09-18-0330 E2】
62. **版本控制边界**：一个仓库；只入库"人写的"（配置约 12 KB）；sessions/ 与 attachments/ 不入库——**对话历史没有备份，所以决策必须写进 docs/**（这是 ADR 存在的理由之一）；`.credentials.yaml` 绝不入库。不用符号链接同步配置（`~/.dsh` 被删则 dsh 直接起不来——"优雅输给了不可能因此起不来"）。【冻结（原则），ADR-023 决定 1/2；快照机制被 ADR-031 取代，见矛盾清单 #5】
63. **schema/契约是前置知识，不是事后 debug 线索**：宿主约束是封闭的、可枚举的（工具 schema 只支持 8 个关键字、插槽注册必填字段、inject 有两处同名不同义的声明），必须提到每个插件开发任务的开始与 review；契约每条标来源（[实测]/[宿主源码]/[闸门]），"未验证"是一等公民——把猜测当规则的契约比没有契约更危险，因为它让人停止怀疑。【冻结，经验 2026-09-18-0330 E3；ADR-024；PLUGIN_CONTRACT（已归档）】
64. **开发/测试/检查/debug 归成一类插件**（lh-devkit / lh-plugin-development 方向）：闸门要被 agent 自己调到（agent 只能通过工具调用东西）；`scripts/` 是给人的，检查要进每个插件开发任务就必须是插件；它只编排检查、不实现业务逻辑。不做"integrate/合并插件"——项目假设是"人不记，agent 记"，合并把耦合代价付出去解决不存在的问题；出现"两个插件必须同步改"的频繁需求时才是真的该合并。【冻结，ADR-024 决定 3/4】
65. **部署形态**：用户 `npx @deepseek-ai/dsh web` 配好模型后对 agent 说"帮我拉取并部署 LearningHarness"。部署插件三条硬约束：**先验证再写入**（没跑过闸门就写 profile 行 = 拿用户的 dsh 做实验）、**失败可回滚**（改 `.dsh` 前备份）、**幂等**；必须显式告知联网与改 `~/.dsh` 并经用户同意；检测并报告环境缺什么（node/pnpm），不猜、不自动装。【冻结（形态；实现未做），ADR-024 决定 2】
66. **LH 会话带 standard preset 基础能力、分两批**：按"是否需要 isolate realm"划界（不是按重要性）；加行前三件事——备份、闸门（闸门对正确配置报错比漏掉错误更糟）、闸门自检（空 preset 必须判红）。产品立场："在 LH 里开发，而不是在 dsh 里开发"——对非专业学习者把 dsh 的开发表达方式隐藏起来；刻意没加 persona（standard 的"you are a coding agent"对学习者是错的，LH 要自己的 persona）、agent-instructions、skill-filesystem（会把 dsh 术语暴露给学习者）。**风险如实记**：LH 会话从此能执行任意命令，这在学习者机器上是否可接受是产品决策，本步选了"要"不等于"永远对"。【冻结（第一批已落地），ADR-030】
67. **每插件一份声明式自我描述**（package.json 的 `lh` 段：kind/summary/inject/provides/depends_on/loads_at/verified）：agent 问"现在有哪些插件能干什么"需要机械可枚举、不会过期的来源；`verified` 让"验过什么"成为可查询事实。【冻结，ADR-024 决定 3】
68. **文本文件只用 edit 工具或编辑器改，绝不用 shell**：PowerShell 写 BOM / 写坏多字节字符（U+FFFD）/ 重定向 UTF-16LE，同一规矩被违反四次——处置从"记进文档"改成"做成闸门"（`check-text-encoding.mjs`）：被违反四次的规矩说明执行方式有问题，把可机械检查的部分变成闸门。配套：JS 一律写成 `.mjs` 文件再跑，不在 shell 里内联（引号/转义被吃掉，最坏是脚本没执行成功而我没察觉）。【冻结，经验 2026-09-16 E13/E14、2026-09-17 E24/E40、2026-09-19-1400 E15/E20】
69. **验证环境必须与生产同构**：换环境的唯一正当理由是"同构"，不是"不打扰人"；弱化版/错误环境里验证得到的成功不能外推——弱化掉的往往正是被测的那一环（dev profile 的 listProviders=0 追了六七轮，切回 web 一测就通；脱离宿主的 mountPreset 审计"没有不可用的行"是假象）。**跨层/跨路径/跨语境之前先问一句"这里和那里一样吗"**——preset 行/profile 行/直接 node 三处 specifier 解析路径不同，同一写法结果不同。【冻结，经验 2026-09-15 E1/E2、2026-09-16 E4/E6；ADR-014 三处对照表】
70. **破坏性操作一律白名单**：不允许"删掉所有不匹配的"启发式（"content_ref 不含冒号就删"匹配到了作者的真实记录——代价是信任）；先报告模式（列出将删什么及判据）、自动备份、一次清理只做一件事。整文件重写的脚本必须输出"改前 → 改后"，否则事后无法自证。【冻结，经验 2026-09-16 E7/E8；WORKFLOW 规则 4】
71. **离线测试的边界要写清楚**：假 ctx 能验"我的代码"（schema 形状、参数校验、落盘路径），验不了"宿主的接受度"——一个不说清边界的测试比没有测试更糟。"测试通过"是需要被怀疑的状态：check() 没 await 会让假通过混进真失败；测试断言编码的是"我当时相信的东西"，信念被数据推翻时改断言（新断言比旧的更强——管诚实性而非存在性）；测试前置条件必须照抄生产真实状态，不能照抄"让实现跑通的最小条件"（预先声明插槽 = 把要守的竞态绕过去）；假实现里的 bug 会把结论整个写反。【冻结，经验 2026-09-17 E22/E25/E33、2026-09-19-0400 E13】
72. **汇总指标绿了要抽读明细**：对齐率/相似度全绿时，逐题读原文仍可能发现"页眉被吸进题干""评注来自下一题"（汇总指标查一致性，读原文才能查出"多出来的东西"和"张冠李戴"）；批量写入/匹配交付前至少逐条读 3 条明细，并故意挑一条"看起来不该是这样"的。【冻结，经验 2026-09-17 E39/E42、2026-09-19-1400 E17】
73. **工具卡住不报错比报错更危险**："卡住"的工具诱导人重跑，而重跑是最坏的反应（check-all 按命名约定发现自己 → 指数级繁殖 752 个进程卡死整机 40 分钟）。处置：子进程硬超时（卡住的上限是"这一项没结果"不是"整机卡住"）、杀掉父进程后确认后代也死、按命令行精确匹配杀进程绝不按名字批量杀（会顺手杀掉宿主）。【冻结，经验 2026-09-18-2100 E7】

### 主题七：事故教训（让 dsh 起不来的四次 + 同类）

74. **四次启动事故的共同形状**：都是宿主**运行时才执行的校验**、都是"声明/形状"类错误、都要真启动到那一步才暴露：① profile 插件相对路径导入（pnpm 复制 + 目录名由包名派生 → 永远解析不到；整条依赖链连锁）；② 客户端 inject 写在 package.json 而非模块导出（`exports.inject` 服务名数组才是门禁认的）；③ list 型插槽注册缺 `options.id`；④ `apply()` 从模块位置推导仓库根（profile 副本上方没有仓库）+ 写死路径一直替这个故障挡枪。**"测试全绿"与"起不来"并存的原因是测试跑在源码目录、生产跑在安装副本。**【冻结，经验 2026-09-18-0100/2100；ADR-025 背景】
75. **挂载失败的代价不是"插件不工作"而是"整个会话不可用"**：preset 行未激活会让该 preset 所有会话建不起来（已存在的重进也失败）；新增 preset 行必须在真实会话里验证一次——`discoverPresets` 的 `broken` 只做 YAML 形状检查，查不出"行在等一个不存在的服务"；报错里的 `waiting for X` 先信它。【冻结，ADR-014 补充；经验 2026-09-16 E1】
76. **pnpm 安装语义**：根 `node_modules/@lh/*` 用 `workspace:*` 是**真软链**（源码即生效）；profile 里是**复制快照**且不因源码改变而刷新（"Already up to date"）——副本需 `sync-lh-deps.mjs` 按 files 清单同步（覆盖前备份；不用 pnpm install 同步：规格没变会跳过、副作用半径太大、拷贝规则不一致）。"改了没生效"先怀疑副本是旧的。【冻结，ADR-025 决定 3/4；经验 E53；ARCH 约束 13】
77. **插槽注册竞态**：客户端 boot 并发拉起所有插件，`shell.overlay` 等非内核插槽由别的包在 apply 时才声明——直接 `slots.register` 几乎必然抢跑（"之前能用"是运气：一直是竞态，只是之前恰好赢了）。正路 `ctx.slots.inject(key, cb)`（声明存在就同步执行，否则推迟到声明提交）。**抢跑一次是白屏（必然被发现），抢跑两次是静默失效（没人会知道）**——静默少一个功能比起不来更难发现。防复发用普查式闸门（什么都不声明的假 slots 把每个客户端 bundle 真 apply 一遍，断言不抛错 + 零注册），按插件普查而不是按已知出事的插槽打补丁。【冻结，经验 2026-09-19-0400 E12/E13】
78. **一条正则截断 49 道题解析、半年没发现**：它不报错也不像坏的（界面显示"像解析的残句"），所以没人去量——**定位线索是"长度是常数"**（23 条截断全是 26 字 = 一行宽度 = `[^\n]*`）；一批坏数据的某个度量是常数时，去找那个常数从哪来。修 bug 的第一版方案要当成假设来验（"我觉得这样能行"与"测出来能行"之间的差别就是一轮返工）。【冻结，经验 2026-09-18-2330 E8/E38】
79. **判定器必须比被测对象宽容**：验证工具自身有 bug 会被误读成被测对象的缺陷（改了签名忘改函数体 → 两次真实调用失败，差点否掉"通道成立"的正确结论；三次"判定器比被测对象更脆"每次都差点否定一个可行方案）。一次验证的结论是"对方不行"时，先问"我的判定是不是太严"。【冻结，经验 2026-09-16 E15、2026-09-17 E46；2026-09-18-0100 E6】
80. **"没看到"≠"没发生"；空字段不报错**：读日志读早了把"那行还没发生"误判成"日志写入失败"；把缺少信息的观测当成否定证据之前，先确认它在该条件下一定会产生可辨识痕迹；抽字段取到空且不报任何错——抽字段前先解压真实样本打出键、抽完用真实形状验证。**验证证据分两级**：旁路证据（日志文件，证明"被加载"）与受影响通道里的证据（提示词/工具/界面，证明"起了作用"）——要证明某部件起了作用，证据必须出现在它影响的通道里。【冻结，经验 2026-09-15 E5/E12/E6、2026-09-17 E56】

## 4. 经验亮点（14 篇经验中反复出现的主题）

1. **让 dsh 起不来的事故是贯穿性主线**：四次事故 + 多次险情（挂载失败、插槽竞态、check-all 递归爆炸），共同教训 = 装载期失败夺走整个产品、按爆炸半径防范、生产路径闸门。（插件开发者/2026-09-18-0100、2026-09-18-2100、2026-09-17 E51–E55、2026-09-19-0400）
2. **"闸门绿了 ≠ 事情对了"**：修复让警报器变绿而底层仍坏、检查器漏报伪装成全绿、满屏误报等于没有检查器、测试前置条件预先满足前提——同一母题至少五次变体。（2026-09-18-2100 E3/E4、2026-09-18-0330 配套教训、2026-09-19-0400 E13、2026-09-19-1400 E19）
3. **路径/层/作用域不同构是第二大母题**：三处 specifier 解析、测试路径≠生产路径、dev profile 假阴性、跨层套用经验（C17–C20 共同形状："跨层之前先问这里和那里一样吗"）。（2026-09-15 E1/E2、2026-09-16 E4/E6、2026-09-18-0100 E3/E4）
4. **用 shell 改文本文件四次事故**（BOM/U+FFFD/UTF-16LE/引号被吃掉）→ 最终处置是把规矩做成闸门："被违反四次的规矩，问题在执行方式不在记性"。（2026-09-16 E13/E14、2026-09-17 E24/E40、2026-09-19-1400 E15/E20）
5. **"没看到 ≠ 没发生"类否定推断**：读日志读早了、空字段静默、把旁路日志当否定证据、判定器比被测对象更脆（三次差点否掉可行方案）。（2026-09-15 E5/E12、2026-09-17 E46/E56、2026-09-18-0100 E6）
6. **静默失败比报错更危险**：解析截断半年没发现（常数长度是线索）、按页对齐"答案是别人的"、id 漂移静默失联、汇总指标全绿但明细全错、键退化（43 块只剩 20 块而 20 恰好"看起来正常"）。（2026-09-18-2330 E8、2026-09-19-1400 E16/E17、2026-09-17 E37/E47）
7. **产物必须自带稳定标识与出处**：42/49 混合批次（顶层 model 只描述最后一次）、`set1-q1` 撞车只能拦下 31 道、"产物没有稳定标识等于没产出"。（2026-09-19-1400 E16/E17；ADR-021 结论五/八）
8. **验证环境必须与生产同构；重启是稀缺资源但可以被接受**：dev profile 六七轮假排查；重启前能验的都验完，重启后才发现问题是真不耐烦点。（2026-09-16 E6；COLLAB D7、项目作者 Y8）
9. **破坏性操作白名单与"我删了作者的真实数据"**：启发式判据从一开始就在猜，"只删我自己的"没有对应机制；代价是信任。（2026-09-16 E7）
10. **作者的纠正有系统性方向**："谁拥有这个决定"（告知而非阻断）、降级是生态生长、工具是 LH 的、插件由 agent 写、认知负担正常但不要过度保护。（项目作者两篇全部 Y 条）
11. **记录方法论**：失效信号 = 决策与信念的分界；弱依据要标在正文；陌生读者验收法；归因区分行为与产物。（决策记录者 D1–D4）
12. **工具卡住不报错诱导重跑，重跑火上浇油**：check-all 自发现指数爆炸卡死整机 40 分钟；处置 = 硬超时 + 按命令行精确匹配杀进程树。（2026-09-18-2100 E7）
