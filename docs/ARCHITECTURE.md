# LearningHarness 架构（v2.0，2026-09-22）

> 本文只回答一个问题：**系统是什么、边界在哪**。协作规则见 `WORKFLOW.md`，对项目作者本人的建模见 `COLLABORATOR_MODEL.md`，本文不重复。事实来源：代码现状 + 冻结的 ADR（归档在 `archive/decisions/`）；冲突处以最新冻结 ADR 为准，只能依据未验证假设处显式标注「假设」。

## 0. 术语表

- **LH**：LearningHarness，本项目。
- **宿主**：dsh（含 Cordis 插件框架），LH 寄生其上的 agent 运行环境；LH 不自研内核（ADR-011）。
- **插件**：装在宿主里的功能单元，拥有全部教学判断；通过 package.json 的 `lh` 段做声明式自我描述。
- **内核**：机制本身——事件存储、资源存储、协议、执行机制；由宿主提供，LH 视为已冻结。
- **事件**：时间流中一次性发生的行为记录，只追加、不可变。
- **资源**：可寻址、可复用的产物（题目、资料、摘要）。
- **信封**：事件的统一外壳字段（ADR-012：id/timestamp/type/provenance/scope/data 等），内核只定义信封，不解释内容。
- **投影**：从事件日志重放计算出的只读视图（如课程树），属缓存，可整体丢弃重建。
- **断言（Claim）**：插件对学习者状态的判断，必须带出处与置信度，可审计、可争议。
- **Bundle**：教学策略资产 = 插件组合 + 系统提示词 patch，可切换、可版本管理、可分享。
- **Context Layer**：每次模型请求前的统一上下文组装点，教学纪律在此由代码强制。
- **preset / profile**：宿主的两类装载层；preset 是 agent 作用域，profile 是界面/会话作用域。
- **工作区**：学习者的数据目录（事件日志、题库、sessions 所在），路径由安装配置给出。
- **闸门**：跑在生产路径上的自动检查脚本（清单与实现归开发工具，不在本文）。
- **ADR**：架构决策记录，归档在 `archive/decisions/`，每条带状态标注。

## 1. 系统是什么

一句话：LH 是一个为自学者服务的开源 Web 应用，把「教什么、怎么教」的判断做成可插拔的插件，由一个只负责机制的宿主运行。

核心循环：

1. 学习者在 LH 会话里对话、做题、进入课程节点；
2. 宿主把会话行为变成事件流，LH 记录器插件把语义事件写进自己的事件日志；
3. 事件日志重放出投影（课程树、练习统计）；
4. 断言器把观察变成带置信度的断言，沿课程树上行沉淀为学习者状态；
5. Bundle（教学策略）在 Context Layer 读取状态与资源，决定下一步注入什么——循环回到 1。

产品护城河是**编排与约束**（什么时机注入什么、允许/禁止模型做什么、记忆怎么沉淀），不是工具本身（ADR-001/004）。

## 2. 内核与插件的边界

第一刀：**事实归内核，解释归插件**（ADR-002）。

| 内核持有（不可插拔） | 插件产出（可竞争） |
|---|---|
| 原始资料 | 摘要、学情分析 |
| 学习行为事件 | 学习者状态断言 |
| 事件日志与投影机制 | 系统行为记录（归记录器插件，ADR-011 写回） |

规则：

- 内核不含任何教学判断与领域逻辑；判断全部归插件。
- 一切解释必须带血缘标注（`derived_from` 链）回流为资源/事件，换插件时历史证据无缝保留（ADR-002/011）。
- 断言接口：**旧 `estimate` 字段已删除**，断言 = 带出处与置信度的集合；低证据必须低置信，禁止硬给估计；人工覆写本身记入日志（ADR-003/011/033）。
- 多评估器并存且允许不一致——分歧本身是「证据不足」的诊断信号。
- 教学约束禁止硬编码进提示词，由 Context Layer 钩子强制执行：钩子是代码级保证，提示词是概率性愿望（ADR-004/005）。
- 判定归插件、语法归内核：凡是能用接口形状防住的误用就不靠提示词请求自觉（ADR-019）。

## 3. 事件系统

- 物理形态：工作区 `data/events.jsonl`，append-only，一行一条；选文件不选数据库——用户应能用记事本打开自己的学习史，「可争议断言」才有前提（ADR-012）。
- 信封字段由内核注册表登记，未知类型拒绝写入；大内容外置为资源、事件只留 `content_ref` 指针；显式写 `null` 而非省略字段，读取端必须区分「没有」与「没记」。
- 只追加不可变：更新 = 新资源 + `supersedes` 指针；注解是一等资源（批判/补充/反驳带 target 指针）；血缘是 DAG（ADR-009）。资源与事件分离：题目是资源，「他这次答了这道题」是事件——遗忘曲线与间隔重复才有表达基础（ADR-017）。
- 可派生的不进日志：日志一旦能存缓存就不再是事实源；投影、索引都是缓存，必须能整体丢弃重建（ADR-014/018）。
- 课程树 = `lh/course/*` 事件的投影，不是可变文件；重组只追加事件、历史不丢、可回放（ADR-032）。
- LH 事件日志必须自持：宿主会话日志词汇表对外部插件封闭，往宿主日志写自定义类型会让会话下次重载失败（ADR-011/012）。
- 存储不是约束：单学者一年约 58 MB 未压缩（实测），不为省空间做设计（ADR-014）。

## 4. 宿主关系

- 根决定（ADR-011）：内核机制采用宿主 dsh，自研终止。宿主提供并视为已冻结：append-only 事件日志、投影与持久化、上下文拦截点（`agent/pre-step`）、系统提示词组装、工具注册与执行管线、插件加载与可逆卸载（Cordis）。
- LH 的资产 = 事件词汇表 + 插件 + 契约，不是内核代码。实现语言 TypeScript（ADR-010/011）；只有适配层允许 import 宿主包。
- preset 是 agent 作用域：够不着 host 面服务（共享逻辑用直接 import），拿得到 `ctx.llm` / `ctx.systemPrompt` / `ctx.tools` / `ctx.sessions`（实测，ADR-014）。
- 模型调用一律走宿主 `ctx.llm` + 档位中间件，不自建 provider 层——自建会丢掉成本透明、策略归因与降级留痕（ADR-016/027）。
- 寄生关系要显式管理：宿主是开发者预览版，LH 大量依赖「实测出来的宿主行为」而非公开 API。**假设**：宿主保持「一切皆插件 + 事件溯源」架构、`agent/pre-step` 等接缝不被破坏性移除；宿主接缝失效且无法隔离 = 失效信号（ADR-011/023）。
- 开发环境有两个家，**"哪个是活的"必须每次先验**（ADR-031/035）：仓库自持的家是 `<仓库>/.dsh`（启动器 `lh-dev.mjs`，跑 `profiles/web`）；而**作者日常在用的那个界面**是 Electron desktop 宿主，它的家是 `~/.dsh`、profile 是 `profiles/desktop`（实测其命令行即 `… C:\Users\Administrator\.dsh\profiles\desktop`）。**装进 `profiles/web` 的界面插件，在 desktop 应用里永远看不到**——而这个症状与"忘了重启"一模一样，是本项目最贵的失败形状。凭据绝不入库；sessions 不入库——对话历史没有备份，所以决策必须写进文档（ADR-023/031/035）。**`lh-dev.mjs` 的适用边界（2026-10-13 定位修正）**：它是**旧机制**开发器（解析 npm 全局 `@deepseek-ai/dsh`、扫 `.agent-presets/`），不是 app 0.2.0-rc.2（bundle + declaration row）的等价物——它跑通不代表 app 跑通（5 个插件静默瘫痪期间它一路全绿）；app 侧的等价闸门是 `scripts/check-bundle.mjs`，功能复活走 bundle 安装（`bundle/README.md`）。
- 课程归属进上下文：`@lh/course-tree` 注册运行时上下文 `lh:course`（order 117），`text` 每次组装时求值，所以刚建的课程与刚绑的会话下一次请求就生效；未绑定时注入空串，取数失败静默降级为"不注入"（ADR-035）。
- **界面也能写，但只有一条写路径**：`@lh/workspace-ui` 的三条写路由与 agent 工具都调 `@lh/course-tree/commands.js`——判断归 agent，机械动作归界面（ADR-035）。
- **题库管理面板（`@lh/question-bank-ui`）与「课程目录」「学习日历」并列**（`main` key `lh-bank` + 侧栏同名 id）：左列题库清单，右列三段——**来源 / 题目 / 做题记录**（时间、作答、三态对错、来源、用时、关联会话）。题目段是**表格 + 分页**（每页 10 或 20 条，作者 2026-10-13 指定）。它比另两块**更窄**：只读 + 两个可逆动作（**归档 / 恢复**，各是一次工作区文件移动，**不写任何事件**）。**删除不在面板里做**——那走清理脚本（报告模式 + 白名单 + 备份，`scripts/cleanup-test-extracts.mjs` 是第一个）。
- **做题记录段的会话坐标缺失是如实留空，不是 bug**：界面路径拿不到"当前会话"（同 §7 开放问题 3），所以 `session_ref: null` 的那些在面板上写"无会话坐标"（并用斜体淡一档显示），**绝不按时间或题库猜一个**——猜出来的关联看起来像真的，比没有更糟。
- 装载期不许抛错：配置缺失、路径解析不出都延迟到「用的时候」响亮失败——`apply()` 抛错 = 整棵插件树加载失败 = dsh 起不来 = 学习者失去入口（ADR-025）。

## 5. 数据与存储（题库纪律）

- 题目编号全局唯一；id 变更必须写 ADR 并说明旧作答记录怎么办（ADR-028）。
- LLM 的答案绝不进判分路径：判分只用官方答案；LLM 与官方答案不一致是免费的题目质量信号，交叉验证逐条保留（ADR-021/029）。
- 判分三态 `true|false|null`：判不了就单列 `unjudged`，不能默认算错；统计按 `source` 分组，`source:'llm'` 的答对**不是**学习证据（ADR-017/018）。
- 对齐单位必须等于语义单位：题对题、视频对时间区间，不能用页码/资料内序号代理——静默错位是真实发生过的（ADR-020/027/028）。
- 产物必须自带稳定 id 与出处：没有稳定标识 = 没产出；出处跟着记录走，不只跟着文件走（ADR-021）。
- 预处理（看题、标注、入库、分块）是离线、一次性、慢的判断工作，走脚本不进插件；LLM 全量处理分批停下来向作者报成本、等确认（ADR-021/029）。
- 知识点 = 两轴封闭词表（题型 × 领域），内容词不许进词表；认不出的标签如实回报为 `unmapped_topics`，不丢弃（ADR-021）。
- **题库的 schema 判据只有一处**：`@lh/question-bank/bank.js`（`loadBank` / `isBankFile` / `listQuestionBanks` / `requireBank`）。题库管理面板**只取该包的子路径**（`/bank`、`/attempt`、`/question`），刻意不 import 它的 `index.js`——那个文件拖进 `@lh/model-tier`，而界面包没有也不需要那条依赖。为此那四个符号 2026-10-13 从 `index.js` 下沉进 `bank.js`（`index.js` 原样 re-export，行为零变化）：**同一份实现要留在能解析到它的那一层**（ADR-037 §6 的同一条）。
- **题库归档/改名没有事件坐标**：归档是一次文件移动，不写事件，所以日志里查不到"这个库什么时候被归档的"。见 §7 开放问题 7。

## 6. 插件契约归宿主

LH 插件接口协议由宿主 dsh/cordis 定义，本文不重复约定。权威参考：`archive/PLUGIN_CONTRACT.md`（已归档）与 lh-plugin-development skill。要点（ADR-024）：宿主约束封闭、可枚举，每一条标来源（[实测]/[宿主源码]/[闸门]）；「未验证」是一等公民——把猜测当规则的契约比没有契约更危险。

## 7. 开放问题

> 不阻塞规则：下列问题都不得成为动工前提；遇到先选最幼稚的可用答案记为「临时」继续推进。

1. 断言置信度的更新协议：多次证据如何结算成一条断言（Claim 结算未做）。
2. 跨会话调度器接口：间隔重复、复习时机。
3. 界面来的作答缺会话坐标：HTTP 路由无会话上下文，卡片作答只能靠时间 + 题库粗关联；修复依赖宿主提供「当前活动会话」服务（未实测）。**课程目录那一侧有同一个缺口**，临时答案是"持续记录最后一次显示在主视图的会话 + 按钮上明写会话 id"（ADR-035 §2），同样等这个服务。
4. 多工作区下的课程树与断言如何组织（临时答案：单工作区，ADR-032）。
5. 新旧题库两册并存：18 条旧作答记录目前只能由旧册解析，处置待作者定（ADR-028/029）。
6. 部署形态（用户 npx dsh 后让 agent 拉取并部署 LH）有设计未实现（ADR-024）。
7. **题库归档/改名没有事件坐标**（2026-10-13 记）：归档 = 工作区文件移动（`lh-questions/.archived/`），刻意不写事件——题库的物理形态是文件（ADR-018 决定 2），文件系统就是这一层的事实源，伪造一条资源事件反而更糟。**已知缺口**：日志里查不到"这个库什么时候被归档的"。**失效信号**：一旦有人要问这个（或要做"归档统计"），就该开始写事件或给题库自身加版本号，**而不是去翻文件系统时间戳**——那个时间戳会被任何一次复制改动。**临时答案**就是现在这样：面板从目录结构推导归档态，并在需要时由人自己看。
