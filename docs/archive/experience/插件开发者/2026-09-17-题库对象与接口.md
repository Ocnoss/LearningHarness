# 插件开发者经验 —— 2026-09-17：题库的对象与接口

> 当天任务（作者原话）：*"先搭起来行为的对象和接口，再去对行为分类。"*
> 交付：`docs/decisions/017`、`docs/decisions/018`、`plugins/lh-question-bank/`（4 个模块 + 2 个测试套件）。
> 当天大部分时间花在**验证**上，而不是写功能代码——这个比例是对的，下面几条说明了为什么。

---

## E21. 先写"对象与接口"，是因为分类器要表达的动词取决于名词

- **场景**：作者要求先搭题库的对象与接口，再对行为分类。我原本的直觉是先做抽取（有真实题目才好谈行为）。
- **决策**：照作者的顺序做。只定义题目（资源）与作答（事件）的结构、id 派生规则、判分与校验，
  **一行抽取代码都不写**。
- **根因**：分类器要表达"他对 X 做了解答"，而 **X 是什么决定了能表达什么**。
  反过来做会得到一个与对象配不上的词汇表——例如若题目没有稳定 id，
  "他第二次答同一道题"这件事根本无法表达，于是遗忘曲线与间隔重复从一开始就无从谈起。
- **解决方案**：`docs/decisions/017` 把"题目是资源、作答是事件"定为骨架，
  再由此推出 id 派生（出处+编号+题干指纹）、答案归一化（标签数组）、作答事件字段（含 `source`）。
  实现时又发现四个 ADR-017 没管的决定（物理形态、多解、判分三态、统计口径），另行冻结为 `018`。
- **启示**：**顺序本身就是一种架构决定。** 遇到"先做哪个"的分歧时，问的不是"哪个更快出成果"，
  而是"哪个是另一个的前提"。前提错了，后面的工作会全部返工，而且是静默返工——
  代码能跑，只是表达不了本该表达的东西。

## E22. 离线测试的边界要写清楚，否则它会变成虚假的安全感

- **场景**：服务端插件改代码必须重启整个 dsh，而重启会打断学习者。
  所以我写了一个**假 ctx**（只实现 `tools.register` / `on`）把插件体真跑起来，37 项断言全过。
- **决策**：在测试文件顶部明确写出"它能拦住什么、拦不住什么"。
- **根因**：假 ctx 能验的是**我的代码**（schema 形状、参数校验、落盘路径、事件写入），
  不能验**宿主的接受度**。宿主的 `assertSupportedJsonSchema` 支持哪几个关键字、
  row 会不会激活，只有真跑才算数。
- **解决方案**：测试文件顶部写明两个清单；另外单独写了 `scripts/check-preset-mount.mjs`，
  在加 preset 行之前先回答"文件能不能 import""inject 有没有人给""apply 会不会抛错"。
- **启示**：**一个不说清边界的测试比没有测试更糟**——它会让人以为"验过了"。
  凡是"我模拟的"都必须标出"我模拟不了什么"。

## E23. 环境变量写成模块级常量，会让"把它指到别处"被静默忽略

- **场景**：`lh-event-store/store.js` 里原本是
  `export const LH_EVENT_LOG = process.env.LH_EVENT_LOG ?? 'D:\\...\\events.jsonl'`。
  我在离线测试里设了 `process.env.LH_EVENT_LOG` 指向沙盒，以为测试数据会落进沙盒。
- **决策**：改成惰性求值的函数 `eventLogPath()` / `contentDirPath()`。
- **根因**：`const` 在**模块加载时**求值。测试 import 插件之后才设环境变量，
  此时常量早已固化——设置被静默忽略。证据：改造前跑测试会在真实 `data/events.jsonl` 里
  出现 `lh/user/attempt` 事件；改造后真实日志是 27 条、题库/作答相关 **0 条**。
- **解决方案**：两个路径都改函数；`appendEvent` / `readEvents` / `writeContent` / `readContent`
  以及 `lh-event-store/index.js` 的自检全部改调用点。
- **启示**：**后果不是"测试不方便"，是"测试把假数据写进了用户的真实学习史"。**
  任何"指向外部资源"的常量都要问一句：调用方有没有可能在 import 之后才决定它指向哪？
  如果有，它就不能是常量。

## E24. PowerShell 改文本文件：这次把文件改到读不出来

- **场景**：我需要把测试文件里 7 处 `assert.rejects(() =>` 改成 `assert.rejects(async () =>`。
  用了一行 `Get-Content -Raw` + `Replace` + `Set-Content`。
- **决策**：立刻用 Node 检验文件编码，发现损坏后删掉重写。
- **根因**：`Set-Content` 的编码处理把多字节字符写成了 `U+FFFD`。
  证据：`node -e` 读出 `hasReplacementChar true`，随后该文件连 `read` 工具都拒绝
  （`invalid UTF-8 text`）。**这不是第一次踩**——之前 `Set-Content -Encoding UTF8` 写过 BOM，
  导致 `Unexpected token '﻿'`。同一个工具，两种坏法。
- **解决方案**：删除损坏文件、用编辑器重写（文件名同时从 `plugin-selftest.mjs` 改为 `selftest-plugin.mjs`，
  与已有的 `selftest.mjs` 命名对齐）；并在新文件顶部写下这条警示。
- **启示**：**"文本文件一律用 Node / 编辑器改"这条规矩我有，但我破了它——因为改动看起来足够小。**
  破坏性工具的诱惑恰好在于"这次只是小改"。真正该改的是**不让"小改"有机会用到错工具**：
  能用 `edit` 工具就用 `edit`（它是字面替换、不碰编码），而不是绕道 shell。

## E25. 测试里的"通过"必须查，否则它可能只是没跑到

- **场景**：插件层测试第一次跑，10 条失败里有 5 条的错误信息本身**就是代码正确拒绝的内容**
  （如"没有一道题通过校验：缺题干"）。
- **决策**：逐条查"为什么正确行为被记为失败"，而不是改代码去迎合测试。
- **根因**：`check(name, fn)` 没有 `await fn()`。
  于是 `assert.rejects` 返回的 Promise 在 `try` 块之外才 reject——**拒绝逃出了断言，
  测试框架把它算成了通过**。同一批输出里既有"正确行为被记为失败"，也有"真正失败被记为通过"。
- **解决方案**：`check` 内改 `await fn()`；所有 `assert.rejects` 的回调改 `async`；
  另外把一条写死次数的统计断言改成**结构不变量**断言
  （写死 `total === 7` 会让它依赖"别的用例跑没跑"，一个用例挂了就连带误报）。
- **启示**：**"测试通过"是一种需要被怀疑的状态**，尤其当它和直觉不符时。
  当天还有两条同类：schema 检查器把 `properties` 下的**属性名**当成了关键字（25 条误报）；
  preset 供需检查器把宿主提供的 `tools`/`llm` 报成"无提供者"（6 条误报）。
  **一个满屏误报的检查器等于没有检查器**——人会学会忽略它，于是真的那条也被忽略。

## E26. id 派生规则是题库里最贵的一条约定，所以它值得被单独测边界

- **场景**：题目 id 定为 `q-` + `sha256(出处|文件|源编号|题干压缩后前40字).slice(0,12)`。
- **决策**：专门为它写一组测试，测**边界的严格两侧**。
- **根因**：id 一旦错了，已经落盘的所有题目都要重新编号，
  下游的作答记录、断言、策略评估全部失联——而**这种错误在数据里看不出来**（都是合法 id）。
- **解决方案**：测试覆盖：同输入同 id、空白差异不影响、全角/半角标点不影响、
  **前 40 字之内分叉 → id 不同**、**前 40 字之外分叉 → id 相同**、
  不同题号不同 id、不同文件不同 id、id 形状。
  其中"边界之外"那条用例**先断言造的数据确实越过了边界**（`compressedLen > 40`），
  否则它是个假通过——第一版就是假通过：我算错了长度，第 30 字就分叉了。
- **启示**：测边界时，**要同时验证"测试数据真的在边界那一侧"**。
  只断言结论的测试可能在测一个根本不相干的情形，而它看起来是绿的。

## E27. 判分三态：把"判不了"混进"答错"会静默污染学习者模型

- **场景**：作答要记 `correct`。直觉上它是布尔值。
- **决策**：`correct: true | false | null`，且 `null` 单列统计、**不进正确率分母**。
- **根因**：判不了的情形真实存在（题目对象缺失、题库里没这道题、作答为空）。
  若默认算错：学习者正确率凭空变低，下游得出"这个知识点他不会"，据此调整教学——
  **污染发生在题库这一层，在下游完全看不出来**。
  同理，`null` 进分母则正确率虚低，进分子则虚高。
- **解决方案**：`judgeAttempt` 返回三态；`summarizeAttempts` 单列 `unjudged` 且 `accuracy` 的分母只算判得了的；
  没有可判数据时 `accuracy` 是 `null` 而不是 `0`（"没数据"不等于"全错"）。
- **启示**：**凡是"我不知道"能被表示成"否"的地方，都要检查它会不会被静默当成"否"。**
  这是当天第二次遇到同构问题（第一次是坐标记录器的"写一个坏坐标比不写更糟"）。

## E28. 填空题的多解：不加这个字段就是在系统性冤枉答对的人

- **场景**：写判分时发现"22"和"二十二"都能算对，但 schema 里只有一个 `answer`。
- **决策**：加 `accept` 字段（其他可接受的答案），`answer` 保持为唯一标准答案。
- **根因**：填空题天然多解。判分若只认一种写法，
  **答对的人会被判错**——而错的判定直接进学习者模型。做自动同义替换也不行：
  那需要语义判断，而 `question.js` 是纯函数层，不该有判断（契约 §1.1）。
- **解决方案**：`answer` 给人看（只该看到一个答案），`accept` 给判分用（全集）；
  两者都不做同义替换，多解必须显式声明。
  另修了一个相关 bug：填空的 `normalizeAnswer` 原会把 `'AB'` 拆成 `['A','B']`
  （那对选择题对、对填空题错）——归一化因此必须**知道题型**。
- **启示**：**"同一个输入有两种合理解释"时，不要选一个默认，要把题型作为参数传进来。**
  强行统一会在一半情形下静默出错。

## E29. 只做接口不做抽取，是一条需要抵抗诱惑的纪律

- **场景**：题库有了对象与接口，最自然的下一步是"从 PDF 抽题，才有真实数据"。
- **决策**：不做。本阶段只交付 `import_questions`（收已结构化的题）与 `record_attempt`。
- **根因**：抽取是**判断**，不是接口（契约 §1.1）；而且它是独立工程
  （`D:\考公资料` 里 170 个扫描版 PDF，OCR 质量决定抽取质量）。
  更实际的理由：**若先给抽取工具，会诱导模型去用它、然后拿到一堆质量不明的东西**，
  于是"题目质量"这个变量从一开始就混进了后面所有环节。
- **解决方案**：`import_questions` 接受 `file_path` 或内联 `questions`——
  任何来源（抽取插件、人写的 JSON、旧项目格式）都能进来。
  格式适配由代码机械完成（接受数组 / `{questions:[]}` / 单题对象三种形态），
  因为**格式适配是机械劳动，让模型去转格式是浪费它的判断力**。
- **启示**：**"先把入口做薄"是一种为自己保留选择权的做法。**
  入口薄了，谁产出题目都可以接；入口厚了（自带抽取），就锁死了一种产出方式。

## 当天的三条判断被推翻，记在这里

1. **作答另存一个 `attempts.jsonl`** —— 我实现时的第一版想法，理由是"高频查询不该扫事件流"。
   否掉：那会造成**两个事实源**且无一致性机制，而作答本来就是事件（ADR-017 决定 1）。
   而且查询成本被高估：JSONL 按行过滤，几千条是毫秒级。
   真到需要索引的规模，正确做法是**派生缓存**（可重建），不是手写账本（丢了就没了）。
2. **题库文件名带时间戳** —— 照抄资源索引器的做法。否掉：索引文档是给人看的快照，
   多留几份有价值；题库是**被程序引用的对象**，路径必须稳定。
   同一原则（更新 = 新资源 + 指针）在两种用途下导出不同的文件名策略。
3. **测试断言写死次数** —— 看起来更严格，实际让用例之间产生隐藏依赖。
   改成结构不变量。

## E30. "两条路不独立"这句话，落在接口上就是"线格式必须结构化"

- **场景**：作者要求刷题既能走对话，也要有点击式输入：*"至少要有打字以外的输入方式……比对话更不容易误触、更流畅、更沉浸"*。
- **决策**：工具返回的题是 `options: [{ label: 'A', text: '1954年' }]`，而不是拼好的 `"A. 1954年"`。
- **根因**：如果返回一段拼好的文本，点击界面就得**回头解析那串文本**——
  措辞一改就静默失灵，而且那种失灵不会有报错，只会让按钮消失或错位。
  结构化之后，文本界面念 `A. 1954年`，图形界面把同一个 `label` 渲染成按钮，**吃同一份数据**。
- **解决方案**：`practice.js` 里两个投影 —— `toPresentableQuestion`（无答案，给做题）与
  `toRevealedQuestion`（带答案与解析，给讲解）。后者只由 `submit_answer` 返回。
- **启示**：**"将来还要支持另一种界面"这句话，必须在定线格式的那一刻就兑现。**
  等到做界面时再改，代价是全链路返工；在那之前，它只是一句愿望。

## E31. 用接口形状防止误用，而不是用提示词请求模型别那样做

- **场景**：刷题循环需要"取题"和"取答案"两件事。最自然的做法是两个工具：`get_questions` 与 `reveal_answer`。
- **决策**：**不拆**。`get_questions` 永不返回答案；答案只能从 `submit_answer` 拿到，
  而 `submit_answer` 同时把作答写进事件日志。**记录与揭示是同一个动作。**
- **根因**：拆开会打开三个缺口，而且每一个都不会留下痕迹（工具调用都是"成功"的）：
  ① agent 可以先揭示答案，再把答案念给学习者；
  ② 先知道答案再"引导"学习者作答；
  ③ 把答案念完之后才记录，或干脆不记录。
- **解决方案**：合成一个工具。于是"拿到解析"在结构上**蕴含**"作答已被记录"。
- **启示**：**凡是"我不希望模型这样做"的事，先问"能不能让它做不到"，而不是"能不能让它别做"。**
  契约 §1.1 说内核拥有语法、插件拥有判断——"不许先看答案"是语法，不该指望自觉。

## E32. 退化要留痕，不要抛错、也不要静默

- **场景**：`unseen`（只出没做过的题）在"全部做过了"时该怎么办？`missed` 在"没有错题"时呢？
- **决策**：**退化为 `sequential`，并在返回值里说明退化了什么**；未知的 `order` 值同样退回并留痕，不抛错。
- **根因**：两种更自然的做法都更糟——
  - 返回空：学习者想继续练，工具说"没题了"，**而题都在**；
  - 抛错：一次参数笔误就让整个循环中断，而学习者并不知道为什么。
- **解决方案**：`selectQuestions` 返回 `{ questions, order, considered, note }`，`note` 说明所有调整。
- **启示**：**工具面对"输入不理想"时，默认应当是"尽力做对的事 + 说清做了什么"**，
  而不是"拒绝"或"装作没发生"。这条与 ADR-016（档位建议而非要求）是同一条精神的另一个面。

## E33. 测试预期又写错了，而失败信息读起来像代码坏了

- **场景**：新加的 20 条用例里 2 条失败：一条说"刚答错的题没进错题本"，一条说 `missed` 取到 5 道但错题本是 0。
- **决策**：先读测试的执行顺序，而不是改代码。
- **根因**：两处都是**测试状态依赖**——
  ① 前面有一条用例故意把 q1 答对（验证"答对后移出错题本"），所以第 8 段再断言 q1 在错题本里就自相矛盾；
  ② `order=missed` 与 `stats.missed_recent` 是**两个不同的量**（一个是取题池、一个是列表上限），
  数字曾经巧合相等，逻辑上从来不成立。
- **解决方案**：前者在断言前**显式制造一次答错**；后者改成断言"取到的每一道都在错题本里，且数量对得上"。
- **启示**：**当测试失败信息读起来像"代码坏了"时，先查测试自己。**
  今天第三次遇到这个模式（E25 的 `await`、schema 检查器把属性名当关键字、这次的执行顺序）——
  共同点是**失败信息描述的是症状，不是原因**。

## E34. 顺带查出的一个能改变将来做法的宿主事实

- **场景**：为"点击式作答"找通道。原本以为要做到壳级前端才行（ADR-013 把它推迟了）。
- **决策**：查宿主，而不是接受"要自己造"。
- **根因**：宿主已经有一个 UI 支撑的服务 `ctx.userQuestions`
  （`@deepseek-ai/dsh-user-questions`），`ask({ questions })` 的每项支持
  `options: [{ label, description }]`、`multiSelect`、`detail`，
  以及**开放的呈现意图标签** `intent.kind`（未知标签由 UI 退回通用列表，编码不变）。
  `ask_user_question` 工具只是它的一个消费者。
- **解决方案**：记进 ARCHITECTURE §0.1 约束 10，**并明确记下未验证的部分**：
  它由宿主面（`dsh-web-app`）提供，而 preset 是 agent 作用域，**能否注入尚未实测**。
  ADR-019 因此决定**不把它作为循环成立的前提**。
- **启示**：**"宿主没有这个能力"这个判断代价很高，所以必须查证。**
  我原本已经写好一个探针插件准备去试，后来想清两件事：探针要作者重启一次才能回答，

## E35. 我判"横排"判错了：三个量只有一个等于"读者看到的样子"

- **场景**：量资料规模时，我看到 `片段阅读600题-题本【上】` 的内嵌图片是 `6357x4724`（宽>高），
  就在报告里写了"这一册是横排的，98% 其他页是竖排"。
- **作者纠正**：*"片段阅读不是横排的呀，我打开看过了，横竖和其他文件没有区别"*。他是对的。
- **根因**：我把**"内嵌图片的像素形状"当成了"页面朝向"**。同一个页面上有三个不同的量：
  1. `MediaBox`（页面尺寸，PDF 用户空间）；
  2. `/Rotate`（查看器要额外旋转的角度）；
  3. **旋转后的有效尺寸** ← **只有这个等于读者看到的样子**。
  实测那一册是「横向 MediaBox + `/Rotate` 90/270」，旋转后就是竖的。
  我的脚本只打印了第 1 个量（更糟：只打了内嵌图的形状），另外两个既没读也没想。
- **解决方案**：`pdf-survey.py` 改为读 `page.rect`（应用 `/Rotate` 之后的显示尺寸）判朝向；
  新增 `page_orientation.py` 把三个量并排打出来；
  **并把这条差异做成回归测试** `check_render_rotation.py`：锁住不变量
  「渲染位图的宽高关系 == `page.rect` 的宽高关系」，覆盖 10 个文件 **788 页**（含所有 `/Rotate≠0` 的页）。
- **为什么这条值得单独记**：这次只让我**写错一句结论**。但它离真正的故障只有一步——
  若渲染没应用 `/Rotate`，送进 OCR 的就是**躺倒的图**，质量下降却**不报错**。
  产出看起来像"OCR 不太准"，于是人会去调模型参数，而问题在渲染。
  **一个关于"方向"的误判，代价可能不是一句话，而是整批数据的质量。**

## E36. 作者纠正的第二处：对齐的单位是题目，不是页

- **场景**：我的对齐方案是"题本与解析各取第 N–M 页，然后逐题配"。
- **作者纠正（原话）**：*"单位应该按题目来……题解会比题集的单题内容多，
  所以取相同页数的话题解的题目会比题集少，这样：都取前 20 页，然后取前 20 题做题解和题集的对应，
  页数相比于题目有较长的冗余。"*
- **根因**：**页是内容的代理量，而两个文件的内容密度不同。**
  实测：题本【上】94 页装约 300 题（0.31 页/题），解析【上】212 页装同样 300 题（0.71 页/题），
  解析每题篇幅是题本的 **2.3 倍**。所以"取同样页数"覆盖的题数不同——
  按页配平会在**两边题数不一致那一刻**开始整体错位，而错位后每题都还是"有答案"的，
  **只是答案是别人的**。这种错不报错，只会让题库静默变成废品。
- **解决方案**：对齐用题号（印出来的、排版无关），页数只是"读到够为止"的冗余。
  可推广的原则：**对齐的单位必须等于语义单位，不能用一个代理量代替它。**
- **启示**：我在别处也用过代理量（`content_ref 不含冒号就删`——那次删掉了作者的真实数据，见 C10）。
  **代理量的危险在于它总是"看起来够用"，直到某个维度的密度变了。**

## E37. 同一份数据、两个工具得出不同结论：那是切块层坏了

- **场景**：对齐报告说"Q4 的题干是《毫无疑问，重大事件作为城市发展动力…》"，

## E38. 解析把批注插在题干句子中间——连续子串匹配原理上就会失败

- **场景**：改成"题干前 N 字在解析里连续出现就算定位到"之后，20 题里仍有 2 题失败。
- **决策**：写 `diagnose_stem_break.py` 做**渐进探针**——对题干的每个长度查一次，
  看在哪一字断掉，并把断点两侧文字**并排打出来**。
- **根因**：并排一看就清楚了：

      题本: …具有无可替代的积极作用 它能集中人力物力财力能
      解析: …具有无可替代的积极作用 它能⑧花生批注 集中人…

      题本: …的确是 无论是学习还是成长 都是逐渐拔节的过程
      解析: …的确是 无论是学习还是成长 [行文结构][后观点结构][开篇引出话题]…

  **不是 OCR 错字，是解析把批注与讲解插进了题干句子的中间**——题干被切开了。

- **解决方案**：改成分段/子序列匹配。
  **而且我第一版修法也是错的**：difflib 的窗口设成"探针等长"，
  于是插入的文字把后面的题干**挤出了窗口**，Q11 只拿到 0.58——
  等长窗口本身就假设了"没有插入"。改成**子序列**（只要求探针字符按顺序出现）后 **20/20 全部命中**。
- **启示**：**修 bug 的第一版方案要当成假设来验。**
  我写下"容忍批注插入"时并没验证它真能容忍——实测显示等长窗口恰恰不能。

## E42. 双栏排版 + OCR 按行输出 = 逐行解析无法可靠挂接

- **场景**：从解析里提"各选项的评注"（`A. …（缺主题词）`）。第一次做完，20 题**全都有**评注，
  看起来很好。
- **决策**：读原文核对 —— 而那一步暴露了问题：Q9 的评注**来自下一题**。
- **根因**：两层错误叠在一起。
  1. **块范围**：本题解析块 = `[本题起点, 下一题起点)`，而**下一题的选项行**落在里面
     （因为"下一题起点"是它**题干**出现的位置，选项在题干之前）。于是评注张冠李戴。
  2. **更根本的**：这份资料是**双栏 / 页边批注**排版，而 OCR 按行输出，
     批注行与正文行在文本里交错。选项字母与它的评注被拆到相隔很远的行上：

         （对策有误）
         A选项谈论的是"相声创作"的问题、B选项谈论的是"相声表演形式"的问题…
         A选项、B选项问题、对策均不正确，排除；…

- **解决方案**：
  - 修掉第 1 层（评注只在 `【参考答案】` 之后取）之后，20 题里**只剩 3 题**有评注 —— 真实水平；
  - 第 2 层试过坐标重建（`rebuild_reading_order.py`），但合并容差把两栏**粘到了一行**，
    分栏点也算错了（675 vs 应为 ~850）。要调对得做版面探测，收益不确定；
  - **最后决定接受这个限制，并显式标注**：讲解要么有、要么 `provenance.analysis_available=false`。
- **判断的代价要说清**：这个损失**不影响判分**——答案是从 `【参考答案】` 直接抽的，
  判分/错题本/覆盖率都不依赖评注。**评注只影响"讲得多好"，不影响"判得对不对"**，
  而刷题工具里判分是承重的。
- **启示**：**"指标全绿"和"数据对得上"是两件事。**
  如果我没读原文核对，"20/20 都有评注"会一直是个让人放心的数字，
  而它背后是错的。**汇总指标查一致性，读原文才能查出"张冠李戴"。**

## E43. 拿一个不可靠的信号去抬置信度，会毁掉置信度本身

- **场景**：我给置信度设计了三档，其中"分布法"（正确选项不带负面评注、其他选项带）
  一度被我认为是**最强信号**，因为它给出的结果很符合直觉。
- **决策**：把每题的原始信号摊开看（`show_confidence_signals.py`），而不是只看分布数字。
- **根因**：**数据推翻了那个推理。** Q1 的标注是
  `{A: 片面, B: 区别比较联系类, D: 区别比较联系类}`，而答案 C 自己也有标注「具体类」——
  也就是说**选中项也可以带标注**，那些标注里混着**题型提示**
  （"区别比较联系类选项"、"具体类选项"），并不全是负面评语。
  所以"选中项无评注"既非必要也非充分。
- **解决方案**：把评注完全**踢出置信度计算**，只用两个可靠信号——
  答案在选项范围内（机械可判）+ 讲解正文显式提及（原文印证）。
  评注仍然照实保存（有人想看），但**不参与判断**。
- **启示**：**置信度这个字段的全部价值在于"能筛出要复核的题"。**
  一旦有一个不可靠的信号参与了它，这个字段就失去了意义——
  而且失效方式是**"低置信度的题看起来变少了"**，那是让人更放心的假象。

## E44. 断言本身也会过时

- **场景**：端到端验证里有一条断言是"每题都必须有非空讲解或明确说明为何没有"。
  在确定"双栏资料拿不回批注"之后，这条必然失败。
- **决策**：**改断言，而不是去凑数据。**
- **根因**：那条断言编码了一个**已被数据推翻的假设**（"每道题都能有讲解"）。
  正确的断言不是"必须有讲解"，而是**诚实性**：
  有就有，没有就必须在 `provenance` 里显式标出来、并说明是哪一种。
- **解决方案**：改成两条：
  ① `analysis_available` 必须与 `analysis` 的实际内容一致，且 `analysis_kind` 合法；

## E46. 三次"判定器比被测对象更脆"

- **场景**：验证模型能不能标对空位位置。三次都判成"失败"，而三次都是**我的判定器**错。

## E47. 键的构成一旦退化，退化是静默的

## E48. 页眉可以落在一道题的中间

- **场景**：逻辑判断第 14 题的选项全丢，题干只剩前半段。
- **根因**：我原来让"页眉页脚噪声行"**结束当前块**（那是为片段阅读的题末污染修的）。
  但实测这一页是：

      …因此小兰是全公司最受欢迎的员工。
      4                      ← 页码
      逻辑判断600起            ← 书名页眉
      四海公考                ← 机构名
      下列选项最能削弱上述结论的是：   ← **题干的后半句**
      A. 公司的高层干部都没有参与…

  块被切断后，`下列选项…` 与选项 A 被归给了**上一题**（污染），
  而第 14 题的 stem 只剩前半段、**选项全丢**。
- **解决方案**：分清**两类噪声**——

  理由：真正的边界由**题号行**给出，不需要靠噪声来断。
  并给块加 `structural_warning`（有题干却无选项时显式标出）。
- **启示**：**"为修 A 加的规则，可能弄坏 B"**——尤其当规则是"见到 X 就做 Y"这种形态时。

## E49. remote 面不可用，但有更朴素的路

- **查到的机制**：`ctx.remote` 是**代码生成的类型化命名空间**，
  由 `@deepseek-ai/dsh-typert-generator` 在**构建期**生成。
- **决策**：**不做**。因为生成器 **不存在于安装的发行版里**（实测包目录里没有），
  手写一个 43KB 的生成文件去骗 loader 是**在骗宿主**。
- **替代路径（更朴素也更稳）**：
  · 宿主提供 `ctx.webServer.register({kind, path, handler})`，插件可注册自己的 HTTP 路由；
  · **客户端 bundle 的投放是白拿的**——`dsh-client-modules` 扫描 Loader 里声明了
    `dsh.client` 的包，自动 serve `/plugins/<id>/client.js` 并注入 boot 图。
- **启示**：**遇到"要用某个高级机制"时，先确认那个机制的前提在你手上是否成立。**
  而 HTTP 恰好让"界面"与"agent 工具"两条路**共用同一套判分实现**（都走 `submitAnswer`），
  这反而比 remote 更好：**不会出现第二套判分**。

## E50. 界面：两处"我以为是 bug，其实是我的断言过时了"

- **场景**：把题库从 20 题扩到 49 题后，`verify-real-bank` 红了 2 条。
- **根因**：两条断言都把**当时的题库大小**编码进去了：

  2. `order=missed` 取题池 与 `missed_recent` 列表**断言相等**——

- **启示**：**写死的数字是"当时的题库"的编码，而题库会长大。**
  断言要写**口径**（上限、序关系、包含关系），不要写**当时的数量**。

## E53. pnpm 对 `file:` 依赖用复制，且**不因源码改变而刷新**

- **症状**：改完代码、`pnpm add` 之后，profile 里的副本**还是旧的**（版本 0.0.1、

  |---|---|---|
  | 工作区根 `node_modules` | **软链**回 `plugins/` | 立即生效 |
  | profile 的 `node_modules` | **复制** | 需要重装 |
  所以"改了源码但行为没变"时，先怀疑**profile 里的副本是旧的**，而不是怀疑代码。
- **启示**：**"改了没生效"和"改错了"在现象上很像**，要有一条能区分两者的检查

## E54. 客户端插件的启动失败：又两道门禁（这次是作者修的）

- **背景**：上一轮修完服务端导入问题后，浏览器启动屏卡在 `Failed to load plugins`。
- **两个错，各是一道宿主校验**：
  1. `cannot get property "slots" without inject` —— cordis 的 inject 门禁读的是
     **模块导出的 `exports.inject`（服务名数组）**，而声明被写在了
     `package.json` 的 `dsh.client.inject`（**包名数组**）里。
     后者只进 boot manifest，宿主当前版本**不拿它装配 fiber 的 inject**。
     对照宿主自己的客户端包可证：`dsh-session-log-export` 导出
     `inject = ["slots", "locale"]`（**服务名，不是包名**）。
  2. `list slot "sidebar.footer.action" requires options.id` ——
     **list 型插槽的注册必须带 `options.id`**（在该插槽内唯一即可）。
     宿主自己的写法：`{ name: "conversation.input.overlay", id: "command-popup", order: 1 }`。
- **共同点**：两者都是**运行时门禁**——类型声明里看不出来，且只在
  **真启动到浏览器那一步**才暴露。我此前所有离线验证都到不了这里。
- **修法**：`exports.inject = ['slots']`；两个注册各补 `id`。
  作者另外新增 `scripts/check-client-inject.mjs` 作闸门（扫 `ctx.<服务>` 访问、
  对照导出的 inject）。它用**手写状态机**剥掉注释与字符串——比我临时用正则复查更严谨：
  我的正则把注释里的 `ctx.remote` 当成了真实访问。
- **启示**：**"声明写在配置文件里"与"声明写在模块导出里"是两件事。**
  宿主在哪一处读取，决定哪一处才算数——而这两者长得非常像。

## E55. 交互形态：常驻入口 vs 对话触发（我的设计被否掉）

- **作者原话**：*"一个出现在 dsh 界面内的刷题按钮很突兀……我更希望的是能通过
  对话里 agent 的调用来启动，就像对话时你给我一个链接，我点进去就开始刷题。"*
- **我为什么没想到**：我把"功能可达"当成目标，于是选了最省事的入口（常驻按钮）。
  作者要的是**入口要匹配意图的时效性**——刷题是由对话产生、也该由对话结束的意图，
  常驻按钮表达的是"这个功能一直在这儿"，而那不是事实。
- **改动**：删掉侧栏注册与组件；新增工具 `start_practice`；
  工具写**启动信号**（文件，因为工具在 agent preset 作用域、面板在 profile 作用域，
  两端不在同一棵树里）→ 面板轮询到就自动打开。详见 `docs/decisions/022`。
- **一个值得记住的对比**：**同一个问题，在"打开面板"与"取题"两个语境下处置相反**——
  · `start_practice` 题库名对不上：**不报错**（职责是开面板，面板会兜底），
    但把可选项列出来让 agent 自纠；
  · `get_questions` 题库名对不上：**报错**（取错题库的题不可恢复，ADR-020 决定 1）。
  **"遇到错误怎么办"没有统一答案，取决于那个错误能不能被兜底。**

## E56. 读日志读早了，于是误判成"日志缺失"

- **症状**：查 `trace.log` 想确认界面有没有真的取过题，发现**没有 `GET /bank`**，
  于是怀疑日志写入失败，还去查了文件大小与软链形态。
- **真相**：**我读的时候那行还没发生。** 再读一次就有了：

      19:20:27  APPLY_CALLED        ← 重启后的启动
      19:21:00  GET /bank bank=考公刷题-片段阅读与逻辑判断 n=1

- **根因**：读的是**那一刻的文件快照**，而学习者是在我读完之后才点的界面。
- **启示**：**"没看到"不等于"没发生"。** 涉及"某人刚刚做了什么"的排查，
  要把**自己读的时刻**也当成变量——先问清时间线，再下结论。
