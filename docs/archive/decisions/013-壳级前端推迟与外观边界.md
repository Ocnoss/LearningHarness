# ADR-013：壳级前端的推迟，与"只在 LH 会话内改外观"这条临时边界

- **背景**：项目的目标形态是 LH 有自己的界面——**点一个按钮就整体进入 LH 的页面，其中不含 dsh 原有元素**（作者 2026-09-16 明确表述）。在做到那一步之前，LH 需要先有一个"看起来像自己"的界面，才能继续开发与试用。
- **现状**：已完成两个客户端插件（`@lh/ui` 侧边栏标记、`@lh/theme` 配色套壳），它们都运行在 dsh 的界面之内。作者试用后确认**色调没问题**，但指出"总体效果和我想的还是不一样"——差别在于整体形态，而不在颜色。

## 决定

**1. 壳级前端（整体切换进 LH 页面）推迟，不在当前阶段开发。**
- 触发条件（作者主动提出）："这个可以先不开发先，我们可以接着开发 lh 的组件和架构"。
- 当前优先级：LH 的组件与架构。

**2. 在壳级前端实现之前，采用"只在 LH 会话内改外观"作为临时边界。**
- 实现：客户端插件订阅 `ctx.sessions.list`（ObservableSnapshot），读 `byId[current].agentPreset`，仅当其为 LH 的 preset id 时给 `<body>` 加 `lh-mode` 类；配色样式全部以 `body.lh-mode` 为前缀。
- 于是 dsh 自己的会话保持 dsh 原配色，LH 会话呈现 LH 配色——两套外观在 CSS 层面互斥，不依赖注入顺序。
- 读不到会话状态时**不套色**（宁可显示 dsh 原样，也不要错误地改掉宿主外观）。

**3. 客户端的扩展一律走宿主正式接口，不用固定定位之类的旁门。**
- 已落地的例证：`@lh/ui` 的标记从 `position: fixed` 元素改为占用宿主的侧边栏品牌槽位 `sidebar.brand.mark`；标记只在 LH 会话里**注册**，非 LH 会话撤销注册。
- 理由：占用槽位是布局的一部分，"与设置重叠"这类问题从根上消失；而固定定位是在与宿主的布局争位置，必然随宿主改动而失效。

## 依赖的前提

1. 宿主继续在客户端暴露 `ctx.sessions.list` 且其快照含 `byId[id].agentPreset`。**这是临时边界的唯一支点**；它若被移除，方案 2 需要重做。
2. 宿主继续提供 `sidebar.brand.mark` 等命名槽位。
3. 在壳级前端出现之前，作者接受"LH 的界面嵌在 dsh 界面之内"这一过渡形态。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| 推迟壳级前端 | 开发者（作者）在 dsh 界面里试用时反复受阻于"这不是我的产品"这一感受，以致影响继续开发——说明过渡形态撑不到组件与架构完成，应提前做壳 |
| 只在 LH 会话内改外观 | 出现"LH 会话里希望保留 dsh 原样、或 dsh 会话里希望用 LH 配色"的实际需求；或 `agentPreset` 不再出现在客户端快照里 |
| 走宿主正式接口 | 需要某个宿主没有暴露的 UI 位置，而唯一的绕过方式是操作宿主 DOM 结构——那时应把需求记为"等壳级前端"，而不是去动宿主的内部结构 |

## 未做的事（明确记录，避免被误认为已完成）

- 壳级前端、整体页面切换、以及"按钮"这一入口：**均未开发**。
- 因此当前任何"LH 看起来是自己的"效果，都只在 LH 会话的配色与一个侧边栏标记范围内成立。

- **状态**：已冻结（2026-09-16）
