# ADR-037：学习日历与日程 —— 日程是事件，日历是「计划 × 事实 × 课程安排」的一张表

- **配套文档**：`docs/日程插件建议.md`（建议层：在此之上还能做哪些日程插件）。本 ADR 只记**已经落地的那部分**与它的依据。

## 0. 一句话

**日程（`lh/schedule/*`）是计划，学习痕迹（`lh/trace/observed`）是事实，课程事件（`lh/course/*`）是结构变化；日历把三者按同一条日期轴并到一张表上。** 把"排的计划"和"做的事"放在同一天，才能回答一个此前没人能回答的问题：**我排的和我做的，对得上吗？**

## 1. 决定（一）：日程 = `lh/schedule/*` 事件的投影

五个动词（additive，旧事件永远可重放）：

| 动词 | 语义 | data 关键字段 |
|---|---|---|
| `lh/schedule/created` | 新建一条日程 | `item_id, title, day, start?, end?, kind, note?, course_id?, session_id?, minutes_planned?, tz?, source?` |
| `lh/schedule/updated` | 改字段（**只带真的改了的键**） | `item_id` + 要改的键；`null` = 清空 |
| `lh/schedule/linked` | 绑课程 / 绑对话 | `item_id, course_id, session_id`（**缺字段按"清空"读**） |
| `lh/schedule/done` | **事实**：这次计划真的发生了 | `item_id, done_at, session_id?, minutes_actual?` |
| `lh/schedule/cancelled` | 撤销（可恢复） | `item_id, reason?` |

日程项字段：`item_id / title / day / until / start / end / kind / status / course_id / session_id / note / minutes_planned / minutes_actual / tz / source / created_at / updated_at / done_at / cancelled_at / cancel_reason / history`。
（`until` = 验收期窗口的最后一天，2026-10-09 追加，见 §11.1。）

**投影的唯一实现在 `plugins/lh-schedule/schedule.js`，写入的唯一路径在 `commands.js`。** 界面（`@lh/schedule-ui` 的三条 POST 路由）与 agent 工具走的是**同一份 commands**——所以"在日历上点的"和"模型建的"日程在日志里字节级同形（与 ADR-035 的分工同形：判断归 agent，机械动作归界面，只有一条写路径）。

### 1.1 为什么 `scope` 是 `schedule/<item_id>` 而不是 `course/<node_id>`

日程是**独立对象**，课程只是它的一个字段。写进课程作用域会立刻遇到两个表达不了的形状：
"这条日程同时与两门课有关"，以及"先建日程、后绑课"（那时 scope 已经写死在不可改的信封里了）。
所以：信封记它自己的坐标，课程关系放 `data.course_id`。日程**可以没有课**（"明天上午背 40 个词"不属于任何课程）。

### 1.2 为什么"撤销"是一种事件，而不是删除

同 ADR-036：append-only 下没有真正的删除。撤销 = 追加一条说它从此刻起不可见。
它因此**不需要两段式确认**（规则 4 的白名单纪律针对的是**不可逆**的破坏性操作）：撤销之后日程仍在日志与日历上（标成"已撤销"），
也能用 `update_schedule` 的 `status:"planned"` 恢复。**要求给原因**才是这里该坚持的事——"为什么这次没做成"
只在撤销那一刻知道，事后补不出来，而它是学习诊断里信息量最大的一类数据。

## 2. 决定（二）：日历 = 三类东西按日期索引

`buildCalendarView(events, { from, to, tz, courses })`（`calendar.js`，唯一视图组装）每天一个桶：

- **计划**：日程项。一条日程可以**在多于一天露面**——排在前天、昨天才做完的那条，会出现在**昨天**
  （因为"昨天真的学了"才是要被看见的事实），`appearances` 记全 `['planned','done']`。
- **事实**：`lh/trace/observed`（记录器插件一直在写的坐标事件）按 `session_ref` 与天分组 → "这天哪段对话动过、动了几下"。
- **课程安排**：`lh/course/*`（建课/改名/绑会话/删课）→ "课程结构什么时候变的"。

**为什么不做成两个界面**：分成"计划"与"记录"两个页面，就对不出账了；而对账（排了没做 / 没做却学了）
正是这个功能存在的理由。空日子也保留在 `days` 里（**空也是一种数据**：连着一周空 = 计划失效的信号）。

**`overdue` 是全局口径，不是区间口径**（`summary.overdue` 与 `list_schedule` 的 `overdue[]` 同义）：
它回答"我总共欠了多少"，而那个数字**不该在翻月份时跳来跳去**——"这个月欠 3 条、上个月欠 8 条"
会让人以为债自己消失了。区间内的"哪天欠着"由格子上的欠徽章表达，界面上的标签因此写明"（全部，不只本月）"。

**事实的日期优先用 `data.time`（宿主事件本来发生的时刻），退到信封 `timestamp`（我们记账的时刻）。**
补写历史（重放/迁移/离线导入）时两者会差很远，而"这次学习发生在哪天"应以发生为准。

## 3. 决定（三）：`done` 是独立事件，不是一条 `updated` 补丁

契约 §2.2 的写入口诀："这件事单独拿出来，对学习诊断有没有意义？"——**有**：
"按计划完成了这次学习"是**计划与现实的接点**（哪条计划、什么时候、在哪段对话里、花了多久），
它是策略评估（ADR 未冻结的那条：动作携带预测、事后对账）唯一的数据源。所以它单独成一个动词。

一次工具调用可能写多条事件（"标记完成 + 绑到当前对话" = `linked` + `done`，顺序 `updated → linked → done`）：
写细读粗（§1.3）——它们在语义上是两件事，分开记才能在日志里分别被引用。

**已知形状（不是 bug，但要知道）**：撤销后恢复（`status:"planned"`）**不会清掉 `cancelled_at`**，
所以那条日程在"被撤销的那天"仍留一个 `cancelled` 露面。那确实是发生过的事实；若要它消失，就得删日志。

## 4. 决定（四）：日期存"墙上时间"，时刻读的时候才按调用方时区折算

- **计划**用**没有时区的墙上时间**：`day` = `YYYY-MM-DD`，`start`/`end` = `HH:MM`。
  它不需要换算，也不会因为夏令时或换机器而漂移；写的时候把当时的时区记进 `tz` 只为将来说得清。
- **事实**是带时间戳的绝对时刻，读的时候按**查询方给的时区**折算成"哪一天"（`dayKeyOf`，走 `Intl` 的 `timeZone`，
  不自己减偏移——手算会在夏令时切换那天错一小时，而那恰好是"排了 09:00 的日程"最容易出问题的一天）。

**已知的口径差（如实记下）**：

| 消费方 | 用哪个时区 | 后果 |
|---|---|---|
| 日历界面 | **浏览器时区**（`Intl.DateTimeFormat().resolvedOptions().timeZone`，随请求发给服务端） | 与学习者看到的一致 |
| agent 工具 `list_schedule` | **宿主进程时区**（工具这一侧没有浏览器上下文） | 跨时区使用时可能与界面差一天，返回值里有 `tz_fallback` 与 `notes` 说明 |
| 运行时上下文 `lh:agenda` | 同上（进程时区） | 同上；工具描述里因此要求模型**优先给绝对日期** |

时区认不出时**回退到 UTC 并如实标注**（`tz_fallback: true` + `notes` 里一句话），不静默当成本地时区——
那样"某天少了两条活动"会查不出来。

## 5. 决定（五）：与宿主「自动化任务」划清边界，并且刻意不同名

宿主自带一个可选 bundle（`@deepseek-ai/dsh-experimental-schedule-bundle`，实测本机 **enabled: false**），
它给根 agent 的 `schedule_create / schedule_list / schedule_update / schedule_delete` 是**会话绑定的定时提醒**
（一次性/每日/每周/cron，到期以 user 消息投递）。**那是提醒，不是学习计划。** 两件事都合法，但不能混：

| | 宿主「自动化任务」 | LH 的 `@lh/schedule` |
|---|---|---|
| 是什么 | 定时提醒（时间 → 投递一句话） | 学习计划的对象（日期 + 内容 + 课程 + 完成事实） |
| 绑定 | 会话 | 可以绑课程与会话，也可以都不绑 |
| 能不能复盘 | 不能（它不是事件溯源的一部分） | 能（`lh/schedule/*` 全部可重放、可对账） |
| 工具名 | `schedule_create / ...`（名词-动词） | `create_schedule / list_schedule / update_schedule / cancel_schedule`（动词-名词，同 LH 既有 `create_course` 一路） |

两套名字**刻意不撞**（撞了就会出现"模型以为在排学习计划、其实在设闹钟"这种静默错配）。
"到点提醒我" → 用宿主的自动化任务；"我哪天学什么、学了没有" → 用这里的四个工具。
`docs/日程插件建议.md` §5 另有一条"桥"的建议（只做翻译，不自建定时器）。

## 6. 决定（六）：装载安全的硬约束——preset 那一半不许依赖 `@lh/course-tree`

**事实（实测）**：preset 行按**绝对路径**从源码树加载（`agent.cordis.yml` 里所有 LH 行都是这个形状），
而源码树的 `node_modules/@lh/` 下**只有根 `package.json` 声明过的包**——
`node_modules/@lh/event-store` 存在，`node_modules/@lh/course-tree` **不存在**。

**后果（如果真的写了那条导入）**：导入失败 → 该行不激活 → **整个 preset 的所有会话都建不起来**（契约 §〇 形态②，
症状是"LH 坏了"，与本项目最贵的失败形状一模一样）。

**所以**：`@lh/schedule` 的静态导入链只允许 `@lh/event-store/*`（实测在根 node_modules 里）+ 包内相对导入。
课程清单因此**当参数收**（`buildCalendarView(..., { courses })`），由拿得到 `@lh/course-tree` 的那一半
（profile 里的 `@lh/schedule-ui` 服务端）喂进来。

**这是"把 2 个包拆成 2 个包"的真正理由**，不是分层审美：两半的**加载位置不同，能解析到的依赖就不同**。

## 7. 决定（七）：安装的顺序纪律写成代码，而不是写成一句提醒

契约 §5.6.5 的顺序是：**备份 → 闸门绿 → 加行 → 真会话验证 → 失败则回滚**。
本次加的是**两个新包**，而 `scripts/sync-lh-deps.mjs` **只更新已存在的副本**（源码里 `if (!existsSync(t.dir)) continue`），
所以新包靠它落不了地；正常路径是 `pnpm install`，而本项目的规则是**不要**在 profile 里跑包管理器
（副作用半径太大，见 sync-lh-deps 顶部）。

于是新增 `scripts/install-lh-schedule.mjs`，把"装包 + 接线"做成**一件事**，并把顺序写成代码：

1. 逐文件复制到 `profiles/<名>/node_modules/@lh/<短名>/`，**复制后读回来算 sha256 校验**；
2. 从**副本**（生产路径，不是源码）`import()` 两个包，并用**假 ctx 真跑一次 `apply()`**，
   看它注册了哪些工具/路由/上下文、有没有抛；
2b. **客户端 bundle 的语法检查**（唯一一条还能把界面弄坏的路径）：真去 `import()` 它，
   **只看抛的是不是 `SyntaxError`**——语法没错的话它会在读完 `window` 时立刻停下
   （浏览器里 `window` 存在，那条路径永远不会走到），于是"抛非语法错 = 至少能被解析"。
   同时静态断言 `__ModuleLoader__.load` / `exports.inject` / `exports["./package.json"]` 三件事都在
   （契约 §2.1 与 §2.4：漏掉任何一条的症状都是浏览器卡在 `Failed to load plugins`）；
3. 把 `package.json` 的 `lh` 自我描述与真跑出来的结果对照（契约 §五之七）；
4. **只有 1~3 全绿才动组合文件**，改前一律备份（`.lh-sync-backup/schedule-install-<时间戳>/` + 一份
   `manifest.json` 清单，回滚只认清单——**第一版按"相对仓库根的路径"备份，而那些文件根本不在仓库里**
   （`C:\Users\Administrator\.dsh\...`），回滚会把它们还原到错误的路径上）。

任何一步失败 → **一个字都不改**，退出码 1。`--dry-run` 只看不写；`--rollback` 只恢复组合文件与 package.json
（不动事件日志）；`--live` 是重启之后的联调（打 `/health`、`/calendar`，然后**真建一条日程再撤掉**，
证明写路径通到底）。

### 7.1 它必须扫"所有的家"，并且**镜像 course-tree 挂在哪一层**

这是本次最容易做错、也最值钱的一段，因为 `ARCHITECTURE.md` §73 把这条写成了本项目**最贵的失败形状**：

> "装进 `profiles/web` 的界面插件，在 desktop 应用里永远看不到——而这个症状与'忘了重启'一模一样。"

实测（2026-10-09）：

| 事实 | 怎么测出来的 |
|---|---|
| `DSH_HOME = C:\Users\Administrator\.dsh` | 环境变量 |
| 那个家下面有 `profiles/desktop`、`web`、`dev`、`headless` | 列目录 |
| 仓库里**还有**一个自持的家 `D:\LearningHarnessv0.1\.dsh`（`lh-dev.mjs` 用的），它也装着一整套 LH 插件 | 列目录 + 读它的 `cordis.patch.yml` |
| **作者正在看的界面来自 `profiles/desktop`** | `Get-NetTCPConnection -LocalPort 19387` → 监听者是 **`DeepSeek Harness.exe`（桌面应用）** |

而两个家的既有结构**不一样**（这不是偶然，是两次不同的决策留下的）：

- `profiles/desktop`：`@lh/course-tree` 是 **profile 行**（"让五个工具在所有会话里可用，不只 LH 模式"）；
- `profiles/web`（两个家都是）：`@lh/course-tree` 是 **preset 行**，profile 只挂界面插件。

所以脚本**不自己发明位置**，而是读既有组合文件、**镜像**它：
哪个 profile 已经有 `@lh/course-tree` → 把 `@lh/schedule`（工具）与 `@lh/schedule-ui`（界面）加到那里；
哪个家的 lh preset 里有 `lh-course-tree` → 把 `lh-schedule` 加到那里。
**界面那一半永远在 profile 层**——它 inject `webServer`，而 preset 是 agent 作用域，够不着 host 面服务（契约 §一.1）。

本次实际落地：`DSH_HOME/desktop`（工具 + 界面）、`DSH_HOME/web`（界面 + preset 里的工具）、
仓库家 `web`（同上）。**三处都是生产副本，三处都真跑了 `apply()`。**

**⚠ 一个实测出来的同步范围缺口（2026-10-09 踩到）**：`scripts/sync-lh-deps.mjs` 只扫
**当前 `DSH_HOME` 下的 profile**（源码里 `dshHome = process.env.DSH_HOME || ~/.dsh`），
所以**仓库自持的那个家它永远同步不到**。表现是：改了源码之后跑 sync，
`DSH_HOME/desktop` 与 `DSH_HOME/web` 更新了，而仓库家 `web` 还停在旧版本——
而"两个家里有一份是旧的"与"改了没生效"从外面看一模一样（本 ADR §7.1 那条最贵的失败形状）。
**所以：改完源码要跨家同步，跑的是本脚本（它扫所有的家），不是 `sync-lh-deps.mjs`。**
`selftest-routes.mjs` 会对**每一份副本**各跑一遍，正是为了让这种不一致当场红。

`@lh/workspace-ui`）同样返回 404、首页返回 401**——所以那是桌面宿主的鉴权/投放路径问题，
不是本包的证据。**这一条只能靠人看一眼**（重启应用 → 侧栏应出现 🗓）。

**该记住的教训（关于"环境坏了"这个结论）**：本会话早期的 `pwsh` **每一次**都以
`0xC0000142`（`STATUS_DLL_INIT_FAILED`）退出——前台、后台、简单命令都一样。
我据此判定"沙箱里跑不了代码"，并**因此**把整个安装设计成
"先逐字节校验、再真跑 `apply()`、全绿才加行"（§7）。后来同一个工具**自己恢复了**，
于是闸门与联调都真跑了，并且——

> **那个设计抓到了一条会让 dsh 完全起不来的真错**：`plugins/lh-schedule/index.js`
> 把 `todayAgenda` 从 `./schedule.js` 导入，而它实际在 `calendar.js` 里。
> 若当时按"我读过一遍，应该没问题"直接加行，**整个 LH preset 的所有会话都会建不起来**。

所以这条教训是双向的：
1. **"环境坏了"必须先复验**（我用了错误的结论做了半小时的设计决定）；
2. 但"因为环境坏了所以跳过闸门、凭读过一遍就上线"是**错的**——
   上面那条导入错正是"读过一遍"抓不到、而"真跑一次 import"一眼就抓到的东西。
   该保留的是那个设计，不是那个结论。

**未验证清单（已收窄）**：
1. **面板的观感**（见上，需人看一眼）。
2. `list_schedule` 的嵌套输出 schema 在真实工具调用下的校验（宿主 `assertSupportedJsonSchema`
   已由 `check-preset-mount` 覆盖形状，但"运行时返回是否被接受"要到第一次真调用才知道；
   其余三个工具的返回值与 schema 已逐字段核对过）。
3. `update_schedule` 的 `session_id: "current"` 在**真**工具调用里拿会话 id 的那条路径
   （靠 `exec.agent.session.id`，与 `@lh/course-tree` 的 `enter_course` 同一形状、同一实测依据）。
4. **`lh:agenda`（118）与 `lh:course`（117）同时注入**——本会话实测两者都在（`lh:course` 未绑定课程时注入空串），
   且 `systemPrompt` 契约表明 `contexts` 是数组、只有同名才遮蔽，所以这条基本可以当结论用。

## 9. 边界与失效信号

- **不做的事**：不做定时提醒（宿主已有）、不做双向日历同步（会出现第二个事实源）、
  不把 LLM 的判断写进 `lh/schedule/*`（日程项只记人的安排；模型可以**建议**，落笔仍是一次带 actor 的写入）。
- **日志只会变大**：`readEvents()` 全量读在日志小的时候够用；一旦"按日期区间点查"变慢，
  就该换存储（ADR-012 决策 1 记的失效信号）。日历按天分桶已经避免了 O(条数 × 天数)，但全量读这一步还在。
- **失效信号**：如果某天发现"日历上的日期与学习者看到的不一致"，第一件事是查 `tz_fallback` 与 `notes`，
  第二件事是查 `apps` 的进程时区——那是 §4 那张表里唯一会静默出错的地方。
- **`docs/日程插件建议.md` 的两条实现侧待办，本次已核**：
  ① `lh/schedule/updated` 确实是**逐次 append-only**（`commands.js` 只写真的变了的键，不覆盖），
  所以"这条计划被推迟过几次"有数据源（`history` + 多条 `updated`）；
  ② `lh:agenda` 与 `lh:course` **可叠加**（见 §8 第 6 条）。

## 11. 追加（2026-10-09，按作者当天反馈）

作者反馈四件事：①「保存」与「月」按钮白底白字；②要**验收期**（可以是模拟考 / ddl / 最终大考），
带倒计时显示在下端、与课程联系；③「这天动过的对话」改叫「当日会话」；④进一步测模型的日期编排能力。
③是措辞，②④见下，①值得单独立一条纪律。

### 11.1 决定（八）：验收期 = 一种日程类型 + 一个可选的**窗口终点**，倒计时是派生量

**不新增事件族。** 验收期"就是一条日程"——有日期、能绑课程、能标记完成，所以直接复用
`lh/schedule/*`。新增的只有两样，两样都是**人排的**：

- 两个 `kind`：`mock`（模拟考）、`final`（最终大考）。连同已有的 `exam`/`deadline` 构成
  `MILESTONE_KINDS = ['exam','mock','final','deadline']`（`deadline` 就是作者说的 ddl）。
- 一个可选字段 `until`：**验收期的最后一天**。"期"是个窗口，而窗口的两个端点都是人排的，所以它进日志。

**倒计时不进日志**（ADR-014「可派生的不进日志」）：`milestoneCountdown(item, today)` 是纯函数，
四种相位分开说，因为它们要说的话完全不同：

| 相位 | 条件 | 说出来的话 |
|---|---|---|
| `before` | `today < day` | 还有 N 天 |
| `today` | `today === day` | 就是今天 |
| `during` | `day < today <= until` | 进行中，还剩 N 天 |
| `past` | 其余 | 已过 N 天（**如实显示，不评判**——它还是 planned 只说明没人标记完成，那是数据不是罪状） |

**没有 `until` 时"过去"就是过去**，不会一直停在"进行中"——把"没有终点"解释成"永远进行中"
就等于没有倒计时。

**倒计时是全局的**（与 `overdue` 同理）：12 月的期末考在 10 月的日历上必须照样显示"还有 71 天"，
否则"翻到那个月才看得见"就等于没有倒计时。

**它出现在三个地方，共用同一个渲染**（`countdownText`，唯一实现）：
- 日历面板**下端**的倒计时条（作者指定的位置；它是背景信息，应该一直看得见）；
- `list_schedule` 的 `milestones[]`（全局，带 `countdown.phase/days_left/days_to_end`）；
- 运行时上下文 `lh:agenda`（**紧跟"今天是哪天"那一行**——它决定"这周该排多密"，
  是模型排计划时第一个该看的东西）。

**验收期的窗口在日历上只落在起点那一天**，不铺满整段窗口：铺满会让一格里塞进 N 天的同一条，
而"进行中，还剩 N 天"由倒计时条负责。这是取舍，不是遗漏。

### 11.2 决定（九）：客户端配色的**令牌铁律**（"白底白字"事故的产物）

作者反馈的两个按钮（`保存` 在编辑表单里、`月` 是选中态的模式切换）都是 `primary: true`。
根因不是"颜色选得不好"，是**用错了令牌类别**：第一版写的是

```
background: var(--dsw-alias-brand-primary)   // ← 把"强调色"当底色
color: '#fff'                                // ← 又硬编白字
```

而宿主的主题令牌表（Inspect 实测 14 个）里，`--dsw-alias-brand-primary` 的定义是
**"Primary brand accent"**，并且**没有任何 on-brand / label-on-accent 前景令牌**——
也就是说"以强调色为底该配什么前景"这件事，主题根本没承诺。当前配色下它是浅色，白字于是消失。

**铁律（此后所有客户端插件都按这条写）：**

> **底色只用 surface 令牌（`--dsw-alias-bg-*`），文字只用 label 令牌（`--dsw-alias-label-*`），
> 强调色（`brand-*` / `state-*`）只做边框、圆点与"非文字"的标记。**

"选中/主要"因此做成：更亮一层的 surface + **强调色边框** + 加粗的 label 文字——
对比度由主题自己保证，我不需要（也做不到）看着调。同一条也适用于徽章：
`今天` / `欠` 徽章从"强调色底 + 白字"改成"surface 底 + 强调色边框"。

**这一条建议上升进 `archive/PLUGIN_CONTRACT.md` §二（客户端插件）**——它是一条
"不看结果就会写错"的规则，而作者看不见代码的运行结果，正是本项目的固定约束。

### 11.3 措辞：右列第二块从「这天动过的对话」改为「当日会话」

作者指定。语义没变（数据仍来自 `lh/trace/observed` 按天分组），"当日会话"更短、也更中性——
原来那句"动过的"带有"我判断它算活动"的味道，而这个判断属于记录器/分类器，不属于一块标题。

### 11.5 顺手发现的两件事（都记下来，都不属于本次改动）

**(a) 宿主对"未在 schema 里声明的工具参数"是静默丢弃的。** `[实测]` 上表第 7 条：
模型传了 `until`，而**在线插件的 schema 里没有这个参数**，宿主既不报错也不转达，
工具正常返回。结果调用方以为设好了窗口，而日志里什么都没有——
比报错更糟，因为它让"看起来成功"和"真的成功"变得无法区分。
**建议补进 `archive/PLUGIN_CONTRACT.md` §一.2**：声明式 schema 是唯一契约，
**没声明的参数会消失**，所以"加了字段却没加进 schema"= 字段不存在。
（本次已在 HTTP 写路由上加了一道硬护栏：不认识的字段一律 400 + 列出可用字段名，见 §11.2 同款纪律。
工具那一侧做不到——host 传给 `execute` 的 args 已经过 schema 过滤，被丢弃的字段在插件里根本看不见。）

**(b) `lh-recorder-trace` 现在收不到事件了——日历的「当日会话」这一栏因此是死的。**
证据链：
- `data/events.jsonl` 里 `lh/trace/observed` 共 981 条，**最后一条是 2026-09-22**；
- 今天（10-09）`plugins/lh-recorder-trace/trace.log` 里有 5 次 `APPLY_CALLED` + `LISTENING`，
  但**没有任何 `INDEXED` / `SKIP_NOT_LEARNING_SESSION`**——而本会话确实是 lh preset
  （`lh:agenda` 注入生效就是证据），所以它本该收到事件；
- 于是：**记录器挂着、`apply()` 也跑了，但 `ctx.on('session/event', …)` 没有回调**。

**归因（标为假设，不当结论）**：今天有 5 次 `APPLY_CALLED`，是因为我在反复改
`cordis.patch.yml` / `agent.cordis.yml`（装日程插件的那几轮）——每次改都触发一次插件树重载。
而这正是 `cordis.patch.yml` 顶部早就写着的风险：*"上游既然写'生命周期尚未测试'，
说明它可能有未发现的半重载状态。"* 一个"全局订阅"在半重载后**没有报错、只是不再回调**，
正是那种症状。**下次重启后应当先看这一条有没有恢复**（一行命令：数一下今天有没有新的
`lh/trace/observed`）——它决定日历的第二栏什么时候活过来，也决定
`docs/日程插件建议.md` 第 2 条（计划 vs 实际对账）有没有数据可用。

（本次改动**不涉及**记录器：它的源码一个字没动，它的最后一条事件也远早于本次工作。）

### 11.6 §11.2 那道护栏抓到的东西（`selftest-routes.mjs` 首跑，2026-10-09）

新写的路由自检第一次跑就抓到三类问题，**没有一类是"测试写错了"**：

1. **仓库家的那份副本是旧的**（连 `milestones` 都没有）——根因就是 §7.1 末尾那条同步范围缺口：
   `sync-lh-deps.mjs` 只同步 `DSH_HOME`，另一个家要跑安装脚本。
2. **`DSH_HOME` 的两份副本是"有护栏但白名单还没加 `source`"的中间态**——因为我在两次同步
   **之间**改了白名单。这条说明一件事：**中间态是真实存在的状态**，而"我改完就跑过闸门了"
   不等于"所有副本都在同一版上"。（顺带：`--live` 自检脚本自己就发 `source`，
   如果没加进白名单，**下一次联调会被自己的护栏挡在门外**——那是自检与护栏互相打架。）
3. **旧副本真的把那条垃圾写进了日志**：没有护栏 → 未知字段测试返回 200 → 日志里多出一条
   `【路由自检】不该被写下去` 的日程（作者当天在日程注入里直接看到了它）。
   自检因此加了一段**自我收拾**：一旦发现"本该被挡却写进去了"，立刻把那条撤销掉并报出来，
   免得每跑一次旧副本就往学习史里塞一条谁也不认识的日程。

三条都指向同一个结论：**"我改了"与"它在跑的是这一版"是两件事，必须每次都用可观察的证据分开。**

### 11.7 表格可读性与动效（作者第二次反馈："单元格内容太多会挤压其他单元格"）

反馈原文：*"表格视图在单元格内容太多的时候会挤压其他单元格，导致总体表格不可读，对每个单元格内显示内容做省略，然后美化动效和视觉效果。"*

#### 根因有**两条**，都必须修（只修一条会留一半）

**① 横向：`repeat(7, 1fr)` 的 `1fr` 隐含下限是 `auto`。**
这是 CSS Grid 的经典陷阱：`1fr` 等价于 `minmax(auto, 1fr)`，而那个 `auto` 是 **min-content** ——
只要某一格里有不能断行的长内容（一句没有空格的长标题就够了），那一列就会**撑破自己的 1/7**，
把其余六列挤窄，整张表随之不可读。
**修法**：`gridTemplateColumns: 'repeat(7, minmax(0, 1fr))'` + 每格 `minWidth: 0` + `overflow: hidden`。
列宽从此**只由容器决定，与内容无关**。

**② 纵向：`minHeight` 会让"内容多的格子"变高，而 `1fr` 布局会把整行拉齐到最高的那一格。**
于是同一天里别的格子被拉出大片空白，格与格的对齐也乱了——这也是"不可读"的一半。
**修法**：格子改成**固定高度**（`CELL_H = 100px`）+ `overflow: hidden`，
超出的内容由底部一行 `还有 N 条…` 交代——**信息不丢，只是收起**，这正是"省略"该有的形状。

#### 省略的**四件套**（缺一即失效）

每一行文字都必须同时具备：`whiteSpace: nowrap` + `overflow: hidden` + `textOverflow: ellipsis` + **`minWidth: 0`**。
最后一条最容易被忘：flex/grid 子项的默认最小尺寸是 `auto`（min-content），
**少了它，前面的 `ellipsis` 根本不会生效**——元素会先把容器顶开，再"优雅"地不省略。
日号与 `今天`/`欠` 徽章则相反，一律 `flex: 0 0 auto`：**它们不允许被挤**。

#### 动效：只能用它，而且要能关掉

宿主明说"不要在组件外写 DOM / 不要 append 到 body"，所以不能注入 `<style>`，也就**没有 @keyframes**
（`@lh/workspace-ui` 踩过同一条）。所以在内联样式里能表达的只有两件事，本次都用了：

- **`transition` + 挂载后翻一个 state**（`useEnterStyle(key)`）：网格按**月份**重播、右列按**选中日**重播、
  验收期条按**条目数**重播。实现细节里有一个坑：翻 state 必须等一帧（`requestAnimationFrame`），
  否则同一帧内 0 → 1 不产生过渡——**内联动效最常见的哑火原因**。
- **hover 状态**：格子微微上浮 1px + 底色抬一层。

**并且问一句"要不要动效"**：`prefers-reduced-motion: reduce` 命中时把时长**整个关掉**（`transition: none`），
而不是缩短一点——动效对一部分人是真的难受，半吊子的尊重不算尊重。

**层级用边框与字重表达，不用底色**：选中 = 内嵌品牌色描边，今天 = 内嵌中性描边，
最近的验收期 = 强调色边框 + 加粗数字。理由见 §11.2 的令牌铁律——
底色要留给 hover，否则"我选中的"和"鼠标底下的"会分不清。

#### 边界与诚实交代

- 本次**只动客户端**（`client.js` 一个文件）：事件、schema、路由、投影都没变，没有迁移问题。
- **我仍然看不见界面**：以上是"为什么这样写"的推理，不是"看起来好看"的结论。
  观感必须作者看一眼（重启应用后侧栏 🗓）。
- 一个已知的粗糙边：如果某天**既有超过 3 条日程、又被服务端截断**，最后一行可能被裁掉几个像素。
  取舍是"格子永远一样大"优先——格子会随内容长高的那种表格，就是这次要修掉的东西。

### 11.8 编辑能力、无限期推迟与「待办区」（作者第三次反馈，2026-10-10）

作者的原话是这次设计的**出发点**（比需求本身更重要）：

> "日程很有可能是模型生成的，在确定生成的时候可能用户没有详细的审阅，或是有突发情况打断，
> 这需要日程的编辑功能，包括取消日程、推迟日程等……对于推迟的日程除了选具体的日期，
> 也支持无限期推迟，这样对应的日程放到代办置顶的位置。"

#### (a) `day` 从"必填"变成"**可清空**"——一个字段解决两件事

- **创建时可以不给日期**：`create_schedule` 的 `required` 从 `['title','day']` 收到 `['title']`。
  不给日期 = **待办**（不至于硬塞一个假日期、让日历上多出一条假的）。
- **推迟可以不给日期**：`update_schedule({day: ""})` = **无限期推迟**（从日历上拿下来、放进待办）。

于是四个动作齐备，全部复用既有词汇、**不新增事件族、不新增动词**：
提前完成（`status:done`）/ 推迟到某天（`day:<日期>`）/ 无限期推迟（`day:""`）/ 取消（`cancel`）。

**投影里一处关键改动**：`updated` 的 `day` 判据从"解析出来的值非不非空"改成
**"data 里有没有这个键"**。前者会让"清空日期"**永远写不进去**——那正是本项目记过很多次的静默失败形状
（`until` 一直用的是"键存在"判据，这次把 `day` 对齐过去）。
另一条：清掉日期时**窗口（`until`）跟着一起清**，否则会留下"没有起点的窗口"这个投影读不出、
界面也画不出的状态；而且这次自动清空**必须**在 `changed` 与事件里留痕（否则重放时窗口会自己消失）。

#### (b) 「待办区」= 同一个包的**第二个** main 面板（`lh-todo`）

不另开插件包：它读同一份投影、走同一条写路径，只是排布不同（列表 vs 网格）。
`buildTodoView()` 就是 `/calendar` 的视图**再重排**——滤掉空日子、只留 `planned`、
把 `backlog`（无日期待办）与 `overdue`（欠账）提到最前。作者要的"放到待办置顶的位置"落成：
**无日期待办那一组带一道强调色左边框，排在最上面**。

**它必须与日历口径不同，而这个不同是有理由的**：

| | 日历（记录视图） | 待办区（决策视图） |
|---|---|---|
| 已完成 / 已撤销 | **要显示**（✓ / 删除线）——那是"发生过什么" | **不显示**——列表只该回答"接下来做什么" |
| 空日子 | 要显示（连着一周空 = 计划失效的信号） | 不显示（几十个空桶是纯噪声） |
| 无日期待办 | 不出现（它不占任何一天） | **排在最前**（等你决定：定日子还是撤掉） |

两条口径都是**自检抓到的真错**：① 第一版把已撤销的日程也列进了待办区（自检数据一多，
十几条删除线挤在同一天）；② 第一版的起点用了 `buildCalendarView` 的默认（= 本月），
于是"11 月 20 日"这样**已经定好日子**的日程在 10 月看**看不见**。修法：起点改成**今天**——
待办区回答的是"接下来"，而"接下来"必然跨月。

#### (c) 视觉重做：从"发丝线连成的表"到"有呼吸的瓷砖"

作者反馈"工作日和周末的填色比较僵硬，边界缺少过渡，边角过于锋利"。

- **边界**：原来靠 `gap:1px` + 容器底色当分隔线 → 改成**真间隙 4px** + 每格自己的圆角（8px）
  与描边；边界由间隙自然断开，不再是一条贯穿的直线。
- **周末**：从**平涂**改成自上而下的**渐变**（`linear-gradient` 到 78% 处收进底色）——
  仍然一眼看出哪两天是周末，但边界是渐隐的。
- **空位不留痕**：月首/月末的占位格原来是填色块，等于在说"这里也是一格，只是空的"；改成透明。
- **今天**：不再用第二圈描边（会和"选中"打架），改成**日号加粗 + 一个品牌色小圆点**；
  **选中**保留品牌色内嵌描边；**hover** 抬起 1px + 一层极浅投影。
- 全部只用内联样式能表达的东西（`transition` / `linear-gradient` / `box-shadow`），
  且 `prefers-reduced-motion` 命中时仍然整个关掉。

#### (d) 顺手修掉两条**闸门自己的毛病**（都是这次踩出来的）

1. **自检在往真实学习史里写数据**。每跑一次路由自检，作者的日历里就多两条"【路由自检】…"
   （乘三份副本）——而作者上一轮问的正是"我担心存储浪费"。
   修法用的是项目**本来就准备好**的那个缝：`eventLogPath()` 是**惰性求值**的，
   `lh-event-store/store.js` 的注释写着它为什么这样设计——
   *"静默的后果是测试把假数据写进了真实的学习史"*。
   于是自检把 `LH_EVENT_LOG` 指到一个临时目录，跑完删掉。
   **顺带把断言变强**：事件计数从 0 开始，"400 时一个字都没写"于是成了确定的事实，
   而不是"前后差为 0"这种可能被巧合满足的形状。实测：真实日志 **0 字节增长**。
2. **Windows 上 `rename` 到正被 dsh 打开的文件会失败**。症状是"装完第一次跑报失败、
   紧接着第二次就过"——两次之间只差时间，于是人会开始怀疑改动本身，而不是怀疑文件锁。
   宿主的 `writeFileAtomic` 对同一件事用的是**有界指数退避**（它的注释里写着），照同一条做法加上重试。
   现在第一次跑就是绿的。

#### (e) 验收更新

- `check-all`：**28 绿 / 1 项应然红**（共 29 项），其中 `@lh/schedule` **101 条断言**、
  `@lh/schedule-ui` 路由自检 **120 条断言 × 3 份副本**（新增：不给日期能建、定日子后离开 backlog
  并出现在那天、空 `day` 清日期且 `changed` 如实报、已撤销的不进待办区）。
- 真实日志体积：**0.59 MB**（150 条日程事件 = 10.2%；`lh/trace` 仍占 84.8%）。自检不再增长它。

### 11.9 待办区**并进**学习日历（作者第四次反馈："将代办区集成到学习日历里"）

**改法**：撤掉上一版"第二个 main 面板 + 第二个侧栏图标"，把待办做成**日历的第三种读法**
（头部按钮 `月 / 周 / 待办`）。同一份数据的入口回到**一个**。

**为什么这个方向是对的（不只是照办）**：

- "我排了什么"（网格看结构、看空档、看验收期）与"接下来做什么"（列表看顺序、做决定）
  是**同一个问题的两面**，上一版却把它们拆成了两个入口；
- 拆开之后必然长出"两套头部、两套忙碌状态、两条提示"——一个视图里有两套"正在忙"，
  是界面开始骗人的起点。所以这次重构把取数/忙碌/提示/错误**全部收回**给 `CalendarPanel`，
  `TodoBody` 只负责画：分区、行动作、空状态；
- 侧栏也不再为同一份数据长第二个图标。

**保留的东西**：`GET /todo` 路由与 `buildTodoView()` **原样保留**，理由没变——
待办不能用日历的载荷：日历按 `month` 取数、`days` 只有当月，而"接下来"必然跨月。
"三种读法各自一条路由"这条结构留下了，去掉的只是"第二个面板"。

**顺带改了包自己的过期描述**（`lh.provides.routes` 补 `/lh/schedule/todo`、`summary` 改成三种读法）：
**包描述的过期比代码的过期更难发现**——它是别人（和模型）盘点生态时唯一的来源。

### 11.10 验收期区的**收起 / 展开**（作者第五次反馈："验收期的区域太小了"）

作者给了两条路："要么添加一个折叠展开，或是一个更大的区域提供更美观的展示"。**两条都做了**，
因为它们是同一个问题的两种用法：

- **收起（默认）**：一条摘要行——只把**最近的**那个说清楚（类型圆点 + 标题 + 日期 + **大号倒计时数字**），
  右边写"共 N 个"和一个「展开」。原来的 4 个 chip 挤在一行、名字被省略号吃掉，
  恰恰是"区域太小"的来源；收成一行之后，最该看的那一个反而更清楚了。
- **展开**：一整块卡片列表（最多 8 个，超出滚动），每张卡有：类型标签、标题、
  日期或`起 ~ 止`窗口、课程、**大号倒计时**（数字 19px 加粗，单位小字），
  以及两个当场能做的动作——「去那天」（跳到日历里那一天，在那里改期/撤销/绑课）
  与「完成」（记一条完成事实）。左边缘那道 3px 竖条是类型色（合令牌铁律）。

**为什么不是"永远更大的区域"**：它会永久吃掉日历的高度，而验收期大多数时候只需要
"还剩几天"这一件事。所以默认给摘要、需要时再要全景——而**这个选择记在本地**
（`lh.schedule.milestonesOpen`）：它是个人阅读习惯，不该每次重选。

**实现上的一句纪律**：大号数字的排版（`milestoneBigValue`：拆成"数字 + 单位"）与
服务端的措辞（`countdownText`："还剩 2 天"）是**同一个事实的两种排版**，
两处都只读服务端算好的 `countdown`，谁也不自己算日期——排版可以不同，口径不能不同。

顺手删掉了随旧条一起作废的 `countdownBar` / `countdownItem` / `countdownNum` 与两个措辞函数：
手工 bundle 里的死代码是下一个读者的负担。

### 11.11 减法：去说明文字、合并"无限期"、界面不再分类（作者第六次反馈）

作者三条要求一起给："不要有过度的说明性文字，将无限期推迟整合进'推迟'里，不需要做说明，
并且不需要对日程进行分类。"

#### (a) 去说明性文字

统一成"**标签 + 计数**"，删掉的都是句子：

| 删掉 | 换成 |
|---|---|
| 待办分区右边的说明（"不占任何一天。定个日子，或者撤掉。"） | 只留分区标题与计数 |
| 待办头部总览行（"今天 … 待办 N · 欠账 N · 计划中 N"） | 删（分区标题旁已有计数） |
| 月历总览的括注（"过期未完成 N 条（**全部，不只本月**）"） | "· 过期 N" |
| 读取失败面板的第二行（"常见原因：LH 事件日志的位置没配好……"） | 删（服务端返回的那句话本来就带修法） |
| 动作提示的后半句（"已撤销（仍在日志与日历里，可改回计划中）。"） | "已撤销。" |
| 时区警告整句（"时区 X 认不出，服务端按 UTC 折算——分组可能与你差一天。"） | "· 时区认不出，按 UTC 折算" |
| 空状态第二行、placeholder 长句、按钮/图标的长 tooltip | 删或压成两三个字 |
| 日详情三块的空态（"这天没有任何学习活动记录。"） | "无会话" / "无日程" / "无课程动作" |
| "改回计划中" | "恢复" |

**判断标准**（留给以后的自己）：**界面上不该有句子。** 需要解释"这个按钮会做什么"时，
先问是不是设计没说清楚——如果是，改设计；如果不是（真的是偶发故障的说明），
那句话该出现在**出错的那一处**，而不是常驻在正常视图里。

#### (b) "无限期推迟"并进"推迟"

原来"推迟"与"无限期"是两个并排按钮，等于把**同一个动作的两种参数**做成了两个动词。
现在只有一个「推迟」，点开后是：明天 / 三天后 / 下周今天 / 两周后 / **不定日期** / 手输日期 + 定到这天。
`day: ""` 的语义一个字没改（`lh/schedule/updated` 里 `day: null`），改的只是入口。

#### (c) 界面不再对日程分类

- 列表、格子、日详情里**没有类型标签、没有类型色点、没有类型色条**了。
  留下的是**状态那一个字符**（· / ✓ / ✗ / ↷）与删除线——它回答"这条现在怎么样"，
  而不是"这条属于哪一类"。
- 表单里原来那个八选一的"类型"下拉，收成一个「验收期」下拉：
  **不设 / 模拟考 / 考试 / 大考 / 截止**。因为八个类型里只有一个问题**必须由人决定**——
  "这条是不是验收期"（它要进下端那个带倒计时的区域）；"学习 / 复习 / 上课"不是需要人回答的问题。

**⚠ 数据层一个字没动**：`kind` 仍在事件里、仍在 agent 工具的词表里（验收期就靠它承载）。
**去掉的是界面上的分类，不是数据**——这条必须写清楚，否则下一个人会以为可以删字段。

#### (d) 顺带：课程 id 不再露在给人看的界面上

原来显示 `课程 course-99c407ec`——那是**存储 id**。现在用载荷里的 `courses` 映射成
"行测 / 资料分析"（`courseLabelOf`，带 path 以区分同名子课程）；映射不到时才退回去掉前缀的 id。
**把 id 露在人看的界面上，也是一种"说明性文字"：那都是机器的话。**

验收：三份副本同步（3 个文件、24 处哈希校验通过）；`@lh/schedule` **101 条** +
路由自检 **120 条 × 3 份**全绿；`check-all` **28 绿 / 1 项应然红**。

### 11.12 撤销默认不可见（开关借宿主的设置席位）、验收期不再分种类、推迟改为相对本条目算

#### (a) 已撤销的日程**默认不可见**，开关放在**宿主的设置**里（不新建设置面板）

作者问了一句"设置里好像就这一个内容，是否值得多做一个设置面板"——**不值得，也不需要**：
宿主已经提供 `settings.general.item` 这个席位，它的目录原文就是
*"a single setting that needs no page of its own"*（`replaceRisk: none`，不需额外权限）。
`@lh/workspace-ui` 在同一个席位放"重载界面"，我们照同一条路放一行「显示已撤销的日程」。
于是：不新增入口、不新增面板、不新增一层导航；以后再有同类选项，仍往这一行里加。

**并且定了一条纪律**：只有"**需要人显式决定、且没法从别处推断**"的界面偏好才配进设置。
反例是验收期区的"收起 / 展开"——它就地放在那个区域上（它属于那块内容，不属于全局设置）。
**设置项越多，越没人看。**

**过滤放在客户端**（`showCancelled` 一把过滤掉 `days[].items` 里的 cancelled）：
一次管住三处（格子 chip、"还有 N 条"的计数、右列当天清单），而且是**立刻**生效——
开关在设置里，面板隔着两个组件，所以两者靠已有的发布订阅打通（面板订阅、设置行写值 + publish）。
`summary.cancelled` 仍然照数：那是"我这段时间撤了几条"的事实，与"要不要看"是两件事。

#### (b) 验收期**不再分种类**

- 新建与修改表单里那个「验收期」下拉，收成一个**复选框**：只回答"是不是验收期"。
  勾上就写 `kind: 'exam'`（最中性的那个词）——于是新数据里不会再出现四种验收期的分叉，
  而历史事件里的 `mock` / `final` / `deadline` 照旧被认出来（客户端的集合是**并集**，不是替换）。

  这条同时回答了上一轮我留下的那个问题（"卡片里要不要留'模拟考/大考'的字"）——**不留**。

**⚠ 又一次：数据层没动。** `kind` 仍在事件里、仍在 agent 工具的词表里（验收期靠它承载）；
去掉的是**界面上对验收期种类的区分**。这一次连"界面分类"的最后两处（表单下拉、卡片类型词）也清了。

#### (c) 推迟的快捷项改为**相对这条日程自己的日期**算

作者点出了关键的一句：*"毕竟改的不一定是'今天'的日程"*。

原来的快捷项是相对**今天**算的（明天 / 三天后 / 下周今天 / 两周后）——它在"今天改明天的日程"时
**恰好也对**，所以这个错很难被发现；只有改**未来的**或**已过期的**日程时才露出来
（一条排在 10-20 的日程点"明天"会被挪到 10-11，而不是 10-21）。
现在以 `item.day` 为基准（没有日期的待办才以今天为基准），并把措辞改成不依赖"今天"的说法：

**一天后 / 三天后 / 一周后**（删掉"两周后"，也删掉"明天""下周今天"这两种以今天为锚的措辞）。

验收：同上（三份副本、101 + 120 断言、`check-all` 28 绿 / 1 项应然红）。
