# ADR-021：入库前的 LLM 预处理，与「题解有多个来源」

- **背景**：作者实测反馈两件事——
  1. *"有些填空题不知道横线或者'空'在哪，这是 ocr 能遇见到的问题"*；
  2. *"用对话打字的方式做题也没有感觉"*（后者另案处理，见 ADR-013 的推迟项）。
- **我的第一版方案（已被作者否掉）**：用几何启发式找空位——
  「行距异常」找留白型、`行首孤立标点`找下划线型。
  实测在「片段阅读600题」上确实有效（q4/q17 给出精确位置、q18 给出插入点），
  但作者不认可，原话：*"我对你这两种辨别填空题的方案都不太认可，我认为既然题目都要进 llm，
  那让 llm 对填空/横线这类词语更警觉一些会不会更好。"*
- **作者的正面提议（原话）**：*"既然原题从 ocr 的粗提取到进题库反正都要过一趟 llm，
  那顺带让 llm 也'看看题'，获取一些题目的信息，作为题解的补充，甚至是预先做一次自己对一次答案，
  就像老师讲试卷之前自己也会先做一次题目，意思就是不单纯将 llm 当做一个分块器，而是一个预处理，
  这个预处理不用完全进上下文，只用作为一个记录来源的，对题解的补充，或者换个角度说，
  对某道题的题解，可能有多个来源的题解，llm 做的，官方题解，用户的注解，
  这些信息都可以注入'题解'中。"*

## 为什么作者的方案更好（不是客套）

1. **空位是语义，不是排版。** "这里要填一句"是关于**这道题**的事实，
   而"行距是常规的 2 倍"是关于**这一页**的偶然特征。
   几何法换一份版式就失效，而且**永远无法证明它完备**——它只能靠抽查来建立信心。
   LLM 读题时"看到"横线是它理解题意的**副产物**，不需要额外机制。

2. **几何法有一个隐藏的失败模式**，而 LLM 路线没有：
   如果 OCR 把那行下划线**连同字一起吃掉**（不是留下断裂），
   行距和标点**都不异常**——几何法会**静默漏检**，而漏检的题看起来完全正常。
   LLM 读题干时会发现"要求填画横线部分，但正文里没有横线"这个**语义矛盾**，
   并据此标注。**用语义矛盾做判据，比用像素做判据稳健得多。**

3. **它把一次已有成本变成三份收益。** LLM 本来就要读题（为了分块），
   顺带产出：题目信息、空位标注、**它自己的一次作答**。边际成本接近零。

## 决定

**1. LLM 是「入库前的预处理器」，不是「分块器」。**

它在同一次读题里产出四类东西：

| 产物 | 用途 | 是否承重 |
|---|---|---|
| 空位标注（有/无/在哪） | 修 OCR 吃掉的空位 | 是（影响题目可读性） |
| 题目信息（题型、知识点、难度线索） | 补充结构化字段 | 否（可选） |
| **它自己的一次作答** | **独立第二意见** | 否（但很有用，见决定 3） |
| 分块结果（题干/选项边界） | 组装题目 | 是 |

**2. 「题解」从一个字符串，变成一组**带来源的题解**。**

```js
question.solutions = [
  { source: 'official',  text: '…', provenance: { file, page } },
  { source: 'llm',       text: '…', provenance: { provider, model, tier, at } },
  { source: 'user',      text: '…', provenance: { session_ref, at } },
]
```

- **为什么必须带来源**：三类题解的可信度**不同**——
  官方题解是权威、LLM 的是一次尝试、用户注解是学习者的理解。
  混成一个字段就等于**把不同可信度的东西当成一样用**，那正是契约 §4.1
  "断言必须可证伪且带出处"要防的事。
- **`analysis` 字段保留为"首选题解"的投影**：也就是 official 优先、没有则 llm。
  这样现有代码（`submit_answer` 的返回、`render`）不用改，
  而信息在 `solutions` 里是全的。**加字段不改语义**，符合 ADR 的演进纪律。

**3. LLM 的答案**绝不**进入判分路径。**

这是本 ADR 最重要的一条约束。

- 判分（`correct`）**只能**用 `official` 答案。LLM 的答案是不可信的推断。
- 但 LLM 的答案与官方答案**不一致**这件事，是**免费的题目质量筛子**：
  两方独立得出不同结论的题，正是**最该被人看一眼的题**。
  产出为 `answer_disagreement` 标注，进入抽样复核清单（ADR-020 决定 5）。
- **为什么这条必须写死**：如果允许 LLM 答案参与判分，就会出现
  "学习者答对了官方答案、却被模型判错"——**而学习者无从察觉**。
  这与 ADR-018 决定 5（判不了要说判不了，不能默认算错）是同一条精神：
  **不确定的东西不能冒充确定的东西。**

**4. 预处理产物**不进对话上下文**。**

作者明确要求：*"这个预处理不用完全进上下文，只用作为一个记录来源的。"*

- 它落在题库文件与配套记录里；
- `submit_answer` 的返回里 `analysis` 仍是**一段文本**（首选题解的投影），
  不是一整包预处理产物——那会把上下文挤爆（资源索引器踩过这个坑：8,400 tokens 每轮重发）。

**5. 预处理与 OCR 一样是「建」的阶段。**

ADR-015：建模与运行分离。预处理是离线、一次性、慢的；插件是运行、要快。
所以它不进插件，走脚本（与 `ocr_pages.py` 同一层），产出中间产物。

## 实测依据

| 事实 | 数字/证据 |
|---|---|
| 空位的两种形态 | 留白型（行距 81 vs 常规 39.5）；下划线型（行距正常） |
| 几何法的覆盖 | 20 页命中 4 处（`find_blanks_by_punctuation.py`） |
| 几何法的边界 | **只给插入点，不给范围**；且对"下划线连同字被吃掉"**静默漏检** |
| 答案的真实形态 | `【参考答案】C`（28 页 37 处，字母分布 A7/B15/C8/D7） |
| 可用的模型档位 | `flash` = xiaomi-token-plan-ams/mimo-v2.5-pro（实测可用、无 reasoning chunk） |

## 试点结果（2026-09-19 补记，本 ADR 决策 1 与依赖前提 1 的验收）

试点脚本 `scripts/pilot_llm_preprocess.mjs` 已在**真实题库**（工作区那份 30 题的
`考公刷题-片段阅读与逻辑判断.json`）上跑过。产出在
`data/pilot-llm-preprocess.json` 与 `data/llm-preprocess-pilot.json`。

### 结论一：一致率高到够用，但只够当"筛子"，不够当"判分"

| 批次 | 题数 | 与官方答案一致 | 每题 token |
|---|---|---|---|
| A 批 | 30 | **25/30（83%）** | 2,451 |
| B 批 | 19 | **17/19（89%）** | 2,103 |

**这个数支持决定 3 的红线，而不是削弱它。** 两批之间**同一道题给过不同答案**
（19 道重叠题里 5 道不一致）。也就是说：同一份题干、同一个 `temperature: 0`，
两次运行能让模型改主意。

> **一个自己都会改主意的答案，绝不能进判分路径。**
> 它只能当"值得人看一眼"的筛子——这正是决定 3 说的用法。

### 结论二：空位定位**不可靠**，走依赖前提 2 的降级路径

| 批次 | 空位判定 |
|---|---|
| A 批 | 2/3 |
| B 批 | **0/3** |

总共 6 次判定对 2 次。**这正是决定 1 预告的那个失败模式**（"它标的空位大量落错位置"），
而本 ADR 早已写好处置：**退化为"标出这题有空位、但不知在哪"，仍比静默漏检好**。

更值得记的是第二层：**它并不是"找不到"，而是"找错了还很自信"**——
两次判定里 `blank_required` 都报了 true，位置却对不上。

→ **结论：一期不把 LLM 的空位位置写进题目字段**，只写"此题要求填空"这类布尔事实；
位置（若确实需要）留给几何法或人工，且必须标来源。

### 结论三：成本（真实数字，供决策）

- 每题约 **2.1–2.5k tokens**（其中约 64% 是推理 token）；
- 按此推算：**片段阅读 600 题 ≈ 1.3–1.5M tokens**；
  五类题集全量（2332 页、约 600×5 题）≈ **5M tokens 量级**。

**这是一笔需要作者点头的花费（ADR-016：花费要透明，选择权在作者）。**
所以一期只跑"已经装进题库的那 30 题"是同意的范围，全量要单独决定。

### 结论四：一个真实的偶发失败模式（已处置）

实测有一题返回**空 content**：`finish_reason = length`、
`reasoning_tokens = 5999`（等于预算）——**模型把全部预算用在推理上，没来得及输出**。
它不是"模型不行"，而是**预算不足**：同一题在小样本试点里用了 3250 token 就正常作答。

处置：扩容重试一次（6000 → 14000），并把首次失败的原因带进结果记录。
**刻意不把初始预算调大**——过大的上限会掩盖"某题稳定需要 12k token"这种信号。

### 结论五（⚠ 这是本轮最该记住的一条）：产物**丢掉了自己的出处**

`data/pilot-llm-preprocess.json` 顶层写着 `model: deepseek-flash`、`total: 49`、
`agreement: 42/49`，但**49 条记录里只有 30 个不同题号**：
它是**两次运行的记录被合并进了同一个文件**，而顶层那个 `model` 字段
只描述了**最后写入它的那一次**。

于是那个 `42/49` 是**把两个模型的一致性算成了一个模型的**——数字没错，含义是错的。

产物是**给人做判断用的**，而一份自己说不清"我是谁跑的"的产物，
会让下游每一个引用它的人都算错。所以：

- 每条结果记录**必须自带模型身份**（本轮已补：`results[].model`）；
- 审计这件事的只读脚本是 `scripts/audit-pilot-provenance.mjs`
  （它按"每题第一次/第二次出现"分批复算，并自检分法是否自洽）。

**这与契约 §1.4「出处字段是重放正确性的前提」是同一条规矩，只是这次踩在脚本产物上。**

## 依赖的前提

1. **LLM 能可靠地"看到"空位。** → **已被试点部分证伪**（2026-09-19）：
   它能判断"这题要求填空"（6/6 都报了 true），但**定不准位置**（2/6）。
   处置见"试点结果 结论二"：一期只取布尔，不取位置。
2. **成本可接受。** 全量 600 题每题一次调用；具体量级要靠试点测量后报给作者决定
   （ADR-016：花费要透明，选择权在作者）。
3. 预处理产物与题库之间的对应关系靠题目 id 建立；**id 由题本 OCR 派生**，
   所以预处理必须在题本分块之后（顺序：OCR → 分块 → 预处理 → 入库）。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| LLM 当预处理器 | 它标的空位大量落错位置 → 说明它对"位置"不可靠，此时**退化为"标出这题有空位但不知在哪"**，仍比静默漏检好 |
| 题解带来源 | 出现"把 llm 题解当官方题解用"的下游 → 该下游错了；**不要**为方便而合并字段 |
| LLM 答案不进判分 | 出现"用 llm 答案判分"的代码路径 → 立刻回退；这是本 ADR 的红线 |
| 预处理不进上下文 | `submit_answer` 的返回明显变长 → 有人把整包产物塞进去了 |
| 预处理是"建"的阶段 | 它在会话中被调用（每次刷题都跑一遍）→ 层次错了，改回脚本 |

## 未做的事

- **预处理的提示词**：已写第一版（`scripts/pilot_llm_preprocess.mjs` 的 `buildPrompt`），
  **但还没变成插件里的正式版本**——它现在住在脚本里，agent 调不到。
- **空位位置**：一期不做（试点证明 LLM 定不准，见"试点结果 结论二"）。
- 多来源题解的**注入方式**（用户注解怎么进）：未做。
- **`topics` 词表**：**已定形态并落地**（`plugins/lh-question-bank/topics.js`，两轴封闭词表 + `unmapped_topics` 如实回报），
  见结论七。词表**内容**仍会随真实题目增长（那是数据问题，不是设计问题）。
- **预处理产物的稳定标识**（结论八的修法）：**未做**。
  预处理必须产出 `{ file, number, question_id }`——`question.js` 的 `deriveQuestionId()`
  已经提供了稳定 id，用它就不存在"两份资料的 set1-q1 撞车"这种事。
- **抽取链进系统**：**未做**。现在 `scripts/` 下那批 Python/Node 脚本（survey → pair → OCR →
  render 旋转 → 对齐 → 答案抽取 → 分块入库）**只能由人按记忆依次执行**，
  agent 调不到；而且题库是脚本直接落盘的，**从未经过 `import_questions`**，
  所以事件流里没有它的 `lh/resource/questions-imported`，
  它的 provenance 还指向一个不存在的 `@lh/extractor`。
  这是**下一步的主线**：把"材料 → 题库"变成系统能力，而不是我会跑的手艺。
- **对话打字"没有感觉"** 的交互方案：另案（作者已选"专门刷题界面"，见 ADR-013 推迟项与本轮探针）。

### 结论六（2026-09-19 追加）：`topics` 的对话式产出**不能直接用**

试点里模型每题给 1–5 个知识点标签，49 题共 **86 个不同标签**，其中：
`片段阅读` / `言语理解` / `中心理解` / `主旨概括` / `主旨对策` / `话题衔接` / `行文逻辑`
——一半以上是**同一件事的不同说法**；另一半是**题目内容词**
（`纳米金属`、`相声`、`老年群体`），不是知识点。

**词表一旦这样长起来，"系统觉得你弱在哪"就永远说不清**（契约 §4.2 要求按域建模）。
处置方向见下一份 ADR：**给模型一份封闭词表让它挑，而不是让它自己造**；
挑不中的如实回报为"未映射"，作为词表该扩的证据。

### 结论七（2026-09-19 追加，已落地）：词表是**两轴**，且"内容词"不许进知识点

86 个标签按"它到底是什么"分三类，三类混在一起是结论六的病根：

| 类别 | 例子 | 处置 |
|---|---|---|
| **题型**（这题要你干什么） | 中心理解、语句填入、削弱论证、真假推理 | **封闭枚举**，约 20 项，机械可校验 |
| **领域**（这题属于哪门） | 片段阅读、逻辑判断、资料分析、数量关系 | **封闭枚举**，量级 <10，对应契约 §4.2 的"域" |
| **内容词**（这题在讲什么） | 纳米金属、相声、老年群体、三聚氰胺 | **不进知识点**，是题干信息，不是能力 |

两级维度合起来记在**同一个 `topics` 数组**里（题型级在前、领域级在后），
理由是断言要按"题型 × 领域"两轴分别结算，而两者必须能一眼分开
（判据：领域项来自封闭小集合，题型项来自封闭中集合，两集合不相交）。

**为什么内容词必须挡在外面**：把 `纳米金属` 当成知识点，等于声称
"你对纳米金属这个知识点掌握得不好"——而**那道题考的是中心理解**。
这正是契约 §4.2 说的"不同课程建模逻辑天然不同，不能混成一锅"在题目层的对应物。

落地形态：词表住在 `plugins/lh-question-bank/topics.js`（它是 `topics` 字段的 schema 所有者），
预处理提示词把词表**打印进去让模型挑**，返回的标签经 `normalizeTopics()` 归一化，
挑不中的进 `unmapped_topics` **如实回报、不丢弃**。

### 结论八（2026-09-19，最贵的一条）：**产物没有稳定标识，等于没产出**

试点那 30 道题的知识点要接进工作区题库时，撞上一个必须先解决的问题：
**匹配键选什么？**

- `source.number`（试点记录里唯一的定位信息）是 `set1-q1` 这种**资料内编号**。
  而工作区题库是两份资料合并的（`extraction: rule, merged: true`）：
  `2025年花生片段阅读600题-题本【上】.pdf` 与 `逻辑判断600题题本篇.pdf`
  **两份都有 `set1-q1` … `set1-q20`，而它们是完全不同的题**。
- 试点产物里**没有文件出处**——记录只有 `number`，没有文件名、没有题干。

于是按题号匹配会把**片段阅读的知识点写到逻辑判断的题上**：
不报错、只是全错，而且**事后无法从产物里发现**。

处置（`scripts/patch-bank-topics.mjs`，三轮收敛）：

| 用的判据 | 为什么 | 结果 |
|---|---|---|
| `题号 + 官方答案` | 由数据本身提供，不需要我猜哪一批是哪个文件 | 把 49 条收敛到 38 个键 |
| 排除 `agree === false` 的记录 | 实测那 7 条**在题库里一道题都对不上**（0/7）——它们的题号与官方答案属于另一次取题 | 剩 32 个唯一键 |
| 撞车时**只认领域标签相符** | `片段阅读` / `逻辑判断` 是独立于匹配键的第二证据 | 判定了 1 道 |
| 撞车且无独立证据 → **拦下不写** | "取最早一条"不是判据，是掷硬币 | 拦下 31 道 |

**最终只有 13/49 道写入成功**，其余如实留在报告里。这不是脚本没写好，而是
**产物的信息量不足以支持批量归属**——这个代价完全来自结论五（产物不记出处）。

> **一般化（值得写进契约）**：**一个产物如果没有稳定标识（id / 文件 / 题干），
> 它就只对"当时读它的那个人"有用。**
> 这与 ADR-020 那条"对齐的单位必须等于语义单位"是同一条：
> `set1-q1` 是**页/序号**这一级的代理量，而真正的语义单位是"哪份资料的哪道题"。

**要修的不是这个脚本，是产出它的那一步**：预处理脚本必须带上
文件名与题目 id（`question.js` 的 `deriveQuestionId` 已经提供了稳定 id）。
这一条已经记进下面的"未做的事"。
