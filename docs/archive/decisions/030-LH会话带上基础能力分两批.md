# ADR-030：LH 会话带上 standard preset 的基础能力——并且是**分两批**带

- 日期：2026-09-20
- 状态：已采纳（第一批已落地，**待一次真会话验证**；第二批未做）
- 相关：ADR-011（宿主采用 dsh）、ADR-024（开发类插件）、
  `WORKFLOW.md §2 规则 3`（分段的依据是客观难度）、ARCHITECTURE §0.1 约束 6（加行是高危编辑）

---

## 背景

作者要"在 LH 会话里发起 2400 题入库，让 LH 的 agent 自己调工具跑完全流程"。
我先查了**通路到底通不通**，用的是宿主会话日志里的工具清单
（`scripts/inspect-session-tools.mjs`，同一时刻两个会话的实测）：

| 会话 | preset | 工具数 | 清单 |
|---|---|---|---|
| 默认会话 | （standard） | **32** | 含 `pwsh` / `read` / `write` / `glob` / `grep` / `web_search` / `subagent` / `workflow` … |
| LH 会话（`session-0e5131a3`） | `lh` | **9** | `import_questions`、`record_attempt`、`list_question_banks`、`get_questions`、`submit_answer`、`get_solution`、`get_practice_stats`、`start_practice`、`index_learning_resources` |

**LH 会话没有 shell、没有文件读写、没有网络、没有 subagent。**
而入库全流程里 OCR / 坐标排序 / 对齐 / 抽答案全是脚本 → 没有 shell 跑不了；
`import_questions` 虽然接受 `file_path`，但那是**插件进程**读文件，
agent 自己连"目录里有哪些中间产物"都看不见。

→ **通路不通，且卡在能力缺口上，不是"工具没调对"。**

## 决定

### 1. LH 会话要带 standard preset 的基础能力（作者的选择：路 A）

理由（作者的判断，我采纳）：**LH 本身要带开发能力**——下一步做 `lh-plugin-development`，
支持用户在 LH 会话里把自己的学习习惯/方法/流程落成插件。既然要开发，
`tool-pwsh` / `tool-fs` / `tool-fs-search` / `tool-web` 这些本来就是必需的。

**并且产品立场是"在 LH 里开发，而不是在 dsh 里开发"**：
对非专业开发者，LH 需要把 dsh 的开发表达方式**隐藏**起来，
让用户专注在"把自己的学习方法落地"，而不是先跨过软件工程的语言门槛。

### 2. 分两批加，**按"是否需要 isolate realm"划界**（不是按重要性划）

standard preset 顶部写明一条硬规则：
**只有"发布服务"的行必须放进带 `isolate` 的组**，否则它发布到 root realm、
与别的 preset 撞名，`dsh-agent-presets` 在**挂载时**就拒绝。

所以：

| 批次 | 行 | 需要 realm 吗 | 状态 |
|---|---|---|---|
| **第一批** | `tool-bash` / `tool-pwsh` / `tool-fs` / `tool-fs-search` / `tool-jobs` / `tool-ask-user` / `tool-todo` / `tool-web` | **不需要**（只注册进宿主 `tools` 注册表，不 provide） | ✅ 已落地 |
| **第二批** | `planning`（isolate `planMode`）、`compaction`（isolate `compaction` + `toolResultPruner`）、`delegation`（isolate `workflowEngine`） | **需要** | ⏸ 未做 |
| 暂不加 | `persona` / `agent-instructions` / `skill-filesystem` / `tool-skill` | 不需要 realm，但有**产品含义** | 见决定 4 |

**第二批为什么不一起加**：它们是"真正会挂载失败的形状"（组 + realm + 子插件列表）。
一次加进去，若失败则**整个 LH preset 的所有会话都建不起来**，
而排查会同时面对三组新结构与八行新能力——**这是"分段依据是客观难度"的直接应用**：
第一批的失败面是"包存在吗"，第二批的失败面是"realm 关系对不对"，两者不该混在一次验证里。

### 3. 加行之前先做三件事（都是被这条纪律逼出来的）

1. **备份**：`preset-lh-before-basetools.yml`（改前的原样，回滚只复制回去）；
2. **闸门**：`check-preset-mount.mjs` 必须绿——但它**第一版把正确配置报成了错**
   （它只认工作区里的文件路径，解析不了 `@deepseek-ai/*` 这种宿主包名，8 行全报"文件不存在"）。
   **闸门对正确的配置报错比漏掉错误的配置更糟**：它会让人去改一个对的东西。
   修法：识别裸包名并在**宿主安装根自己的 `node_modules`** 里核对存在性
   （实测位置：`…/npm/node_modules/@deepseek-ai/dsh/node_modules/<包名>`）。
3. **闸门的自检**：`selftest-preset-mount.mjs`，四态各验一次。
   它当场抓到**第三个真问题**：**空 preset 被判通过**——
   若 YAML 被改坏到解析出 0 行，闸门原来会打印"加载失败 0 行"并退出码 0，
   而"0 行"的真实后果正是"该 preset 的所有会话都建不起来"。
   已修：解析出 0 行 = 红灯。

### 4. 刻意**没加**的三行，各有理由（留给作者定）

| 行 | 为什么不加 | 要加的话意味着什么 |
|---|---|---|
| `persona` | standard 的 persona 文本是 *"You are a coding agent…"* —— 那句话对**学习者会话是错的**。LH 需要自己的 persona（学习伙伴/教练的语气），而不是抄一份 | 要**写一段 LH 自己的 persona 文本**，不是照抄。这是产品文案决策 |
| `agent-instructions` | 它会去发现并读取 `AGENTS.md`（实测工作区与学习者工作区**都没有**这个文件）。加了不会有副作用，但也不会有作用——**除了**将来给 agent 写项目级指令时 | 它是"给 agent 的项目级说明书"入口。开发插件时大概会需要，但那时该由 lh-plugin-development 决定放什么内容 |
| `skill-filesystem` / `tool-skill` | 它会发现本机的技能目录并合并进目录（当前 `cordis-plugin-development`、`editing-cordis-compositions` 就是这么来的）。**加了等于把 dsh 的开发术语暴露给学习者** | 恰恰与决定 1 的"隐藏 dsh 的表达方式"相反。若要给 LH 技能，应当是 **LH 自己的技能**（如"把一段学习流程写成插件"），而不是 dsh 的插件开发技能 |

## 风险（如实记下，不粉饰）

1. **LH 会话从此能在学习者机器上执行任意命令。** 作者自己的机器上没问题；
   但 LH 的目标用户是"非编程专业的学习者"，**"给学习者会话一个 shell"在别处是否可接受是一个产品决策**——
   本 ADR 记的是"在这一步上选了要"，不是"这件事永远对"。
2. **加行 = 高危编辑**：若宿主解析不了 `@deepseek-ai/*` 裸包名，LH preset 会整棵树挂不上。
   离线闸门只能证明"包存在/文件能 import"，**不能证明宿主真的会这样调度**，
   所以必须有决定 5 的验证步骤。
3. 第二批的组与 realm 关系没验过。

## 决定 5：验证与回滚（必须做，不能省）

```powershell
# 1) 重启 dsh，然后开一个 LH 会话，只发一句：
#    "你能用哪些工具？列一下名字"
#    期望：出现 pwsh / read / write / edit / glob / grep / web_search 等（而不是只有 9 个）
# 2) 若该会话的列表里**没有**基础工具，或 LH 会话建不起来：
Copy-Item 'D:\LearningHarnessv0.1\.lh-sync-backup\preset-lh-before-basetools.yml' `
          "$env:USERPROFILE\.dsh\.agent-presets\lh\agent.cordis.yml" -Force
# 然后重启 dsh —— 回到改前的 9 个工具状态
```

## 怎么知道它错了

| 失效信号 | 说明 |
|---|---|
| 重启后 LH 会话建不起来 | 宿主解析不了那些包名 → 立刻回滚（决定 5） |
| 工具列表里出现了基础工具，但 LH 自己的 9 个工具没了 | preset 被覆盖或被截断 → 看 `agent.cordis.yml` 里 LH 那 5 行还在不在 |
| 学习者抱怨"它开始跟我讲 shell / 路径" | **产品问题**：能力给了，但表达方式没隐藏 → 这是 `lh-plugin-development` 要解决的，不是回退能力 |
| `check-preset-mount` 报"宿主包找不到" | 要么包名写错，要么 dsh 升级后包被重命名 → 去 dsh 安装根的 `node_modules` 里核对真实包名 |
