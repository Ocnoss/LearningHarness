# ADR-033：断言器**插件化**（描述符 + 声明式传递路径），信息只以 L3 断言沿树上行

- 日期：2026-09-21
- 状态：已采纳（**离线自测 42 项通过、闸门全绿；待一次真会话验证**）
- 相关：ADR-032（课程树是传递的坐标系）、ARCHITECTURE §3.1（Claim 接口：evidence 强制可回溯）、
  ARCHITECTURE §3.2（L3 元级：断言器本身可换）、`WORKFLOW.md §4.1`（断言带出处、可争议）、
  `lh-recorder-trace/index.js` 文件头（preset 够不着 root-realm 服务的同一约束）

---

## 背景

ADR-032 给了课程树一个稳定坐标系。现在要在这棵树上跑**断言的产生与向上传递**：
学习者在"第 3 级子课程"里说一句话，系统要产出一条 3 级断言，
并让它**沿树向上**串出 2 级、1 级断言（高层断言器综合低层证据）。

两个问题必须现在定：
1. **断言器怎么组织**，才能"多个评估器可并存、允许不一致"（ARCHITECTURE §2.4）且日后可换？
2. **"传给谁"这条路径由谁裁决**，才能既支持"逐层向上"，又支持将来"跨层直送""到此为止"？

## 关键事实（查证过的，不是推断）

1. **preset 是 agent 作用域，够不着 host 面 root-realm 的服务**（ARCHITECTURE §0.1 约束 5、
   recorder-trace 文件头实证）。往 root realm 发布服务需要带 `isolate` 的组，**未实测、风险高**。
   → 所以"断言器注册表"这一步**不能**想当然用 cordis 跨 realm 服务。
2. `store.append()` **返回写入的事件对象（含 `id`）**（ADR-032 关键事实 4）→ "派生断言指向子断言事件 id"可落地。
3. ARCHITECTURE §3.1 Claim 接口：`evidence: [证据ID列表]` 是**强制**字段（可回溯到内核事件），
   `低证据必须返回低置信`。断言事件的形状必须承袭这条。
4. 契约纪律：`apply()` 装载期不抛错；旁路观测**绝不**把异常冒泡进宿主事件管线（recorder-trace 的 append 失败处理）。

## 决定

### 1. 一个断言器 = 一个**描述符对象**（声明式，可换）

```
{
  id: 'virtual',                    // 唯一 id；节点的 asserter 字段按它选
  tier: 'flash',                    // 建议档位（供引擎/审计参考）
  appliesTo(node) -> bool,          // 是否适用于该节点（默认恒真）
  propagate: { mode, target? },     // 传递路径声明（见决定 2）
  assert({ input, node, tree, target, evidence, time, llm, call })
     -> { statement, confidence, propagate_to, model? }
}
```

节点用 `asserter` 字段指名要哪个断言器（`buildTree` 从 `created` 事件的 `data.asserter` 投影）；
没指名或指了个注册表里没有的，**退回默认而非报错**——断言链路不该因一个写错的名字整条断掉。

### 2. 传递路径由 `descriptor.propagate` **声明**，`resolvePropagateTarget` 是**唯一裁决处**（纯函数）

| `mode` | 语义 |
|---|---|
| `'parent'`（默认） | 逐层向上，传给父节点；到根自然停止 |
| `'node'` | 跨层，`target` 可为 `'root'` / 层级数字 / 具体 `node_id` |
| `'stop'` | 不传递（这条断言是终点） |

「传给谁」是本次最容易错、也最难在真会话里肉眼发现的地方（**传错父节点是静默错误**）。
所以把它抽成不碰文件/环境/模型的纯函数，让 `selftest.mjs` 用合成树**穷举**四种情形。

### 3. 断言只以 **L3 形式沿树上行**，每跳写一条 `lh/assertion/made`（承袭 Claim 接口）

事件 `data` 形状：`{ node_id, asserter, statement, evidence, derived_from, propagate_to, confidence, model }`。
- `evidence`：**触发坐标**（叶子断言有值，如 `session/<id>#<seq>`；派生跳为空）——承袭 §3.1 的强制可回溯。
- `derived_from`：**子断言事件 id 数组**（叶子为空）——高层断言的证据是低层断言，血缘成链（ARCHITECTURE §2.3 派生血缘规则）。
- `propagate_to`：目标 scope（`course/<node_id>`）或 null（到根/停止）。
- 引擎据 `derived_from` 递归：产出叶子断言 → 求目标 → 对目标节点再跑一次，其 `derived_from` 指向刚写的事件 id → 直到 null。

### 4. 注册表先用**内置 `Map`**（临时答案，记入开放问题），不用 cordis 服务

`createRegistry()` 返回一张 `Map<id, descriptor>`，首个条目是虚拟断言器（ADR-034）。
理由见关键事实 1：preset 发布 root-realm 服务需 isolate realm，未实测、风险高。
**"断言器服务化注册表"（跨插件动态注册）列入 ARCHITECTURE §5 开放问题**，等真出现第二个需要动态注册的断言器再做。

## 当时有哪些别的选择 / 为什么排除

| 别的选择 | 为什么排除 |
|---|---|
| **传递逻辑硬编码在 `index.js`**（每个断言器 if-else） | 加断言器就要改引擎；传递路径散在多处，**无法穷举测试**——而传错父节点是静默错误 |
| **断言器用 cordis 服务化注册表**（跨插件动态注册） | 关键事实 1：preset 发布 root-realm 服务需 isolate realm，未实测、风险高。**不是不做，是现在不做**（列开放问题） |
| **传递固定"只传父"**（不可声明跨层/停止） | 表达力不足：无法说"这条断言是终点"或"跨层直送根"。真实断言器按层级有不同上行策略 |
| **什么都不做**（只产叶子断言，不传递） | 违反需求核心：信息要沿树上行到高层断言器综合。叶子断言孤立无价值 |

## 依赖什么前提 / 假设（前提塌了要重审）

1. **内置 Map 注册表够用**：当前只有虚拟断言器一个。出现"需跨插件动态注册"就是它塌的时候。
2. **`derived_from` 能拿到子断言事件 id**：依赖 `append()` 返回含 id 的对象（关键事实 2，已验证）。
3. **一次触发内复用同一份树投影**：`propagate` 递归共享同一个 `tree`，保证坐标一致（不在递归中途重放）。
4. **传递路径可声明** = 未来不同层级断言器可有不同上行策略（逐层/跨层/停止）。

## 怎么知道它错了（可观察信号，不是"感觉不对"）

| 失效信号 | 说明 / 处置 |
|---|---|
| **出现第二个断言器且需跨插件注册** | 内置 Map 前提塌了 → 启动"断言器服务化注册表"（开放问题），届时需实测 isolate realm |
| **`resolvePropagateTarget` 表达不了某种真实上行策略**（如"传给同层兄弟""传给所有祖先"） | `mode` 词汇不足 → 扩 mode，但**必须同步扩 selftest 的穷举** |
| **真会话里 `derived_from` 链断裂**（指向不存在的事件 id） | `append()` 返回值假设塌了，或递归中途 tree 变了 → 查 `index.js` propagate L275-286 |
| **传递出现环 / 爆栈** | `visited` + `MAX_PROPAGATE_DEPTH=32` 护栏失效 → 查 `index.js` L201-211 |
| **断言传到错的父节点**（静默错误） | 最危险：真会话肉眼看不出 → 只能靠 selftest 穷举 + 真会话后**审计 `derived_from`/`propagate_to` 链** |

## 验证（本次真做过，不是推算）

| 步骤 | 结果 |
|---|---|
| `node plugins/lh-asserter/selftest.mjs`（离线，合成树 + 假 `call`） | **42 通过 / 0 失败**：parent 逐层/到根停止、stop、node 跨层（root/level/id/非法）、`selectAsserter` 默认/指名/退回、虚拟断言器提示词与产出形状、fallback |
| `node scripts/check-all.mjs` | 24 项：**23 绿 + 1 应然红 + 0 不该红**；check-plugin-contract 校验 `lh` 段与实现一致 |

**证据位置**：
- `plugins/lh-asserter/asserters.js`：描述符形状约定（L4-19）、`createRegistry`（L43-50）、
  `selectAsserter` 退回默认（L63-68）、`resolvePropagateTarget` 唯一裁决（L80-124）。
- `plugins/lh-asserter/index.js`：`propagate` 递归引擎（L200-287）、防环 `visited`+`MAX_PROPAGATE_DEPTH`（L201-211）、
  `derived_from: [envelope.id]`（L281）、事件 data 形状（L256-265）。
- `plugins/lh-asserter/selftest.mjs`：穷举传递路径（`mkTree` 构造最小树）。

## 没做的（如实记下）

- **断言器服务化注册表没做**（决定 4）：当前是内置 Map。触发信号见上表第 1 行。
- **置信度结算协议没做**：`confidence` 现在是断言器各自返回的原始值，
  "多次证据如何结算成一个 Claim"是 ARCHITECTURE §5 开放问题 2，本次不碰。
- **人工覆写没做**：§3.1 说"学习者/教练可人工覆写，覆写记入事件"——本次只有 agent 产断言，无覆写通道。
- **跨层传递的真机验证没做**：selftest 穷举了 `node` 模式的解析，但真会话里只跑默认的 `parent` 逐层（ADR-034 验证步骤）。
