# ADR-035：课程目录的形态、界面写权限、以及"装到哪个家"

- **状态**：已冻结（2026-10-08）
- **触发**：作者要求"开发一个课程树视图用来管理会话，允许在课程中建立子课程，子课程按课程来分类会话，
  每一级别课程下都可以有会话；为了不和目前的工作区区域冲突，为工作区添加折叠功能并在工作区区域下
  新建一个可折叠的课程区域；课程的级别和名字会放入上下文输入到会话中"。
- **为什么写 ADR**：它同时触发两条 §4.3 的 ADR 触发条件——
  (a) **修订 ADR-022 已冻结的"界面入口"立场**；(b) **改变活文档已写下的承诺**
  （`ARCHITECTURE.md` §4"开发环境……启动器 lh-dev.mjs"与 §7 开放问题 3 的表述）。

---

## 0. 先摆三个**从宿主源码读出来**的事实（它们决定了后面所有选项）

这三条不是推测，是读 `app.asar` 得到的；行号即证据。**它们推翻了作者和我最初共同的设想**
（"在工作区区域下面加一块可折叠的课程区"）。

**事实 1：侧栏的工作区浏览区是 `single` 槽，只能整个替换，不能"包住"。**

- 同优先级再注册会**抛错**：
  `single slot "sidebar.workspaces" already has a registration at priority 0 (registered by mf) — register at a different priority to shadow it (lowest renders)`（`694700`）；
- 排序是 `(a.priority ?? 0) - (b.priority ?? 0)` → **数字小的渲染**（`694750`）；
- 而"替换方想把官方那份渲染在自己里面"这条路被另一条检查堵死：
  `if (options.children) … if (childRec?.spec) throw new Error('slot "X" is already declared (by …)')`（`694720`）。
  即：**已经声明过的子槽，第二个条目不能再声明**。而官方浏览区的子槽
  （`sidebar.workspaces.session.menu.item` / `.row.action` / `.directoryFlow`）正是由那个条目声明的。
- → 结论：**"接管侧栏会话区但复用官方列表"在框架层不成立**。要那个位置，就得自己重写一份会话列表，
  代价是**搜索、按工作区树分组、拖拽排序、会话右键菜单（重命名/分叉/归档/置顶）、添加工作区对话框**
  全部要么重做、要么没有。

**事实 2：作者要的"工作区折叠"**已经**有了。**

官方工作区浏览区自带：按工作区分组可折叠、每个工作区"展开其余／收起"（`717476`）、
"祖先默认展开，已有的折叠偏好除外"、折叠状态存在浏览器本地（`717490`）、
以及可折叠的区头搜索（`717496`）。→ 这一条**不需要做任何事**。

**事实 3：作者日常用的那个界面，此前从来没有装过 LH 的任何界面插件。**

`Get-CimInstance Win32_Process` 的 Electron 命令行是
`… dsh-desktop-host/lib/index.js … C:\Users\Administrator\.dsh\profiles\desktop …`，
与本会话的环境变量一致（`DSH_HOME=C:\Users\Administrator\.dsh`、`DSH_PROFILE=desktop`）。
而 `profiles/desktop/package.json` 的 `dependencies` 是 `{}`、patch 里没有任何 `@lh/*` 行。
此前所有 LH 界面都装在 **`profiles/web`**（两个家都是）——**那是一个没人在看的面上**。

## 1. 决定（一）：课程目录做成**中央面板**（`main` key `lh`）+ 侧栏图标，不接管侧栏会话区

作者在知道上面三条之后选了这一条（选项乙/甲被否）。

- `main` 槽是 **keyed、keyDomain 开放、无 id 白名单**：`hasMainPanel = entries("main").some(e => e.options.key === id)`（`433242`），
  先例是 `plugins` / `schedules`（`443900` / `470960`）。
- 侧栏入口用 `sidebar.panellist`，**id 与 main 的 key 同名**（`692585`：同一个 id 寻址 main 的那个 key）。
- **渲染细节不在本 ADR**，见 `plugins/lh-workspace-ui/`。

### 与 ADR-022 的关系（这是本 ADR 存在的主要理由）

ADR-022 冻结过一条立场：**"去掉常驻的侧栏按钮；界面上不再有任何刷题入口"**，
理由是作者原话"一个出现在 dsh 界面内的刷题按钮**很突兀**"。
本次却在侧栏加了一个**常驻图标**。这是**部分修订**，理由必须写清、不能含糊过去：

| | 刷题（ADR-022 的场景） | 课程目录（本次） |
|---|---|---|
| 意图的时效 | **有时效**：由对话产生，也该由对话结束 | **长期**：它是"我的课程与对话归在哪"的**导航面** |
| 常驻表达的是 | "这个功能一直在这儿"——**不是事实** | "你的课程一直在那儿"——**正是事实** |
| 与官方元素的类比 | 官方没有"常驻刷题"这种东西 | 官方的**工作区/会话浏览区本身就是常驻侧栏元素** |

→ **修订的边界**：ADR-022 的立场对"**有时效的意图**"（刷题、一次性动作）继续完全有效；
对"**长期存在的导航面**"不适用。**不是**"ADR-022 作废了"。

**我判断错这条的信号**：作者觉得侧栏那个 📚 图标碍事／多余／该藏起来
（他说过"很突兀"这个词，若这次也用同一个词，就说明我这条区分站不住，
正确修法是把它改成**非入口的间接形态**——例如只留对话里的卡片，或放进命令面板）。

## 2. 决定（二）：界面**获得写权限**，但写路径与 agent 工具**是同一份代码**

第一版 `lh-workspace-ui` 刻意只读，注释理由是"写入仍走 agent 工具"。
这条在"只有对话一个入口"时成立，**与"课程树视图用来管理会话"直接冲突**：
建子课程、改名、把会话挪到某门课下，全都要先跟模型说一句——那就不是视图管理，
是"对话管理 + 一个只读显示器"。

**新分工**：**判断归 agent，机械动作归界面。**
服务端半新增三条写路由（`POST /lh/workspace/course|rename|bind`），它们
**不做任何教学判断**，只把学习者点的那一下翻译成一条课程事件；
事件怎么拼、层级怎么算、歧义怎么报，全部复用 `@lh/course-tree/commands` ——
**与 agent 工具同一份代码**。

- **为什么"同一份代码"是硬要求而不是偏好**：`buildTree` 对认不得的字段是**跳过**、不是报错。
  两条路各拼一遍信封，稍有出入（scope 写法、provenance 版本、`data` 字段名）就会
  **一边认、一边静默忽略**——正是本项目反复记的"静默失败"形状。
  把它变成一次代码重构（`index.js` 的三个工具也改为调 `commands.js`），
  于是"点按钮建的课"和"模型建的课"在 `events.jsonl` 里**字节级同形**。
- **别的选择**：(i) 保持只读、全靠 agent 工具——否，与需求冲突；
  (ii) 界面自己 `fetch` 到一个通用"写事件"路由（把 type/data 传给服务端）——否，
  那等于把事件信封的构造权交给浏览器，是最坏的一种"灵活"；
  (iii) 什么都不做、只把树画出来——否，那就没有"管理"。
- **前提／假设**：`ctx.webServer.register` 在 profile 作用域可用（已在 `lh-practice` / `lh-course-ui` 实装）。
- **失效信号**：日志里出现"只可能由界面写出"的事件形状却与工具写的不同 → 说明有人又开了一条写路径，
  **应当立刻把它并回 `commands.js`**，而不是去改投影容忍它。

### 一个**如实记下**的缺口（同 ADR-022 修订 9 记的那一条）

HTTP 路由**没有会话上下文**——这是宿主限制，不是本插件的疏忽。
所以"把**当前**这段对话绑到这门课"这件事，界面**不能**自己知道当前是哪个会话。
本次的处置：

- 面板从宿主给的 `useSessions` 里**持续记录**"最后一次显示在主视图里的会话"
  （`retainedBy.mainView > 0`），面板打开后该值不再更新（面板占着主区）；
- 按钮上**明写会话 id**，让学习者一眼看得出要绑的是哪一篇——**猜错要看得见**，而不是静默绑错；
- 另一条更硬的路径保留：在对话里让 agent 调 `enter_course`（它有 `exec.agent.session.id`，**精确**）。

→ 这一条是**临时答案**：等宿主提供"当前活动会话"服务（`ARCHITECTURE` §7 开放问题 3），
界面这条路应当改用它。

## 3. 决定（三）：课程的层级与名字**注入运行时上下文**（`lh:course`，order 117）

作者的原话要求就是这个（"课程的级别和名字会放入上下文输入到会话中"）。

- 落点是 `ctx.systemPrompt.context({ name: 'lh:course', order: 117, text })`，
  由 `@lh/course-tree` 注册（preset 作用域，与工具同处一处）。
- **为什么必须是"每次组装都会出现的位置"**：本项目实测过——写在**工具描述**里的规则会被忽略两轮
  （`host-compat.md` §五"规则写在了读不到的地方"）。运行时上下文每次都在。
- `text` 是**函数**，每次组装时求值 → 学习者刚建的子课程、刚绑的会话，**下一次请求就生效**，不需重启。
- order 取 117：宿主把档位可用性放在 116（`lh-model-tier`），课程归属是**比资源情况更强的前提**
  （它决定这段对话该按哪门课的纪律来），排在它之后。
- 会话 id 取自 `context.agent.session.header.id`（回退 `agent.session.id`）。
- **未绑定课程时注入空串**，不硬编一句"你还没选课"——不打扰是默认。
- **失败一律静默为"不注入"**：数据目录没配好、日志坏了、拿不到会话 id，
  都不该让整轮模型调用崩掉。看不到课程说明是**降级**，把调用弄崩是**故障**，代价不对等。
- **失效信号**：作者说"我明明绑了课，模型还是不知道" → 先看这一条上下文有没有出现在组装结果里
  （`selftest.mjs` 第 10 节验的是注册与取值，验不了组装顺序）。

## 4. 决定（四）：装到 **`profiles/desktop`**（作者日常那个界面）

由事实 3 得出：LH 的界面只有装进 desktop profile 才会出现在作者真正在用的窗口里。

- 改动是三处、**全部可回退**：profile 的 `package.json` 加三条 `file:` 依赖、
  `cordis.patch.yml` 加一个 `insert` 块、跑一次 `pnpm --dir <profile> install` + `sync-lh-deps.mjs`。
  回退 = 删掉那个 insert 块（包留着不影响启动），要清干净再删依赖。
  改动前已备份两个文件到 `.lh-backup-desktop-<时间戳>/`。
- **风险如实记**：profile 的 **user patch 层出错会让启动直接失败**
  （"profile and user-patch errors still fail startup"）。本次用三道检查把它压到最低：
  `check-plugin-imports`（能在生产路径 import）、`check-profile-apply`（假 ctx 真跑 apply）、
  `sync-lh-deps` + `check-installed-copies`（副本是最新的）。**这三道都不能替代一次真启动。**
- **别的选择**：(i) 继续只装 `profiles/web`，另开一个 `dsh web` 浏览器实例——否，
  那要作者在"日常应用"和"学习环境"之间来回切，而他要的是**在一个地方学**；
  (ii) 把 desktop profile 整个换成 `lh-dev.mjs` 管的家——否，那是宿主的应用目录，
  不属于本仓库管，强改会把"哪个家是活的"这条本来就容易搞错的事弄得更乱。
- **失效信号**：应用起不来（→ 先删 insert 块，再按 `.lh-backup-desktop-*` 还原）；
  应用起来了但侧栏没有 📚（→ 看宿主跳过行时的 stderr，以及浏览器 console 有没有
  `Failed to load plugins`）。

## 5. 证据在哪

| 结论 | 证据 |
|---|---|
| single 槽只能替换、不能包住 | `app.asar` `694700` / `694720` / `694750` |
| 官方工作区浏览区已自带折叠 | `app.asar` `717476` / `717490` / `717496` |
| `main` 槽无 id 白名单、先例是 `plugins`/`schedules` | `app.asar` `433242` / `443900` / `470960` |
| `main` 槽提供 `useSessions` 等 standard props | Cordis Inspect `Slots.listSubTree(root:"main")` 的 `catalog.standardProps` |
| 活的界面是 desktop profile | `Get-CimInstance Win32_Process` 的 Electron 命令行 + 会话环境变量 `DSH_*` |
| 写入只有一处 | `plugins/lh-course-tree/commands.js`（工具与路由都调它） |
| 上下文注入可取值 | `plugins/lh-workspace-ui/selftest.mjs` 第 10 节（7 条断言） |
| 界面能画、能折、能绑 | `plugins/lh-workspace-ui/selftest-client.mjs`（39 条断言，含递归渲染） |
| 闸门 | `node scripts/check-all.mjs` → 25 绿 / 1 应然红（`check-restart`） |
| patch 不会让应用起不来 | **本轮新增闸门** `scripts/check-profile-patch.mjs`（profile 的 `cordis.patch.yml` 能否解析成数组 + 每个 `@lh/*` 行能否解析到包与两半）。此前这一类**没有任何闸门**，而它是"应用直接起不来"里最便宜也最常见的一种 |
