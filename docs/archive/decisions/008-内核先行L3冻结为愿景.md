# ADR-008：开发顺序——内核先行，L3 元插件冻结为愿景

- **背景**：插件清单跨越三个成熟度层级（L1 文本级 / L2 代码级 / L3 元级），动工难度差异大。
- **决定**：先写内核（loop/registry/context/session，全部领域无关）；L1 第一天插件化；L2 随注册表就绪跟进；L3"插件的开发插件化"冻结为愿景，L1 阶段只做"skill 作者插件"（自然语言教学方法 → SKILL.md）。
- **理由**：代码是收敛加速器，内核无任何领域借口可拖延；L3 的代码生成部分依赖沙箱等基础设施，时机未到。
- **放弃**：先写领域工具再补框架（会欠下架构债）；早期追求全自动插件生成。
- **状态**：**已废止（2026-09，见 ADR-011）**。废止理由：本条的前提是"内核由 LH 自己编写"；ADR-011 决定内核机制采用宿主 dsh，LH 不再自研内核，因此"先写内核"不再是一个可执行的动作。其中仍然有效的部分（L3 元插件冻结为愿景、L1 阶段只做 skill 作者插件）由 ADR-011 保留。
