# ADR-020：资料分类与题目抽取——对齐的单位是题目，不是页

- **背景**：作者定下这一步的目标：把 LH 做成刷题工具之后，先解决"题目怎么进来"。
  作者给的形态：*"将考公资料里的刷题-片段阅读600题录入进题库，题目和题解都在里面"*，
  流程是 *"agent 读文件名确定带'题本'后缀的是题集、带'解析'后缀的是题解，然后上篇和上篇对应，
  下篇和下篇对应，再抽出前几题简单校验一下是不是对应的，如果对应，把文件发给分题插件，
  ocr 图转文字-文字输入进 llm 分块并校验-分块结果录入题库"*。
- **作者对本 ADR 的直接纠正（原话）**：
  *"单位应该按题目来，当然目前是测试没问题，但是题解会比题集的单题内容多，
  所以取相同页数的话题解的题目会比题集少，这样：都取前 20 页，然后取前 20 题做题解和题集的对应，
  页数相比于题目有较长的冗余，后面对于全篇也是类似的思路，按题目顺序做对应，
  对应后随机抽一些题目来让 llm 做校验，检查对应是否准确。"*

## 决定

**1. 对齐的单位是题目，页只是"读到够为止"的冗余载体。**

**这条纠正了一个真缺陷。** 我最初的设计是"两个文件各取第 N–M 页然后配对"。
那是错的，而且错得很隐蔽：

| | 题本【上】 | 解析【上】 |
|---|---|---|
| 页数 | 94 | 212 |
| 承载题数 | 约 300 | 约 300 |
| 每题平均篇幅 | 约 0.31 页 | 约 0.71 页 |

**解析每题的篇幅是题本的 2.3 倍**（因为含讲解、批注、来源标注）。
所以"取同样页数"覆盖的题数不同——第 12 页的题本内容对不上第 12 页的解析内容。
按页配平会在**两边题目数量不一致那一刻**开始整体错位，而且错位之后每一题都还是"有答案"的，
**只是答案是别人的**。这种错不会报错，只会让题库静默变成废品。

**正确做法**：对齐用题号（印出来的，排版无关），页数向题目看齐——
题本 20 题可能占 6 页、解析 20 题可能占 15 页，各读到够 20 题为止。

**由此得到一条可推广的原则**：
> **对齐的单位必须等于语义单位，不能用一个"代理量"（页、字节、字符数）去代替它。**
> 代理量只在两个东西的密度相同时才等价，而"题本"与"解析"恰恰密度不同。

**2. 对齐的键是"哪一套 + 套内第几题"，而不是绝对位置。**

实测两个文件都在每套开头印 `练习题NN套`，套内题号从 1 重新开始。
所以键是 `(套号, 套内题号)`，两个文件都印，且**排版无关**。
绝对题号（把 600 题从 1 编到 600）不能用作键：上/下两册各自从 1 开始。

**3. 校验用题干文字，不用题号。**

对齐之后必须逐题验"解析里那一块讲的确实是题本里那道题"。判据是
**题本题干的前 12 个非标点字符是否出现在解析块里**。

- 不用"题号看起来对"：题号可能因为 OCR 漏字而错位，而错位后仍然"看起来对"。
- 不用"页数比例"：那正是被纠正的代理量。
- 取 12 个字符是折中：太少会在题库里撞车（"这段文字旨在说明"是套话，每题都有），
  太多会被 OCR 的单个错字打断。

**4. 题干只从题本取，解析只提供答案与讲解。**

实测解析页的 OCR 长这样：

```
1. (2021 年新疆省考 77%)
①花生批注：
如果从专业发展的角度看，同届不同专业的学生"混居"①，不仅会拓展
学生"混居"是全文论述话题。          ← 批注插在题干中间
学生的知识面，从更多维度构建学生的知识结构（A选项），还会给学生带来
②花生批注：
文章结构：分总结构。
```

**批注插在题干中间，还有上标标记**。所以：

- 若两边各取一次题干再"合并"，会得到两段不同的噪声文本，而且**没法判断该信哪个**；
- 抽取的单位虽然是「题本+解析」这一对，但两个文件**在字段上分工**：
  题本 → `stem` / `options`，解析 → `answer` / `analysis`。

**5. 全篇也按题目顺序对齐，然后随机抽样让 LLM 校验。**

作者明确这条要推广到全篇：*"后面对于全篇也是类似的思路，按题目顺序做对应，
对应后随机抽一些题目来让 llm 做校验"*。

抽样校验的意义：题干文字校验能抓"错位"，但抓不住"解析块里混进了邻题的讲解"
（因为邻近几题的题干也可能在附近出现）。那种错误要靠 LLM 读整块判断。

**6. 配对是前置条件，不是便利功能。**

只有题本、没有解析的题库**跑不起刷题循环**：`get_questions` 不返回答案，
`submit_answer` 靠题库里的 `answer` 判分——答案缺失会让判分全变 `null`（ADR-018 决定 5）。
所以"配对"必须在校验通过之后才能推进到抽取，不能先抽后配。

**7. OCR 用轻量引擎即可，但渲染必须正确。**

作者定：*"小体量就可以，不需要很高的准确度，而且后面还要 llm 校验的"*。
实测 RapidOCR（ONNX）单页 1.5–3.0 秒，中文识别质量足够（题干文字可用于校验）。

**但有一个前提被单独查证过**：渲染必须应用 PDF 的 `/Rotate`。
有些页是"横向 mediabox + /Rotate 90"，扫描仪把 A4 横着存再标旋转。
如果渲染不应用它，送进 OCR 的就是**躺倒的图**——识别质量下降却**不报错**。
`scripts/check_render_rotation.py` 把这条锁成回归测试。

## 实测数据（供后续决策）

`D:\考公资料\刷题` 全量：**10 个 PDF、2332 页、全部为扫描件（文本层 0 字符）**。

| 文件 | 页数 | 体积 | 分册 |
|---|---|---|---|
| 片段阅读600题-题本【上】/【下】 | 94 / 92 | 17.1 / 10.2 MB | 上 / 下 |
| 片段阅读600题-解析【上】/【下】 | 212 / 212 | 37.7 / 23.4 MB | 上 / 下 |
| 数量关系600题【题本】/【解析】 | 127 / 361 | 5.2 / 15.3 MB | — |
| 资料分析600题 题本篇/解析篇 | 188 / 392 | 84.6 / 182.2 MB | — |
| 逻辑判断600题 题本篇/解析篇 | 190 / 464 | 157.6 / 64.8 MB | — |

- **解析篇页数普遍是题本片的 1.7–2.9 倍**——这条实测数据就是决定 1 的依据。
- 上/下切点：**练习题第 16 套**（题本【上】末页页眉 `(上册)`、末题第 18 题；题本【下】从第 16 套第 1 题开始；
  两边目录各自列出 01–15 与 16–30）。
- 单页 OCR 实测 1.5–3.0 秒（降采样到长边 2000 后）。
  全量 2332 页约 1–2 小时；仅片段阅读 610 页约 20–30 分钟。

## 运行环境（实测，省得再查）

- **系统 Python 是坏的**：PATH 上的 `python.exe` 是 Windows Store 空占位符，
  `py.exe` 指向不存在的 `C:\Python312`，`Programs\Python\Python39` 是个空目录。
- **可用的是 `D:\miniconda\python.exe`**（3.12.9），已装 PyMuPDF 1.28.2（PDF 渲染）
  与 RapidOCR + onnxruntime 1.30（本轮装）。pypi 可达。

## 依赖的前提

1. `排列题本与解析` 依赖文件名带有可辨认的角色标记（题本/解析、题本篇/解析篇）。
   实测本批资料全部满足；**没有标记的资料需要人工指定**，脚本会报"未识别"而不是猜。
2. 题干文字校验依赖 OCR 质量达到"前 12 字基本正确"。实测满足。
3. 解析里**没有显式的 `答案：D` 行**，答案要从批注或讲解里推——这是字段抽取最难的一步，
   本 ADR 只定"从解析取"，不定怎么取。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| 按题目对齐（不用页） | 出现某套题两边数量不一致且无法对齐 → 先查是不是漏识别了题号，**不要退回按页对齐** |
| 键是（套号, 套内题号） | 某份资料的套号没印在页面上 → 需要改用"题号连续性"推断，并标注该文件置信度较低 |
| 校验用题干前 12 字 | 大量题目校验失败但人工看是对的 → 说明 OCR 质量不足或阈值不当，调 12 这个数；**不要取消校验** |
| 题干只从题本取 | 出现"题本缺题干、解析有"的题（如缺页）→ 那时应把该题标为残缺并报出，而不是从解析补 |
| 配对是前置条件 | 出现"先抽了再说配对"的流程 → 会产出答案全错位的题库，且表面上正常 |
| 渲染应用 /Rotate | `check_render_rotation.py` 失败 → 立刻停，所有 OCR 结果作废重跑 |
