# ADR-028：题目 id 必须全局唯一——并因此**换掉了 15 道题的 id**

- 日期：2026-09-20
- 状态：已采纳（**含一个破坏性后果，需要作者知情**）
- 相关：ADR-017（题目的对象与接口）、ADR-018（题库的物理形态）、ADR-020（对齐的单位）、
  `plugins/lh-question-bank/question.js` 的 `deriveQuestionId`

---

## 背景

新合成链（模型读题干 + 规则抽答案，见 ADR-029）跑通后，我核对了一件事：
**新题库里那道题的 id，和作者已经刷过题的那道题是不是同一个？**

答案是**不是**，而且**一道都不重合**：

```
旧：q-fc1f076fc0fd   number=set1-q1   path=2025年花生片段阅读600题-题本【上】.pdf
新：q-7ce38750fd84   number=练习题01-q1 path=片段阅读600题/2025年花生片段阅读600题-题本【上】.pdf
题干是同一道题。
```

事件日志里有 **18 条作答记录、涉及 15 道题**，全部指向旧 id。
`deriveQuestionId` 的注释早就写着这条后果：**"id 一变，那些答题记录就指向不存在的题——那是不可恢复的损失"**。
所以这件事必须写清楚，由作者决定怎么处置。

## 为什么 id 会变（三个参数里有两个不同）

`deriveQuestionId` 的键是 `(sourceRoot, sourceFile, number, 题干前 40 字)`：

| 参数 | 旧题库 | 新链 | 为什么新链这样选 |
|---|---|---|---|
| `number` | `set1-q1` | **`练习题01-q1`** | `set1-qN` 是**资料内编号**：两份资料都有 `set1-q1`，是两道不同的题。旧的合并题库里这个撞车**真实存在**（见下） |
| `sourceFile` | `2025年花生…题本【上】.pdf` | `片段阅读600题/2025年花生…题本【上】.pdf` | 新链的自然形态是"资料根下按科目录入"；相对路径与实测的记录一致 |
| `sourceRoot` | `D:\考公资料` | `D:\考公资料` | 相同 |

**我还试过反推旧 id**（`scripts/diff-question-ids.mjs`）：用旧题库的 `source_root` + 旧 `source_file` + 旧 `number` + 同一题干，
算出来是 `q-15fb5eca93d7`，**不是** `q-fc1f076fc0fd`。也就是说旧题库当年的派生参数
与它自己文件里记下来的字段**对不上**（多半来自更早的 `build_bank.py`），
那条链已经无法复现——**这本身也是一个必须知道的事实：旧 id 不可重算**。

## 决定

### 1. `number` 在题库里必须是**全局唯一**的题号，不再用资料内编号

新形态：`练习题01-q1`、`练习题02-q14`（分组 + 题内号）。

**这不是风格问题，是消除一个真实存在的撞车。** 旧题库里：

```
set1-q1 @ 2025年花生片段阅读600题-题本【上】.pdf = "如果从专业发展的角度看，同届不同专业的学生…"
set1-q1 @ 逻辑判断600题题本篇.pdf               = "中国古诗中曾有'借酒消愁愁更愁'的句子…"
```

两道完全不同的题共用一个 `number`。虽然 id 因为 `sourceFile` 不同而没有撞，
但**任何按 `number` 做的匹配都会错**——这正是 2026-09-19 那次
"知识点补丁只能补 13/49" 的根因（见 ADR-021 结论八）。

### 2. 破坏性后果：15 道题的 id 变了，18 条作答记录被孤立

**如实记下代价，不粉饰**：

- 旧题库（`考公刷题-片段阅读与逻辑判断.json`，49 题）**还在工作区里，没有被删**；
- 那 18 条作答记录指向的旧 id 在那份旧题库里**依然能解析**（历史没坏）；
- 但它们**不在**新题库里，所以新链看不到那段刷题史。

三种处置，作者选一：

| 处置 | 代价 | 收益 |
|---|---|---|
| **(a) 两册并存**（默认，什么都不做） | 旧 49 题与新 39 题有 20 道是重复的（同题两个 id），按知识点出题会重复出 | 零风险；旧记录完整 |
| **(b) 旧册退役**（`install-bank.mjs` 的反向操作：移走文件） | 那 18 条记录变成孤儿（历史留着，但没有题库能解析它们） | 只有一个权威题库，id 与出处统一 |
| **(c) 迁移旧记录**（按题干配对，追加"迁移"事件） | 不是不可做，但要**往日志里追记**——那是"伪造/修补历史"，与"只追加"的纪律相冲突 | 刷题史不丢 |

**我的建议是 (a) 先并存**，等四个 600 题全部入库、新链稳定之后，
再由作者决定是 (b) 还是 (c)。理由：现在旧册是**唯一能解析那 18 条记录的东西**，
在它退役之前没有任何损失，而它占的位置只是一个额外的题库名。

### 3. 因此定下一条纪律：**id 只能在"题库重建"时变，且必须写进 ADR**

`deriveQuestionId` 的三个参数里，`sourceRoot` / `sourceFile` 属于**安装期决定**，
`number` 属于**抽取期决定**。任何一处变更都会让 id 漂移，而**漂移不会报错**——
它只会让作答历史静默失联。所以：

> 改这三个参数中的任何一个 → 必须写一条 ADR，并说明已有作答记录怎么办。

## 怎么知道它错了

| 失效信号 | 说明 |
|---|---|
| 同一个题库里出现"同题两个 id"（题干相同、id 不同） | 说明有两套抽取参数在用 → 回看本条决定 2 |
| 作答记录里出现 `question_id` 解析不到的条目 | 说明 id 已经漂移过、且没人记下来 |
| 四个 600 题入库后，题号里出现 `set?`（分组为空） | 说明某份资料不印分组标签 → 需要 `--pages-per-set` 兜底（见 ADR-029） |
