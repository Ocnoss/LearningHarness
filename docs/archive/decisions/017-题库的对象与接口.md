# ADR-017：题库的对象与接口——题目是资源，作答是行为

- **背景**：下一步要做题库相关插件。作者定的顺序是对的：**"先搭起来行为的对象和接口，再去对行为分类"**。
  理由：分类器要表达"他对 X 做了解答"，而 **X 是什么决定了能表达什么行为**。
  反过来做会得到一个与对象配不上的词汇表。
- **参考**：`D:\Learning plugins\output\sample_questions.json` 给出过前人抽取的题目结构：
  ```json
  { "id": 1, "content": "下列关于马克思主义基本原理的说法，正确的是：",
    "options": ["…", "…", "…", "…"], "answer": "A", "analysis": "…" }
  ```
  **这个结构对"做单选题"够用，但对 LH 不够**——它没有出处、没有知识点、也没有跨资料的稳定身份。

## 决定

**1. 题目（Question）是"资源"，不是"事件"。**
- 依据 `docs/decisions/009`：**事件 = 时间流中的一次性行为；资源 = 可寻址可复用的产物。**
- 一道题会被反复引用（多次作答、多次讲解、被多个策略使用），所以它是**资源**，
  有稳定 id，可被 `content_ref` / `derived_from` 指向。
- **作答（Attempt）是事件**：用户在某时刻答了某题、选了什么、结果如何。一次性行为 → 事件。

这条切分是整个题库的骨架。它同时解决了一件事：**"这道题"与"他这次答这道题"是两个不同的东西**，
将来"同一题在不同时间答对率不同"才能被表达（那正是遗忘曲线与间隔重复的依据）。

**2. 题目的稳定 id 由"出处 + 源编号"派生，不用顺序号。**
```js
questionId = 'q-' + sha256(`${sourceRoot}|${sourceFile}|${numberInSource}|${stem前40字}`).slice(0, 12)
```
- 理由：**顺序号不是身份**。`id: 1` 在不同资料里都指第 1 题；重新导入一次就可能全部错位。
  而"出处 + 源编号 + 题干指纹"让同一道题从同一份资料里总是得到同一个 id（**幂等重导**），
  也让"同一题出现在两份资料里"可以被发现（题干相同、出处不同）。
- 为什么加"题干前 40 字"：有些题集的编号本身会变（重排版、合并分册）。
  加题干指纹后，编号漂移不会让同一道题变成两道。
- 为什么不用纯内容哈希：同一道题的 OCR 结果可能差一个空格就变 id。
  出处 + 编号提供稳定性，题干指纹提供抗漂移——两者结合。

**3. 答案统一归一化为"选项标签数组"，而不是单个字母。**
```js
answer: ['A']          // 单选
answer: ['A', 'C']     // 多选
answer: ['42']         // 填空（内容即答案文本）
```
- 理由：单选与多选共用一套结构，**下游不必为题型分叉**。
  题型信息留在 `kind` 字段里（`single_choice` / `multiple_choice` / `fill_blank` / `other`），
  但"答案是什么"只有一种表示。
- `other` 是显式的兜底：**遇到无法归类的题型时如实标注，而不是丢题或强行归类**。

**4. 题目必须带出处与知识点，两者都可空但必须显式写。**
```js
{
  id, kind, stem, options, answer, analysis,
  topics: [],                 // 知识点引用（契约 §4.3 待定，先允许空）
  source: {                   // 出处：指回资料
    resource_ref,             // 哪份资料（LH 资源事件 id 或 content_ref）
    path,                     // 资料路径
    number,                   // 资料内的题号
    page,                     // 可选：页码（PDF 抽取时可得）
  },
  provenance: { plugin, version, model? },   // 谁抽的、用什么模型（若是 LLM 抽取）
}
```
- `topics` 先允许空数组：契约 §4.3 的知识点体系尚未定案（自动抽取 / 用户自建 / 混合）。
  **空数组是合法状态**，不是"未填写"。这样题库可以先跑起来，知识点体系定案后再补。
- `provenance` 里记 `model?`：若题目是 LLM 抽取的，**那是有误差的判断**，必须可追溯
  （与 ADR-016 的"降级必须留痕"同一个理由：仪器质量决定下游可信度）。

**5. 批量导入是一条事件 + 一次外置内容，不是每题一条事件。**
- 导入记 `lh/resource/questions-imported`，带 `content_ref` 指向外置的题目集合文件
  （形态与资源索引器一致：**产物进工作区文件，事件只留指针**）。
- 单题不各记一条事件：**导入是"一次性行为"，题目是"产物"**——
  题目已经在文件里且有稳定 id，不需要在事件流里各占一行。
- 但**作答必须有事件**，因为它是一次性行为，且是学习证据的载体。

**6. 作答事件的形状（这是"行为的对象"与"行为分类"之间的接口）。**
```js
// 事件类型：lh/user/attempt
{
  question_id,                 // 指回题目资源
  response,                    // 用户实际给的东西（选了什么 / 填了什么）
  correct: true | false | null,// null = 尚不可判（如填空需人工或 LLM 判定）
  source: 'human' | 'llm' | ...,// 谁在作答——这决定它是不是学习证据
  duration_ms,                 // 可选：用时
  context: { session_ref, seq } // 可选：指回当时的对话（坐标）
}
```
- **`correct` 允许 `null`**：判定可能是另一步（填空、主观题），而"尚未判定"与"答错"是两件事。
- **`source` 必填**：AI 代答不是学习证据（契约 §3.1 明确警惕"AI 代写作弊"）。
  这个字段让分类器能机械地把非人类作答排除掉——与坐标记录器里 `source_kind` 的作用同构。
- `context` 引用对话坐标：于是"他答这道题时正在问什么"可回溯（用已实现的取回器）。

**7. 本阶段只做"对象与接口"，不做抽取。**
从扫描版 PDF 里批量抽题（OCR + 版式解析 + 图表题）是**独立的、更大的工程**，
且它属于"抽取"（一种判断），不属于"对象定义"。
所以本阶段交付：schema + 校验 + 导入/作答的接口 + **少量手写题目**用于验证。
批量抽取等 schema 稳定后，由专门插件做（它会用 `lh-model-tier` 的 `flash` 档 + `callModel`）。

## 依赖的前提

1. 契约 §4.3 的知识点体系尚未定案——`topics` 允许空，体系定案后补，**不阻塞**。
2. 题目的批量抽取依赖扫描 PDF 的内容可读。**风险**：`D:\考公资料` 里的题集是扫描版
   （170 个 PDF，大部分应是图片型），OCR 质量决定抽取质量。**这不在本 ADR 范围内**。
3. 作答的判分逻辑可能来自插件（规则）或模型（LLM 判定）。本 ADR 只定字段，不定判分方式。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| 题目是资源、作答是事件 | 出现"必须把题目本身的变化也记成时间流"的需求（如题目被修正）→ 那时应当**新资源 + `supersedes`**（ADR-009 决定 3），而不是改成事件 |
| id 由出处+编号+指纹派生 | 同一道题被重复导入却得到不同 id（说明指纹不稳），或不同题得到同一 id（说明指纹区分度不够）→ 调整指纹长度或加入更多字段 |
| 答案归一化为数组 | 出现"必须有单字母答案"的下游（如第三方题库格式）→ 加一个**投影**做转换，不改本字段 |
| `topics` 允许空 | 知识点体系定案后长期没人填 → 说明抽取/自建那条路没做，题库与教学脱节 |
| `correct` 允许 null | 长期大量 null（说明判分那一环没做）→ 判分要补，但**不能改成默认 false** |
| 只做对象不做抽取 | schema 稳定后迟迟没有真实题目 → 抽取成了瓶颈，应立刻转向 |
