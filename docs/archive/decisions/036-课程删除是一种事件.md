# ADR-036：课程的"删除"是一种事件，而且删除只删结构、不删对话

- **状态**：已冻结（2026-10-08）
- **触发**：作者要求"添加对课程的删除功能，并且与重命名、新增子课程等功能的按钮集成"。
- **为什么写 ADR**：ADR-032 冻结过课程树的**事件词汇**（`lh/course/created|renamed|reparented|session-bound`）。
  本次要往里加一个词，属于 §4.3(a)"修订一条已冻结的决策"。同时它引入了一种**新的破坏性操作**，
  而"破坏性操作一律白名单"是本项目的规则 4——两者都需要留下依据。

---

## 1. 决定（一）：删除 = 追加一条 `lh/course/deleted`，而不是真的删掉什么

append-only 下没有真正的删除。删一门课的记录方式是"再写一条说它从此刻起不可见"：

```json
{ "type": "lh/course/deleted", "data": { "node_id": "course-xxxx", "title": "资料分析",
  "sub_course_ids": ["..."], "session_ids": ["..."] } }
```

于是：旧事件一条不动、树能重放出"删除之前长什么样"、删错了查得到**是谁在什么时候删的**。
代价是日志只增不减——本项目已经接受过这个代价（ADR-012：日志一旦能改就不再是事实源）。

**`sub_course_ids` / `session_ids` 是唯一两个"派生物"字段，而且投影完全不读它们。**
理由是它们记的不是树的状态，而是**人的决定**：

> "删的那一刻，被列出来给人看过、并被确认的是这些东西。"

派生范围会随之后的 reparent 而变，而"他当时确认了什么"不会变——那恰恰是事故复盘要问的问题。
所以它们不是"缓存进了日志"，是白名单纪律的证据。

## 2. 决定（二）：可见性 = "被删的节点 + 它**当下**的全部后代"，每次投影时重算

**不是**在删除事件里预先列出后代。理由是一条具体的失效路径：

> 若后代列表在写入那一刻冻住，之后**再往被删节点下加一个子课程**就不会被列进去，
> 于是出现"父课已删、子课还在树上"的鬼影。

每次投影按当前结构重算的语义是"**这个节点及其当下的一切后代不可见**"——一句话、无需解释残留情况。

实现上必须**迭代到不动点**，不能一遍扫描：删除可以嵌套（先删子、再删父），
一遍扫描在链长 > 1 时会漏（先遇到子节点时它的父还没被标记）。`selftest.mjs` 第 10 节钉的就是这一条。

**边界（明确不做）**：删 B 不会连带删它的父 A。把父也一起删掉等于越权，
而那正是规则 4 要防的形状（"删掉所有不匹配的"）。

## 3. 决定（三）：删除**只删课程结构，不删对话**

会话是宿主的东西，LH 无权删。原来绑在被删节点下的对话变成**"未归课"**。

- 绑定事实（`lh/course/session-bound`）**仍然留在日志里**，投影不做"它还算不算数"的判断
  ——这是投影与视图的分工：投影回答"哪些节点不可见"，视图回答"某会话因此算未归课"。
  `directory.js` 据此把这类绑定放进 `orphan_bindings`，界面把它们当未归课显示（**不静默吞掉**）。
- `resolveCourseRef` 默认**不命中已删节点**（`includeHidden` 才命中）。
  这一条是必须的：否则"删了一门课之后再用它的 id 建子课程"会成功，
  新子课程挂在一个不可见的父上，**当场变成鬼影**。
- `coursePathText` 对"绑到已删课程"的会话返回 null（= 不注入上下文）。
  不判可见性的话，模型会继续被告知"你属于「资料分析」"，而那门课在界面上已经不存在——
  上下文与实际所见不一致，是最难查的一类错。

## 4. 决定（四）：删除的形状是**两段式**，而且白名单挡在**接口**上

| 入口 | 第一段（只读） | 第二段（写入） |
|---|---|---|
| 界面 | 点「删除」→ `GET /lh/workspace/impact?node=…` → 弹出清单 | 点「确认删除」→ `POST /delete` 带 `confirm: true` |
| agent | `delete_course` **不带** `confirm` → 只回报影响面 | 带 `confirm: true` 才真的删 |
| HTTP 接口 | — | `confirm !== true` → **409 + 影响面**，拒绝执行 |

三条路用的是**同一个纯函数** `previewDelete`（`@lh/course-tree/commands`），
所以"界面给你看的清单"和"模型给你念的清单"不可能不一致。

**为什么接口层也要挡**：一个"点一下就删掉一棵树"的接口，迟早会被某处顺手调用。
按钮上的确认框挡不住别的调用方；`confirm: true` 这个显式参数能。

**别的选择**：(i) 只允许删空节点（无子课程、无会话）——否，用起来太烦，
且"先清空再删"会把一次操作拆成很多次，反而更容易误删；
(ii) 删除时把子课程提升到父级——否，那等于**静默改变**了学习者的结构意图，
不如明确地说"这一支都没了"；(iii) 不做删除——否，作者明确要求。

## 5. 决定（五）：界面里三个课程操作**集成为一行按钮**，删除排最后

第一版是"改名 / 加子课程"两张各自带输入框的卡片竖排 + 删除另做一处：
三个功能占掉半屏，而且两张卡片长得一模一样，一眼分不出在改哪个。
现在是一行**改名 / ＋ 子课程 / 删除**：点哪个才展开哪个的输入，同一时刻最多一个编辑器打开；
删除在最后（危险动作不放在鼠标动线上）并且是唯一用 `state-error-primary` 的按钮。

## 6. 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| 删除是追加事件 | 有人报告"删了之后日志里查不到是谁删的" → 说明有别的路径在直接删数据 |
| 可见性每次重算 | 树上出现"看不见的父、看得见的子"的鬼影，或删了子课程父课程也消失了 |
| 只删结构不删对话 | 作者说"我删了课，我的对话没了" → **最高优先级**，先查 `previewDelete` 的 `session_ids` 是不是被当成了待删清单 |
| 两段式 + 接口层 confirm | 日志里出现"没人确认过的 deleted 事件" → 有调用方绕过了 `confirm` |
| 按钮集成一行 | 作者说"分不出在改哪门课" → 说明按钮行的上下文（标题/颜色）不够显眼 |

## 7. 证据在哪

| 结论 | 证据 |
|---|---|
| 删除事件与投影 | `plugins/lh-course-tree/tree.js`（`DELETED`、`hidden`、`isHidden`） |
| 不动点迭代的必要性 | `plugins/lh-course-tree/selftest.mjs` 第 10 节（先删子、再删父） |
| 不命中已删节点 | 同文件第 9 节（`resolveCourseRef` 按 id 与标题都不命中） |
| 绑定事实保留、但算未归课 | 同文件第 12 节 + `directory.js` 的 `orphan_bindings` |
| 两段式与接口层拒绝 | `plugins/lh-workspace-ui/selftest.mjs` 第 8 节（409 路径）+ `index.js` 的 `/delete` |
| 界面：预览不变、确认才删 | `plugins/lh-workspace-ui/selftest-client.mjs` 第 9 节 |
| 色彩只用主题令牌 | 同文件第 12 节（扫"不挂在 `var(--dsw-alias-` 上的裸色值"必为空） |
| 闸门 | `node scripts/check-all.mjs` |

## 8. 未做的事（如实）

- **拖动改父**（`lh/course/reparented` 事件与投影都已支持，缺界面手势）。
- **撤销删除**（"取消删除"= 用新 id 重建一个同名课程，历史不接续；真正的撤销需要一条
  与 `deleted` 对偶的事件，本轮没设计）。
- **界面长什么样我仍然没看过**（无头）：色彩搭配、动效快慢、按钮行的疏密只能由作者看一眼。
  本轮能给的是"颜色全部来自主题令牌""没有裸色值"这两条**可验证**的约束。
