# ADR-029：抽取链的两侧分工——题本归模型（读+改错），解析归规则（抽答案），模型作答只作交叉验证

- 日期：2026-09-20
- 状态：已采纳（第 1–2 套已跑通，四个 600 题待跑）
- 相关：ADR-015（建模与运行分离）、ADR-018（选项与答案的结构）、ADR-020（对齐单位是题目）、
  ADR-021（入库前的 LLM 预处理、答案绝不进判分）、ADR-028（题目 id）

---

## 背景

作者要"把四个 600 题共 2400 题全部入库"，并指定：
**每做 600 题停下来等确认**；先确认 OCR 分块是否过 LLM；并要看 token / 时间 / 内存。

上一轮实测（`data/extract/probe-*.json`）定下的分题方案是"整页喂、按语义辨题"，
但当时**只到"抽题"为止**，没有接上答案与题库。本 ADR 记录接上之后的两侧分工。

## 决定

### 1. 两侧各司其职，**不混**

| 侧 | 谁做 | 产出 | 为什么是它 |
|---|---|---|---|
| **题本** | **模型**（`extract-questions.mjs`）：整页整体读、顺手修正 OCR 错字与断行 | 题干 / 选项 / 分组 / 页码 / 它自己的作答 | 双栏串行与断行是规则切不好的：旧链 20 题里 **17 题选项评注全丢、13 题讲解不足 20 字**（`count_column_damage.py` 实测） |
| **解析** | **规则**（`extract_answers.py`，已有链）：抽 `【参考答案】` / 题型 / 实战解析 / 选项评注 | 官方答案 / 讲解 / 置信度 | 答案**印在纸上**（`【参考答案】C`，28 页 37 处），规则抽得准、可复现、零成本。该脚本自己写的判断：*"用 LLM 去做一件规则能做的事，既贵又不可复现"* |

**模型把题干重新输出一遍不是冗余，是校验通道**（作者 2026-09-20 明确）：
OCR 没有"接收修改意见"的接口，所以"模型读出来的文本"就是唯一可用的反馈；
它与 OCR 原文的差异即证据（逐字差异 = 识别问题；结构差异 = 阅读顺序问题）。
因此**题干以模型输出为准，OCR 原文降为校验基准**。

### 2. 模型自己的作答**绝不进判分路径**，只做交叉验证

ADDRESS-021 决定 3 的红线不变。新增的用法是：把模型的独立作答与官方答案对比，
**不一致的题就是最该被人看一眼的题**。

**实测证明这条不是形式**：第 1–2 套里 9 道不一致中，**多数是解析侧的答案块错位**——
`练习题01-q4` 的官方答案标 B，而它的讲解正文讲的是"建筑设计者在把握本土与外来关系"
（那是**第 3 题**的讲解），模型选 C 反而对。
而规则链自己的三项自校验**一项都没报**（还标了 high/medium 置信度）。

> **结论：模型独立作答是当前唯一能抓到"答案块错位"的仪器。**
> 所以交叉验证必须**保留并在报告里逐条列出**，不能合成一个分数盖过去。

### 3. 窗口 = 分组锚优先 + 题数预算封顶 + 跨页保护

- **分组锚**：套/章节/专题印在页面上（`练习题01套`），是语义边界，不落在题中间；
- **题数预算**（程序用题号正则数得出来）：实测逼出来的——逻辑判断每套 16 页、
  题干是多段材料，一窗 20 题的输出会顶到 16k 上限被截断，而**截断不报错、只静默丢半截**；
- **跨页保护**：下一窗回退 `(一道题最多占几页 - 1)` 页。回退那一页不是浪费——
  边界上的题会被两个窗口各读一次，于是**重叠买到的是一次独立复核**（见决定 4）。

**页码是程序级语义**：喂进去时当锚，模型只引用，不需要判断。

### 4. 重叠窗口的唯一用途是"独立复核"，所以它必须被算出来

`crossCheck` 按 `(分组, 题内号)` 比对两次读法的答案与文本相似度：
一致 = 共识；不一致 = 进复核清单。

**实测抓到一条真实非确定性**：`练习题01 第8题` 在窗口 2-5 读成 A、窗口 5-7 读成 D，
而官方答案是 A——**同一模型、同一 `temperature: 0`，两次读法不同**。
这正是它同时也在"模型 vs 官方"不一致清单里的那道题。
→ **一道题被读两次且两次不同，是"这题模型不可靠"的确定性信号。**

### 5. 出处必须**按题回填**（`normalizeQuestion` 之后）

踩到的坑：把分组/页码/模型作答塞进 raw 的 `provenance` 是白费的——
`normalizeQuestion` 只搬它认识的字段，`provenance` 用**传进去的参数**覆盖，
于是这些信息**全被丢掉**，而表现是"题库里查不到这题是哪一套的"（不报错，只是没有）。

修法：`number` 换成全局唯一的 `练习题01-q1`（同时根治 ADR-028 的撞车），
再用同一个 number 把出处回填进题库对象——**id 与出处绑在同一把钥匙上**。

## 实测（片段阅读 第 1–2 套，端到端跑通）

| 阶段 | 工具 | 结果 |
|---|---|---|
| 题本切题 | 模型（`mimo-v2.5-pro`，7 窗并发 3） | 40 题（2 套各 20 题，无缺号），**56k tokens / 墙钟 323s / 峰值内存 62 MB** |
| 解析侧阅读顺序 | `apply-reading-order.py`（**确定性、不花 token**） | 31 页里 30 页文本改变；重排后第 1–2 套对齐 **41/41 全对** |
| 答案抽取 | `extract_answers.py`（规则） | 41/41 有答案（high 9 / medium 31 / low 1），含讲解与选项评注 |
| 合并 | `assemble-bank.mjs` | **39/40 入库**（1 题因选项缺失被拒），全部有官方答案/讲解/知识点，出处 39/39 回填 |
| 交叉验证 | 同上 | 一致 **30/39（77%）**；9 条不一致逐条列出 |
| 入库路径 | 插件自己的 `getQuestions` / `submitAnswer` | 取题**不泄答案**；判分三态正常；作答写进事件日志 |

## 成本推算（四科 2400 题）

按实测每窗约 8k tokens（输入 2.6k + 输出 5.4k）：

| | 窗口数 | tokens | 墙钟 |
|---|---|---|---|
| 题本侧（约 590 页） | ~130 | ~1.0M | ~1 小时 |
| 解析侧（约 1440 页） | ~145 | ~1.0M | ~1 小时 |
| OCR（2028 页，串行 1.5s/页） | — | — | ~52 分钟 |
| **合计** | ~275 | **~2M tokens** | **~3 小时** |

**这是"每 600 题停下来"的换算**：每批约 45–60 分钟、约 0.5M tokens。

## 依赖的前提

1. 题本与解析**都印分组标签**（实测片段阅读与逻辑判断都印；不印的用 `--pages-per-set` 兜底）；
2. 解析侧的答案形态是 `【参考答案】X`（实测该资料如此；其它资料需先 `probe_answer_markers.py` 探查）；
3. 一道题不超过 `--max-question-pages` 页（当前取 2）。

## 怎么知道它错了

| 决策 | 失效信号 |
|---|---|
| 题干归模型 | 入库的题里出现"被改写/概括过的题干"（比对原文即可发现）→ 提示词里的"只修正不改写"没生效 |
| 答案归规则 | 出现"官方答案与讲解正文说的不是一个选项"→ 解析侧块边界错位（**本轮已实测到 1 例**）→ 该题进复核，不要用它判分 |
| 模型作答只作交叉验证 | 一旦发现模型答案被写进题目的 `answer` 字段 → 立刻回退，这是红线 |
| 题数预算封顶 | 某窗的输出 token 长期贴着上限 → 说明预算该调小，否则迟早截断（而截断不报错） |
| 跨窗复核 | 一致率突然下降 → 先看是不是窗口切小了（边界上的题变多） |
| 出处按题回填 | 题号里出现 `set?` 或 `null` → 分组没读到 → 检查套头正则与资料是否印标签 |
