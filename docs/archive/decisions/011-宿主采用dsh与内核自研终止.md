# ADR-011：宿主采用 dsh，内核自研终止

- **背景**：LH 的原定路线（ADR-008）是"先写内核（loop/registry/context/session）"，并在 Python 中完成了可运行的骨架（`agent/loop.py`、`registry.py`、`context.py`，含 append-only JSONL 事件与 `pre_model_call`/`post_tool_result` 两个钩子）。实践结果是：内核机制本身被写出来了，但项目停在那里——没有产生任何面向学习者的可用功能，而 ADR 累积到十份。
- **根本原因（本条的核心证据）**：`ARCHITECTURE.md` 第三条法律"第 N 层未书面冻结前，禁止讨论第 N+1 层"使接口层的冻结成为动工前提，而接口层四个开放问题的正确答案只能由"东西真的跑起来"提供。规则因此保证了"未完成"是一个稳定状态。这不是能力问题，是度量方式问题。
- **决定**：
  1. **内核机制采用宿主 dsh**，LH 不再自研内核。宿主已提供并视为已冻结：append-only 事件日志（`dsh-session`）、投影与投影持久化（`dsh-session-projection` + `dsh-session-projection-cache`）、上下文拦截点（`agent/pre-step`）、系统提示词组装（`dsh-system-prompt`）、工具注册与执行管线（`dsh-tools`）、插件加载与可逆卸载（Cordis）、撤销与回滚。
  2. **LH 的资产是事件词汇表 + 插件 + 契约**，不是内核代码。§8.2 的"契约自持"落到文件边界上：只有适配层允许 import 宿主包，领域层只 import LH 自己的类型。
  3. **实现语言改为 TypeScript**（宿主为 Node 运行时）。Python 骨架降级为对照实现与思路来源，不再维护。
  4. **保留 ADR-008 中仍然有效的部分**：L3"插件开发插件化"继续冻结为愿景；L1 阶段只做 skill 作者插件。
  5. **产品形态与外壳解耦的判断不变**（ADR-010 仍然有效）：产品为开源 Web 应用，宿主自带界面只是早期外壳；部署门槛不是主要风险——一段可粘贴的命令或三分钟部署视频对非专业学习者不构成实质障碍。
- **新增：第四条分层法律（产品法律）**
  > **任何时刻，必须存在一条用户可感知的完整闭环在运行。允许被冻结的层次，只能是这条闭环已经走过的层次。**
  - 理由：现有三条法律度量的是"冻结"，而冻结的正确性只能由运行提供。没有闭环，冻结就是猜测的累积。
  - 推论：文档不得先于闭环扩张。当"再想清楚一点"与"让最小闭环跑通"冲突时，后者优先。
- **对既有决定的写回**：
  - **ADR-008 废止**（前提消失）。
  - **ADR-010 修订**（内核不再是自研 Python 库；语言改为 TypeScript；验证顺序保留）。
  - **ADR-002 表述更正**：原表述把"插件调用记录"列为内核持有的三类事实之一。按新契约 §1.4（内核连"什么值得记"都不知道），系统行为记录归**记录器插件**，内核不裁决操作元数据的学习语义。ADR-002 的实质立场（事实归内核、解释归插件、解释必须带血缘回流）不变。
  - **Claim 接口（ARCHITECTURE.md §3.1）升级**：`query(topic) → Claim{estimate, confidence, evidence}` 中的 `estimate` 删除，改为**带出处与置信度的断言集**（新契约 §4.1）；不做确定性画像，断言必须可审计、可争议，且只有沿课程树向上时才以断言形式流动。此为概念升级，非推翻。
- **第一个用户**：项目作者本人。验收标准随之可测量：**连续自用两周后，判断系统对自己的断言是否准确、是否可反驳**。§8.2 的三段式路线、分岔点、界面错配等问题全部推迟，不再构成 MVP 的前置条件。
- **放弃**：自研内核；为内核机制写任何设计文档（宿主已冻结它们）；在最小闭环跑通前冻结接口层；等待"架构完全想清楚"再动工。
- **可参考的宿主生态先例**（不作为依赖，仅证明可行性）：`dsh-roleplay` 以投影持有领域状态、私有上下文另立事实源、回退随事件前缀恢复；`dsh-liketavern` 实现了角色卡、prompt presets、lorebooks、长期记忆与可回滚操作——其中"策略即数据 + 条件触发注入"与 LH 策略层的构想同形。

### 依赖的前提（前提塌了，本 ADR 需重审）

1. 宿主 dsh 保持"一切皆插件 + 事件溯源"的架构，且 `agent/pre-step`、`sessionProjections.register` 等接缝不被破坏性变更移除。**已知风险**：dsh 为开发者预览版，README 明确将有破坏性变更，且有移除 SQLite 后端的先例（新契约 §8.1 已记录）。
2. 第三方的会话级投影足以承载 L2 证据层；跨会话的 L3 断言集必须由 LH 自己持有（宿主投影按 session 键控）。
3. 作者本人能作为有效测量仪器：能判断"系统对我的断言准不准"。

### 新增证据与一处重要更正（2026-09-15，阶段 1–2 实测）

**已证实的机制（源码级 + 实测）**：

| 事实 | 证据 |
|---|---|
| 自定义 preset 走 `<DSH_HOME>/.agent-presets/<id>/agent.cordis.yml` 可被宿主发现，trust=`user` | 实测：`discoverPresets()` 列出 `lh`，未标 broken |
| preset 的显示元数据 `preset.yml`（name/description）被读取 | 实测：选择器名显示为"LH 学习模式（验证中）" |
| preset 行里的**相对路径**从 preset 自己的目录解析 | 源码：`dsh-agent-presets/lib/index.js:500` `if (name.startsWith('.')) return super.import(...)`，而 `Include` 把 baseUrl 设为组合文件目录 |
| preset 行里的**绝对 Windows 路径可用** | 源码：同上 `:496` `pathToFileURL(name).href`。**更正**：此前"绝对路径不可用"只对 profile patch 成立（那里 `boot()` 不传 `bareModuleBaseUrl`，未安装做该转换的 Include 子类），preset 行是例外 |
| 裸包名从宿主组合目录解析 | 源码：同上 `:501-505` `internal.import(specifier, base)`，base 来自 mount 前记录的 `agentCtx.baseUrl` |

**更正：`ignorable` 标记无法由外部插件设置 —— 决定性影响 LH 的事件落点**

原判断（本文档早期版本及会话中）认为"插件可以往 dsh 会话日志写自定义事件，只要标记 `ignorable: true`"。**实测与源码表明做不到**：

1. `Session.append(type, data, ...opts)` 构造事件时**只提取** `sourceEventSeqs` 与 `surfaceOp`，`ignorable` 被丢弃（`dsh-session/lib/index.js` append 实现）。
2. 持久化批量写入的是事件对象本身：`this.pending.push(structuredClone(event))`（`dsh-session-persistence/lib/index.js:326`）。
3. 重载时 `assertEventsSupported` 拒绝"未知类型且 `ignorable !== true`"的事件（同文件 `:1119`）。
4. 结论：**外部插件用 `session.append` 写自定义事件类型，会使该会话在下次重载时拒绝加载。**

**因此本文档"决定 2"（LH 事件信封自持）不仅是设计偏好，而是唯一可行的路线**：dsh 会话日志的词汇表对外部插件事实上是封闭的。若确实需要与会话绑定的持久状态，可用通道是 `sessionProjections.register`（宿主持有并按 session∩key 持久化，状态须为纯 JSON，`stateVersion` 作失效锚），而不是往日志追加事件。
