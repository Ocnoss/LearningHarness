# ADR-010：产品形式——开源 Web 应用，内核无头库

- **背景**：确定早期产品形式；要求早期动工不导致架构僵化。
- **决定**：产品形态为开源 Web 应用；但内核（harness/）实现为纯 Python 库，零 HTTP 依赖，Web 后端只是与 CLI 平等的一层壳（apps/ 下）。验证顺序：先 CLI 壳验证内核 API，再套 FastAPI。
- **理由**：参照 dsh 的能力/终端解耦形态；未来必有其他壳（移动端、SDK）；干净的内核库更易吸引开源贡献。
- **放弃**：内核与 Web 后端一体（每次加壳还债）；先做 Web UI（验证内核 API 的成本高）。
- **状态**：**已修订（2026-09，见 ADR-011）**。修订内容：内核不再是"LH 自己实现的纯 Python 库"，而是宿主 dsh 提供的机制；LH 的实现语言随之确定为 TypeScript（宿主为 Node 运行时）。仍然有效的部分：产品形态为开源 Web 应用、内核与外壳解耦、先以最薄的壳验证内核 API 再谈产品界面——该验证顺序由 ADR-011 继承，只是"内核 API"改为"宿主机制 + LH 插件契约"。
