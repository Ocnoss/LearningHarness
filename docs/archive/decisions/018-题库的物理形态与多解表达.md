# ADR-018：题库的物理形态——单一事实源与"多解"的表达

- **背景**：ADR-017 定了题库的对象与接口（题目是资源、作答是事件、id 派生规则、作答事件字段）。
  实现时撞上四个它没管的决定，而这些决定**改起来比字段贵**——它们决定数据住在哪、
  以及"以前的记录以后还能不能读"。
- **作者原话（本次任务）**：*"先搭起来行为的对象和接口，再去对行为分类"*。
  所以本 ADR 与 ADR-017 一起构成"对象与接口"这一阶段的完整交付，**不含抽取**。

## 决定

**1. 作答事件写入 `events.jsonl`，**不**另开一个 `attempts.jsonl`。**

这条推翻了我实现时的第一版想法。第一版打算把作答单独存一个 append-only 的账本文件，
理由是"作答会被高频查询，混在事件流里要扫描"。

**为什么否掉自己**：`events.jsonl` 已经是 LH 的唯一事实源（契约 §2.2）。
把作答再写一份到别的文件，就有**两个事实源**，而两者之间没有任何机制保证一致——
这正是契约最反对的事。而且：

- 作答**本来就是事件**（ADR-017 决定 1），把它搬出事件流是自相矛盾的；
- 查询成本被高估了：`events.jsonl` 是 JSONL，按行读 + 按 `type` 过滤，
  几千条记录的扫描在毫秒级。**先测量再优化**，而这里连测量都还没做；
- 真到了需要索引的规模，正确的做法是**派生缓存**（契约允许的"可派生"类），
  缓存丢了可以重建。而另开一个手写账本**丢了就没了**——它会被误当成事实源。

**由此产生的一条纪律**：任何为查询建立的索引文件都是**缓存**，必须能从 `events.jsonl` 重建；
不允许出现"只有那个文件里有"的信息。

**2. 题库以文件形式存在工作区，事件只留指针。**

```
<workspaceRoot>/lh-questions/<题库名>.json     ← 题库正文（人可读、可带走、可手改）
events.jsonl: lh/resource/questions-imported    ← 一条事件，content_ref 指向它
```

与资源索引器（`lh-index/`）同构。理由也同构：

- 题库是**产物**，用途是"存在工作区里、以后反复引用"，不是变成一段对话记录或一条巨型事件；
- 契约 §2.2：大 payload 不内嵌，进内容存储；
- 落到**工作区**而不是 `data/`：题库属于学习内容，跟着学习者走；
  `data/` 放的是 LH 自己的运行数据（事件日志、模型档位配置）。两者寿命不同，不该混。

**3. 题库更新 = 同名文件重写 + 事件里记 `supersedes`。**

- 文件名稳定（不加重导时间戳），所以**引用题库的路径不会因重导而失效**；
- 但"旧版本"不靠文件保留——文件被覆盖了，而 `supersedes` 链在事件流里留下"哪次取代了哪次"；
- 旧题库正文若要找回，靠 `data/resources/` 里的历史 `content_ref`。

这与资源索引器**不同**（后者每次生成带时间戳的新文档）。差异的理由：
索引文档是**给人看的快照**，多留几份有价值；题库是**被程序引用的对象**，路径必须稳定。
**同一个原则（ADR-009 决定 3：更新 = 新资源 + 指针），在两种用途下导出不同的文件名策略。**

**4. 题目结构加 `accept` 字段：其他可接受的答案。**

```js
{ answer: ['22'], accept: ['二十二', '22人'] }   // 标准答案 + 其他判为正确的写法
```

**为什么必须加**：填空题天然多解。"我答了'二十二'，标准答案写的是'22'，被判定为错"——
这不是判分严格，这是**把答对的人判错**。而错的判定会直接污染学习者模型：
它会得出"这个知识点他不会"，然后据此调整教学。**污染源在题库这一层，在下游看不出来。**

- `answer` 保持**唯一的标准答案**（给人看时只该看到一个答案）；
- `accept` 是**判分时的全集**；
- 两者都不做同义替换（"22" 与 "二十二" 是两回事，必须显式声明）——
  自动同义替换需要语义判断，而这里是纯函数层，不该有判断。

**5. 判分是三态：`true` / `false` / `null`。**

`judgeAttempt` 在以下情形返回 `null`（判不了）：题目对象缺失、题库里没这道题、
作答为空、答案字段为空。**判不了就说判不了，不能默认算错。**

由此推出一条统计纪律：**正确率的分母只算判得了的题**，且 `unjudged` 单列报告。

- 把 `null` 算进分母 → 正确率凭空变低；
- 算进分子 → 虚高；
- 只报一个百分比而不报 `unjudged` → 人看不出"这份数据有多少靠不住"。

契约 §5.3 说工具质量是策略评估的天花板。**判分是工具，所以它的不确定性必须可见，
而不是被一个看起来很确定的数字盖住。**

**6. 目前没有任何"人不算数"的捷径：统计必须按 `source` 分组。**

`correct: true` 且 `source: 'llm'` **不是学习证据**。汇总函数默认按来源分组报告，
而不是把所有作答混成一个正确率——否则"模型答对了"会被算成"我会了"。
（ADR-017 决定 6 与本条是一件事的两面：字段在写入端，纪律在读取端。）

**7. 本阶段暴露给模型的是"接口工具"，不是"抽取工具"。**

交付两个工具：

| 工具 | 作用 |
|---|---|
| `add_questions_to_bank` | 把**已结构化**的题目写进题库（校验 + 派生 id + 落盘 + 记事件） |
| `record_attempt` | 记录一次作答（判分 + 记事件） |

**为什么不给"从 PDF 抽题"的工具**：那需要 OCR 与版式解析，是独立工程，
且它是判断不是接口。给了会诱导模型去用它、然后拿到一堆质量不明的东西
（契约 §1.1：内核拥有语法，插件拥有判断；抽取是判断）。
**先把"题目进来以后怎么用"打通，再解决"题目怎么进来"。** 这与 ADR-017 决定 7 一致。

## 依赖的前提

1. `events.jsonl` 的规模在可预见期内不需要索引。**若单次读取超过约 200 ms**，需要改的是加缓存，不是改事实源。
2. 题库文件名由模型给（`bank_name`），必须做文件名安全化（复用 `safeFileSegment`）。
3. 工具入参 schema 必须落在宿主支持的关键字内（`type/oneOf/properties/required/additionalProperties/items/enum/const` + `description`/`title`）——
   这是实测的宿主约束，不是风格选择。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| 作答只进 `events.jsonl` | 单次读取明显变慢（> 200 ms）→ 那时加**派生缓存**，而不是改事实源；若有人绕过缓存写第二个文件，本条已被违反 |
| 题库落工作区、事件留指针 | 题库与事件对不上（文件被手改但事件没更新）→ 需要 `validateBank` 前置校验，或引入题库自身的版本号 |
| 同名覆盖 + `supersedes` | 出现"想同时保留两版题库做对比"的需求 → 那种需求应当用**不同题库名**表达，而不是靠文件名带时间戳 |
| 加 `accept` | `accept` 长期为空且正确率异常低 → 说明抽取时没在做多解识别，判分在系统性冤枉人 |
| 判分三态 | `null` 长期占大多数 → 判分这一环没做，**要补，不能改成默认 false** |
| 按 `source` 分组 | 出现把 llm 作答混入学习者正确率的报表 → 该报表错了，而不是模型答得好 |
| 只给接口工具不给抽取工具 | schema 稳定后长期没有真实题目 → 抽取成了瓶颈，应立即转向（同 ADR-017） |

## 未做的事

- 题目抽取（OCR / 版式解析 / 图表题）：未实现。
- 知识点体系、判分的 LLM 兜底（主观题）、间隔重复调度：均未实现。
- 题库的"跨资料去重"（同一题出现在两份资料里）：id 规则已让它**可被发现**（题干指纹相同、出处不同），
  但没有实现合并或提示。
