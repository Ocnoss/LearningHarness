# ADR-012：LH 事件日志的物理形态与信封起步字段

- **背景**：`ADR-011` 决定 2 要求 LH 自持事件信封、内核机制采用宿主。事件日志是 LH 的第一块自有地基——分类器、学习者模型、策略评估全部投影在它之上。因此它的物理形态与信封字段需要在第一次落代码前定下来。
- **前置事实（决定了这件事没有选择余地）**：宿主的会话日志词汇表对外部插件**事实上封闭**。`Session.append` 构造事件时只保留 `sourceEventSeqs` / `surfaceOp`，**丢弃 `ignorable`**；持久化写入的是事件对象本身（`dsh-session-persistence/lib/index.js:326`）；重载时 `assertEventsSupported` 拒绝"未知类型且 `ignorable !== true`"的事件（同文件 `:1119`）。后果是外部插件写自定义事件类型会让该会话**下次重载时拒绝加载**。因此"往宿主日志里写 LH 事件"不是偏好问题，是不可行。

## 决定

**1. 物理形态：工作区下的 JSONL 文件，append-only。**
- 落点 `D:\LearningHarnessv0.1\data\events.jsonl`，一行一条事件。
- 选它而不是数据库：契约要求"上游炸了带着契约和数据迁走"（§8.2），文件是最直接的形式；且用户应当能用记事本打开自己的学习史——这对"可争议断言"是前提条件，不是便利。
- **失效信号**：若需要频繁按条件查询（如"某知识点近 30 天的事件"）而每次都要全量扫描，说明文件形态撑不住，应换 SQLite 或类似索引。

**2. 信封：起步只落能填满的字段。**
- 契约 §2.2 的信封有 9 个字段。本次落：`id` / `timestamp` / `schema_version` / `actor` / `type` / `provenance` / `scope` / `data`。
- `session_ref` / `content_ref` **显式写 `null` 而非省略**：读取端必须能区分"没有"与"没记"——这与 §1.3"写细读粗"一致。
- `content_ref`（大内容外置）暂不实现，因为现在还没有大内容。
- **失效信号**：若后续出现"空着关键字段且无法回填"的事件，说明字段留少了，需要一次 additive 补字段（契约允许加字段，不允许改语义）。

**3. `scope` 起步取常量 `'root'`。**
- 契约 §2.1 的课程树尚未存在，因此所有事件暂时都属于根作用域。
- **失效信号**：一旦要做课程拆分/合并，`scope` 需要被赋予真实节点路径 → 说明该字段承载的东西比现在多。届时按契约"事件不动、只改树元数据"处理（§2.1 事件不动纪律）。

**4. 调试痕迹与 LH 事件严格分开。**
- 插件的开发期日志写 `plugins/<name>/trace.log`，**绝不写进 LH 事件日志**。
- 理由：日志是唯一事实源。调试噪声一旦进去，投影与重放都要额外过滤，且违背"内核连什么值得记都不知道"（§1.4）——能不能进日志本身就是一个判断，而判断属于记录器插件，不属于脚手架。

## 依赖的前提

1. 用户接受"学习史以本地文本文件形式存在"。这同时是隐私选择：数据不出机器。
2. 宿主继续提供 `sessionProjections`，使 LH 的统计能投影到界面而不必自造 UI 链路。
3. 事件量在个人学习尺度内（数十万条以内），文件形态的读取成本可接受。

## 怎么知道它错了

| 决定 | 失效信号 |
|---|---|
| JSONL 文件形态 | 出现"必须建索引才能用"的查询需求；或单文件超过数十 MB 导致打开/追加明显变慢 |
| 信封字段择取 | 出现空着关键字段且无法回填的事件；或某字段在写入端从未被消费（说明留多了） |
| `scope='root'` | 课程树出现后需要回改历史事件的 scope（说明起步定义太窄） |
| 调试与事件分离 | `trace.log` 里出现了本该是事件的内容（说明判断标准没落到插件里） |
| 投影接线 | 界面读不到 `lhEvents`，或宿主投影机制在版本升级中变更 |

## 未验证事项

- 尚未在真实会话中验证 `lh-event-store` 的写入与投影（组合已可加载，逻辑已离线自测通过）。
- "文件形态在小规模下够用"这一条只有推理，没有实测数据；应在事件量上来后重新评估。
