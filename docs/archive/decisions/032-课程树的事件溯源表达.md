# ADR-032：课程树用**事件溯源**表达——树 = `lh/course/*` 事件的投影

- 日期：2026-09-21
- 状态：已采纳（**离线自测 32 项通过、闸门全绿；待一次真会话验证**）
- 相关：ADR-011（宿主采用 dsh）、ADR-012（宿主会话词汇表封闭）、
  `LH内核契约-v0.1.md §1.2/§2.1/§2.2`（一切状态是日志的投影、事件不动纪律、信封 `scope`）、
  ARCHITECTURE §0.1 约束 1（自定义事件类型会让会话重载失败）、ADR-033（断言器按树传递）

---

## 背景

本次要做「递归课程树 + 断言沿树向上传递」。断言要"传给父课程的断言器"，
就必须先有一个**稳定的课程树**，且每个节点有**稳定坐标**（断言事件的 `scope` 要指向它）。

课程树会长大、会重组：改名、把一个子课程挪到另一个父下、拆分/合并。
问题是：**这棵树存在哪儿、以什么形态存？**

## 关键事实（查证过的，不是推断）

1. 契约 §1.2：**一切状态是日志的投影**；§2.1「事件不动纪律」明写：
   *课程拆分/合并只改树的元数据，事件永远留在被写入的节点*。
2. 契约 §2.2 的信封有 `scope` 字段（"节点路径 / 课程树作用域"），
   **此前 LH 只填过 `session/<id>`（recorder-trace），`scope` 的课程语义一直是空的**——本次是第一次真正填它。
3. ARCHITECTURE §0.1 约束 1（ADR-012 实证）：**宿主会话日志的词汇表对外部插件封闭**，
   写自定义事件类型会让会话重载失败。所以课程事件只能进 **LH 自己的** `data/events.jsonl`（`@lh/event-store`）。
4. `@lh/event-store/store.js` 的 `readEvents()` / `LhEventStore.append()` 已验证可用，
   且 `append()` **返回写入的事件对象（含 `id` 与 `timestamp`）**——这让"派生事件指向源事件 id"成为可能。

## 决定

### 1. 课程树 = `lh/course/*` 事件的重放结果（事件溯源），不是一个可变的 `courses.json`

树的全部形态由四类事件投影而来（`tree.js` 的 `COURSE_EVENT_TYPES`）：

| 事件 | data | 语义 |
|---|---|---|
| `lh/course/created` | `{ node_id, parent_id\|null, title, level, asserter }` | 建节点 |
| `lh/course/renamed` | `{ node_id, title }` | 改名（后到覆盖先到） |
| `lh/course/reparented` | `{ node_id, parent_id\|null }` | 换父（**带防环**） |
| `lh/course/session-bound` | `{ node_id, session_id }` | 把会话绑到节点（每会话取最新） |

重组课程（改名/换父）是**追加一条新事件**，历史不丢、可回放；
"某时刻树长什么样"可由事件时间戳重建，不需要额外快照。

### 2. `tree.js` 是课程树的**唯一投影实现**（同 `store.js` / `model.js` 的纪律）

`buildTree(events)` 是纯函数：**输入事件数组，输出树**，不碰文件/环境/宿主。
断言器（按它向上传递）、界面（按它递归渲染）、工具（按它解析"用户说的是哪门课"）
**三处都 `import { buildTree } from '@lh/course-tree/tree'`**，不各推一套。
输出全用普通对象/数组（不用 Map/Set），以便直接 JSON 序列化发给界面路由。

### 3. `scope` 升级为课程节点路径 `course/<node_id>`（additive，不动冻结信封）

`scopeOf(nodeId)` = `course/<node_id>`，与 recorder-trace 现用的 `session/<id>` 同形状（前缀区分种类），
可反解（`nodeIdOfScope`）。节点 id 用短 uuid（`course-<8位>`）而非标题派生——
标题会重复、会改，而 id 是断言传递的坐标，必须稳定唯一。
**这是 additive 的**：只是开始填一个此前为空的字段，不改信封结构、不影响旧事件。

## 当时有哪些别的选择 / 为什么排除

| 别的选择 | 为什么排除 |
|---|---|
| **一个可变的 `courses.json`**（直接读写文件） | 违反契约 §1.2「状态是日志的投影」；重组会**丢历史**；断言无法"换断言器重放即翻新"；并发写要自己处理锁 |
| **记进宿主会话日志** | 约束 1（ADR-012 实证）：自定义事件类型会让**会话重载失败**。课程事件只能进 LH 自己的日志 |
| **什么都不做**（不做课程树，断言直接挂 `session/<id>`） | 断言就失去"课程归属"这个坐标，**无法按层级向上传递**——而那正是本次需求的核心。会话是平的，树才有"父" |

## 依赖什么前提 / 假设（前提塌了要重审）

1. **事件日志 append-only 且可完整重放**（`@lh/event-store` 已验证）。若日志会被截断/压缩，投影就不完整。
2. **`buildTree` 每次全量重放的成本可接受**：课程节点是"人手建"的量级（几百个内），
   全量重放是毫秒级。**这是本决策最可能先塌的前提**（见失效信号）。
3. **`scope` 字段是 additive 的**：信封已冻结但 `scope` 此前未填课程语义，现在填不破坏旧事件。

## 怎么知道它错了（可观察信号，不是"感觉不对"）

| 失效信号 | 说明 / 处置 |
|---|---|
| **每次触发都 `readEvents()`+`buildTree()` 变慢**（事件涨到几万条） | 全量重放的前提塌了 → 需要投影缓存/快照（按 `surface.replaceGeneration` 之类锚点失效），像 recorder-trace 的 presetCache 那样 |
| **出现"同一课程两种树形"** | `tree.js` 不再是唯一实现，有人另推了一套 → 回到决定 2，把逻辑收拢 |
| **`reparent` 后 `level` 计算异常/疑似死循环** | 防环（`isDescendant` + `guard<1000`）失效 → 查 `tree.js` L158-168 |
| **`scope` 反解歧义**（`course/` 前缀与别的 scope 种类撞） | 决定 3 的前缀约定不够 → 需要更严格的 scope 命名空间 |

## 验证（本次真做过，不是推算）

| 步骤 | 结果 |
|---|---|
| `node plugins/lh-course-tree/selftest.mjs`（离线，合成事件喂 `buildTree`） | **32 通过 / 0 失败**：三级树投影/层级/链、session-bound 取最新、`resolveCourseRef`（id/标题/歧义/查不到）、renamed、reparent 防环、孤儿当根、幂等、scope 往返 |
| `node scripts/check-all.mjs`（`DSH_HOME` 指向 repo `.dsh`） | 24 项：**23 绿 + 1 应然红（check-restart）+ 0 不该红**；含 check-plugin-contract / check-plugin-imports / check-preset-mount / check-installed-copies |
| 真实事件日志污染检查 | `data/events.jsonl` 240 行，其中 `lh/course/*`、`lh/assertion/*` **0 条**——离线自测未写真实学习史（约束 9 的教训） |

**证据位置**：
- `plugins/lh-course-tree/tree.js`：`COURSE_EVENT_TYPES`（L29-34）、`scopeOf`/`nodeIdOfScope`（L63-71）、
  `buildTree`（L90-149）、`isDescendant` 防环（L158-168）、`levelOf`（L176-186）、`resolveCourseRef`（L246-261）。
- `plugins/lh-course-tree/index.js`：三个工具 `create_course`/`list_courses`/`enter_course`（`enter_course` 靠 `exec.agent.session.id`）。
- 挂载：`.dsh/.agent-presets/lh/agent.cordis.yml` L132-139（普通行，**不 provide root-realm 服务**，故不需 isolate realm）。

## 没做的（如实记下）

- **投影缓存/快照没做**：当前每次触发全量重放。节点量级小时是对的（少一处会漂移的缓存失效逻辑）；
  量级大了再做，触发信号见上表。
- **课程的删除/归档语义没定**：只有 created/renamed/reparented/session-bound，没有 `deleted`。
  事件溯源下"删除"应是追加一条 tombstone，但当前需求没用到，留空。
- **多工作区**：树是单工作区（单个 `data/events.jsonl`）的投影；跨工作区未决（同 ARCHITECTURE §5）。
