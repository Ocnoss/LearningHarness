# ADR-009：内核资源记录设计五条

- **背景**：内核需承载资源记录；"多个老师批判性讨论一个学生"要求记录系统支持"关于记录的记录"。
- **决定**：
  1. 资源与事件分离：事件 = 时间流中的一次性行为；资源 = 可寻址可复用的产物；插件产出动作记事件、产物记资源，互相引用。
  2. 信封与内容分离：内核只定义信封（id / type / created_by / derived_from / supersedes / created_at / payload），payload 由类型自定，内核不解释。
  3. 只追加不可变：更新 = 新资源 + supersedes 指针，旧版本永不覆盖。
  4. 注解是一等资源：批判、补充、反驳均为 payload 带 target 指针的独立资源，学情 = 原始证据 + 多插件多时间的注解树。
  5. derived_from 为列表：血缘是 DAG，支持跨阶段、跨方法的成果流动；类型由内核注册表登记，未知类型拒绝写入。
- **理由**：血缘可审计（评估插件质量依赖旧版本留存）；注解树兑现"多评估器并存可批判"的承诺；类型注册表防生态腐烂。
- **放弃**：可修改的记录（破坏审计性）；内核理解 payload（内核腐化的开端）；现在就设计具体 payload（违反分层，归插件）。
- **推迟**：存储介质与索引实现（MVP 用文件系统 + JSON 索引，存储对插件不可见）。
- **状态**：已冻结（2026-09）
