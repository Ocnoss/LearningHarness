# Learning Harness 架构宪章

> 唯一事实源。任何讨论的结论必须写回本文档或 decisions/ 下的 ADR，否则视为未发生。
> 已定项默认不重议，除非有新证据（不是新想法）。
> 分层法律：第 N 层未书面冻结前，禁止讨论第 N+1 层。
> **产品法律（第四条，ADR-011）：任何时刻，必须存在一条用户可感知的完整闭环在运行。允许被冻结的层次，只能是这条闭环已经走过的层次。**
> 推论：文档不得先于闭环扩张。当"再想清楚一点"与"让最小闭环跑通"冲突时，后者优先。

**一处必须知道的数据现状（2026-09-19 实测，不是设计）**：工作区那份 49 题的题库
（`考公刷题-片段阅读与逻辑判断.json`）是**两份资料合并**的
（`2025年花生片段阅读600题-题本【上】.pdf` 20 题 + `逻辑判断600题题本篇.pdf` 29 题），
**两份的题号都从 `set1-q1` 开始**，所以 `source.number` 只在资料内唯一、**跨资料会撞车**。
另有三个具体缺陷（都还没修，别当它们是好的）：
1. 它**从未经过 `import_questions`**，所以事件流里没有它的 `lh/resource/questions-imported`；
2. 它的 provenance 指向 `@lh/extractor` —— **这个插件不存在**（是脚本直接落盘时写下的）；
3. 它的 `topics` 只有 **13/49** 道有值（试点产物缺文件出处，只能保守匹配，见 ADR-021 结论八）。

**已确认的宿主约束（写在这里省得重查）**：
1. 宿主会话日志的词汇表对外部插件**封闭**——写自定义事件类型会让会话重载失败（实证，见 ADR-012）。故 LH 事件自持。
2. 客户端插件需要**服务端半**作为入口行；`exports` 必须暴露 `"./package.json"`，否则客户端半静默不被发现。
3. 服务端插件改动**必须重启 dsh**（web profile 关了服务端 HMR，上游注释说其生命周期未测试；**我实测打开它并给源码根也无效**）。客户端 bundle 改动只需浏览器刷新。
4. **specifier 解析有三处不同路径**（preset 行 / profile 行 / 直接 node），同一写法在不同位置结果不同——见 ADR-014 的对照表。
5. preset 是 **agent 作用域**：够不着 host 面发布的服务（共享逻辑用直接 import），但**能拿到 `ctx.llm` / `ctx.systemPrompt` / `ctx.tools` / `ctx.sessions`**（实测）。
6. **preset 行未激活会让该 preset 的所有会话都不可用**（不只是插件不工作）——加行是高风险的编辑动作。
7. 宿主自己的**政策类上下文**形态可照抄：`dsh-sandbox-policy`（order 110）、`dsh-user-approval`（order 115），
   用 `ctx.inject(['systemPrompt'], s => s.systemPrompt.context({ name, order, text: (ctx) => string }))`。
8. 工具执行上下文里能拿到 `exec.agent.session.header.cwd`（工作区根）与 `exec.agent.session.id`，
   **但拿不到当前会话事件的 `seq`**——所以工具侧记的坐标只能到会话级，`context.seq` 只能是 `null`。
   不编造它：坐标错比坐标缺更糟（同 `lh-recorder-trace` 的判断）。
9. 环境变量（`LH_EVENT_LOG` / `LH_CONTENT_DIR`）必须**惰性求值**。写成模块级常量会在 import 时固化，
   于是任何"把它指到别处"的调用方都被静默忽略——**实测后果是离线测试把假数据写进了真实学习史**。
10. **"打字以外的输入方式"有现成通道**：宿主提供 `ctx.userQuestions`
    （`@deepseek-ai/dsh-user-questions`，UI 支撑的服务），`ask({questions})` 的每项支持
    `options: [{ label, description }]`、`multiSelect`、`detail`，以及**开放的呈现意图标签** `intent.kind`
    （未知标签由 UI 退回通用选项列表，**编码不变 → 将来做专用界面不需要改协议**）。
    **未验证**：它由宿主面（`dsh-web-app`）提供，而 preset 是 agent 作用域——能否被 preset 插件注入尚未实测。
    所以 ADR-019 决定不把它作为循环成立的前提（题的线格式已带 `label`，加不加点击都不返工）。
11. **客户端插件的 `inject` 必须导出在模块里**（`exports.inject = ['slots', …]`，**服务名**数组）。
    `package.json` 的 `dsh.client.inject`（**包名**数组）只进 boot manifest，
    宿主当前版本**不拿它装配 fiber 的 inject**。漏了会在**浏览器启动屏**报
    `cannot get property "slots" without inject`（实测，见 ADR-023 与 `PLUGIN_CONTRACT.md §2.1`）。
12. **list 型插槽注册必须给 `options.id`**（该插槽内唯一），否则浏览器启动时报
    `list slot "<名>" requires options.id`（实测）。推荐用 `ctx.slots.inject(key, cb)` 包一层——
    它等到插槽声明存在再注册。清单见 `PLUGIN_CONTRACT.md §2.3`。
13. **pnpm 对 `file:` 目录依赖是「拷贝快照」，不是软链；且目录名由包名派生。**
    两处形态**必须分开记**（2026-09-18 更正，此前这里写的是"工作区根那边是软链、改源码立即生效"，
    那句话**是错的**，而且错得贵——它让"改了没生效"失去了怀疑对象）：

    | 位置 | 形态 | 改源码后 |
    |---|---|---|
    | 仓库根 `node_modules/@lh/x` | **workspace 软链** → `plugins/lh-x`（需 `pnpm-workspace.yaml` + `workspace:*`） | 立即生效 |
    | profile `node_modules/@lh/x` | **真实目录，拷贝**（`nodeLinker: hoisted`） | **不动，必须同步** |

    因此：包内**不能用相对路径引用别的插件**（`../lh-xxx/…` 会解析成不存在的 `@lh/lh-xxx/`），
    必须包名 + `file:` 依赖声明。
    查：`scripts/check-installed-copies.mjs`；修：`scripts/sync-lh-deps.mjs`。
    **不要用 `pnpm install` 同步**：规格没变它认为"已是最新"直接跳过。
14. **dev profile 不是"克隆"**：它由 `scripts/dev-watch.mjs` 生成、用绝对 `file://` 指向**同一份源码**。
    所以它能提供"便宜的重启"，但**拦不住"源码坏了"**——那不是隔离（ADR-023 决定 3）。
15. **profile 插件的 `apply()` 抛错会让整棵插件树加载失败、dsh 起不来**；
    而学习者面对加载失败的界面时，**看不到"该改哪一行"**。
    所以**装载期不许抛错**：配置缺失改成"用的时候拒绝"（503 / 工具报错 + 修法）。
    代价是**拆掉了一个警报器**（"apply 抛不抛错"曾经间接暴露配置问题），
    所以另设 `scripts/check-paths-resolution.mjs` 直接问路径解析（ADR-025）。
16. **profile 副本的上方没有 LH 仓库**，所以"从模块位置往上找仓库根"在生产里必然失败。
    运行时需要的路径由**安装期配置** `lh-install.json` 给出（仓库根一份 + 每个 profile 一份），
    解析顺序：环境变量 → `lh-install.json` → `lh-workspace` 包标记（ADR-025）。


## 1. 理念层（已冻结）

- 服务对象：初高中之外的广大自学者，目标高度异构（备考 / 技能掌握 / 自我提升）。
- 核心判断：学习者的异构性（目的、资料、方法、节奏）是问题域的本体，因此**教学策略本身必须可插拔**——这是采用 Harness 架构的根本原因。
- 产品差异化不在工具，而在**编排与约束**：什么时机注入什么信息、允许/禁止模型做什么、记忆怎么沉淀。

## 2. 架构层（已冻结）

### 2.1 总原则：一切皆插件

内核只负责机制，不含任何教学判断与领域逻辑。判断和解释全部归插件。

### 2.2 内核构成（三条腿 + 机制）

```
内核 = 资源存储 + 事件存储 + 协议 + 执行机制
```

- **资源存储**：所有上传学习资料的原始记录（只进不出）。
- **事件存储**：append-only 学习事件日志。记录三类事件：
  1. 用户对话；
  2. 用户做题/学习行为；
  3. **系统行为**（哪个插件在何时被调用、产出了什么、钩子拦截了什么）。
- **协议**：事件钩子点 + 资源/事件格式 + 工具接口 + Claim 接口。（协议是资源和事件成立的前提，不是独立待定项。）
- **执行机制**：Turn/Step 循环 + 上下文组装器。机制归内核，挂在机制钩子上的判断归插件。

### 2.3 事实与解释的切分（本架构的第一刀）

| 事实（内核，不可插拔） | 解释（插件，可竞争） |
|---|---|
| 原始资料 | 资料摘要、提炼、整理 |
| 学习行为事件 | 学情分析、掌握度判断 |
| 插件调用记录 | 插件质量评估 |

**派生资源血缘规则**：插件产出必须回流为带血缘标注的资源/事件
（`derived_from: 资源ID, by: 插件ID, version`），一切解释可回溯到原始事实。

### 2.4 关键架构组件

- **Bundle**：教学策略资产 = 插件组合 + 系统提示词 patch（如：备考冲刺 / 技能掌握 / 深度自学）。
- **Context Layer**：每次模型请求前的统一上下文组装点，承担**教学法的强制执行**（钩子 > 提示词愿望）。
- **学习者模型**：插件化，多个评估器可并存，允许不一致（分歧 = 证据不足的信号）。

## 3. 接口层（部分冻结）

### 3.1 已冻结：Claim 接口

```
query(topic) → Claim {
    estimate:    掌握度（刻度由插件定义）
    confidence:  置信度
    evidence:    [证据ID列表]   # 强制，可回溯到内核事件
    timestamp
}
```

- 低证据时必须返回低置信，禁止强行给出估计。
- 学习者/教练可人工覆写，覆写本身记入事件日志。

### 3.2 插件化成熟度分层

| 层级 | 内容 | 难度 |
|---|---|---|
| L1 文本级 | 提示词、bundle、skill、资料总结器 | 低（markdown/配置） |
| L2 代码级 | 工具、学情分析器、测评器 | 中（注册表 + 契约） |
| L3 元级 | 插件的开发本身插件化 | 高（冻结为愿景；L1 阶段先做"skill 作者插件"） |

## 5. 开放问题清单（上限 10 条，新窗口只允许从此取题）

> **不阻塞规则（ADR-011 产品法律的直接推论）**：清单中的任何问题都**不得**成为动工的前提。遇到未决问题时，选择最幼稚的可用答案继续推进，并把答案记为"临时"，同时把该问题保留在清单里。允许被冻结的答案，只能是闭环已经走过的答案。
> 因此："临时答案"是合法状态，且优于"未决"。

1. 测评工具（出题/诊断）的证据格式——仪器质量是全部评估插件的天花板
2. Claim 置信度的更新协议（多次证据如何结算）
3. 跨会话调度器接口（间隔重复、复习时机）
4. 记忆文件的写入权限（哪些工具/插件可以写学习者模型）
5. **（ADR-011 新增）开发工作流的认知负担**：如何保证单次工作单位不需要同时持有多个未决问题；人只做判断，AI 承担跨文件记忆与翻译。见 `WORKFLOW.md`。
6. **（2026-09-19 新增）界面来的作答缺会话坐标**：`lh/user/attempt` 的 `session_ref` 与 `context.seq` 都是 `null`——HTTP 路由没有会话上下文（约束 8）。
   后果：日志里有"谁、何时、答了哪道题、对错如何"，但**没有**"这次作答属于哪场对话"，卡片与作答只能靠时间 + 题库 + 题号粗关联。
   **临时答案（合法状态）**：显式留空，不编坐标。要修得让界面把会话身份带进请求，或宿主提供"当前活动会话"服务——**尚未实测**。
7. **（2026-09-19 新增）知识点词表的扩张纪律**：两轴词表已落地（ADR-021 结论七），但"加词"的判据与流程还没定。
   已知约束：新词必须**在真实题目里出现过**（`unmapped_topics` 就是它的来源清单）；
   同一个意思只留一个规范名。**谁有权加词、加了之后历史断言怎么处理**，未决。
8. **（2026-09-21 新增，ADR-033 决定 4）断言器注册表的服务化**：当前注册表是 `lh-asserter` 内置的一张 `Map`（首条是虚拟断言器）。因为 preset 是 agent 作用域，往 root realm 发布「断言器注册表」服务需要带 `isolate` 的组，**未实测、风险高**。
   **临时答案（合法状态）**：内置 Map。升级信号：出现第二个**需跨插件动态注册**的断言器；届时须先实测 isolate realm 组能否在 preset 发布服务。
9. **（2026-09-21 新增，ADR-032）多工作区下的课程树与断言**：课程树是**单工作区**（单个 `data/events.jsonl`）的投影，`scope=course/<node_id>` 的 node_id 只在本工作区唯一。同一学习者的多份工作史如何组织课程树/断言，未决。
   **临时答案（合法状态）**：只做单工作区（`lh-install.json` 给出工作区根，ADR-025）；多工作区等真需求出现再定。
10. **（2026-09-21 新增，ADR-032/034）课程 UI 侧的断言缺会话坐标**：与第 6 条**同一根因**（约束 8：HTTP 路由无会话上下文）。`lh-course-ui` 浮层只能靠 HTTP 读事件，拿不到「当前活动会话」，故「哪条断言属于这场对话」靠 `lh/course/session-bound` + 时间关联，与 practice 现状一致。
   **临时答案（合法状态）**：不编坐标，用 session-bound + 时间关联。要修得让界面把会话身份带进请求，或宿主提供「当前活动会话」服务（同第 6 条，**尚未实测**）。
