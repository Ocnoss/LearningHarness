# 题库管理 · 完备性检查（2026-10-14）

- **被检查对象**：`@lh/question-bank`（1 个包，11 个工具）+ `@lh/question-bank-ui`（管理面板，8 条路由 / 3 个槽位）
- **检查时的状态**：`a36194e`，工作区干净，闸门 **34 绿 / 1 应然红 / 0 不该红**
- **结论**：**面板本身是完备的**（下面 A 类全绿）；**不完备的部分分四类**——环境生效（1、2）、有意不做（3–7）、建议未批准（8、9）、无真数据走过（12）。**第 12 类最值得处理**，因为它让"看起来支持"和"确实支持"之间存在差距。

## A. 已完成且已验证（不是"写完了"，是"有自测有闸门"）

| 能力 | 证据 |
|---|---|
| 四段读法 + 题库清单 | `GET /health /banks /source /questions /attempts`；路由自测 266 条 × 4 份实现 |
| 只读纪律 | 读路径**不写盘**（有断言）；未知参数一律 400 并列出可用值 |
| 归档 / 恢复 | `renameSync` 落盘，拒绝覆盖，**不写事件**（有意：机械动作不是事实） |
| 作答备注 | `POST /note` + `lh/resource/note-made`；只追加，编辑 = 新备注 + `supersedes`；空正文拒绝 |
| 判分口径 | 三态 `correct`（冻结）+ **派生四态判决**（正确/部分正确/错误/无法判别）；部分正确不进正确率分子分母 |
| 不混算 | 默认只看「用户」；作答者**多选**（可按型号分别看，含"选中所有模型"）；模型答对不算"我会了"（ADR-018 决定 6） |
| 作答者列 | 显示**型号**（未记录型号时如实显示「模型（未记录型号）」） |
| 正确答案列 | 一律**字符型**（选择 A、填空 42、将来简答整段文字） |
| 表格与分页 | 题目段 / 做题记录都是 **5 / 10 / 20**、默认 5；筛选、展开、窄屏省略号四件套 |
| 备注入口 | 最右窄列（✎ / ＋）→ **行内展开**读写；`author` 区分用户与模型 |
| 视觉纪律 | 颜色只出现在圆点/条/边框，文字一律 label 令牌；只用主题令牌 |
| 断言器/口径只有一处 | 判决与部分正确的唯一实现在 `@lh/question-bank/attempt.js`，视图层只转发 |

**真实数据体检**（2026-10-14）：2 个题库 / 88 题（第1册 39 题、片段阅读与判断 49 题）；事件 1239 条；作答 = 用户 21 条（20 对上号 + 1 孤儿）+ `deepseek-v4.1-flash` 39 条；判决 = 用户正确 11 / 错误 9，模型正确 31 / 错误 8。
知识点覆盖：第1册 **39/39**、片段阅读与判断 **13/49**（后者有大量词表外标签）。

## B. 不完备项

### 第 1 类：环境生效（代码没问题，是"还没生效"）

| # | 事项 | 现状 | 怎么算完 |
|---|---|---|---|
| 1 | 面板在 app 里可见 | 首次生效**需要重启 dsh**（`check-restart` 是唯一应然红） | 重启后打开面板 |
| 2 | **11 个题库工具在 app 里调不到** | LH preset 未装 bundle（T2 未完成）。**面板不受影响**，但"会话里让模型做题""写备注"这两条路在 app 里是断的 | 装 bundle 并重启 |

### 第 2 类：设计上**有意**不做（不是欠债，是决定）

| # | 事项 | 决定与理由 |
|---|---|---|
| 3 | 归档/恢复**没有事件坐标** | 归档是机械动作、不写事件（ADR-035/037）。代价：事后在事实源里查不到"谁在什么时候归档了哪个库" |
| 4 | 同题检测 | 作者 2026-10-14 决定**不做**：已发现的重复来自"对同一题库抽了两次"，是开发期产物 |
| 5 | 题目级备注（跨多次作答累积） | 字段留了位置（`target_kind: 'question'`），**界面不做**（作者定"先只做作答级"） |
| 6 | 部分正确**不进**正确率 | 有意（"答对一半不能默认算错"）。失效信号写在 ADR-038：若要按分数算掌握度，得回来改口径 |
| 7 | 用户称呼 | 占位符「用户」+ `lh.user.name` 本地偏好已就位；"开始时问称呼"的功能未做 |

### 第 3 类：我提过、**未经批准**（不算欠债，等你定）

| # | 建议 | 价值 |
|---|---|---|
| 8 | 错题闭环视图（错题 → 重做 → 是否清掉） | 现状只能看到"最近错误"，看不到"这道题我修好了没有" |
| 9 | 知识点掌握度表 | 现在只有"知识点覆盖 13/49"这种**覆盖度**，没有**掌握度**（做过几道、正确率、最近错误） |

### 第 4 类：**没有真数据走过**的界面分支（最值得处理）

| 分支 | 真数据现状 |
|---|---|
| 无法判别（`correct: null`） | **0 条** |
| 部分正确（分数 6/12） | **0 条** |
| 复合题（大题多小题） | **0 道**（88/88 都是单选） |
| 一题多次作答 | 只有 1 道题 4 次，其余最多 1–2 次 |
| 跨天分布 | 作答只集中在 2026-09-17 ~ 09-22（5 天），距今天已约 3 周空档 |

**这意味着**：那三类分支只有单测覆盖，**真数据从未走过**——"看起来支持"和"确实支持"之间有差距。
**这正是「模型作答」和「构造样本」能补的空白**（构造样本 = 不调模型、按画像造，可复现地走一遍这些分支）。

### 第 5 类：未在真机验证

| # | 事项 | 说明 |
|---|---|---|
| 10 | 面板观感 | 无头环境看不到：9 列表格在窄屏、备注行内展开的观感、作答者浮层的滚动条（**滚动条本身无法定制**——宿主禁止注入 `<style>`，只能控制容器高度） |
| 11 | 真题库规模 | 只接过自建 2 库（39 / 49 题）。几百上千题时的分页、筛选、选择器都没验证过（这也是「模型作答」选题设计的输入） |

## C. 一句话总结

**面板作为"如实展示事实源 + 少量机械动作"是完备的、有纪律的、被闸门守住。**
真正欠的三块是：**① 生效（重启 + preset bundle）、② 真数据没走过的三类分支、③ 两个未经批准的视图建议（错题闭环、知识点掌握度）**。
其中 ② 与「模型作答」的目标重叠——**先让模型作答把这三类分支走通，比再写新界面更值**。
