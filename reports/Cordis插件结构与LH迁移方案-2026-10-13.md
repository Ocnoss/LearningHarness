## 0. 一句话

**不是你的插件和 Cordis / dsh 不兼容，而是你日常用的那个 app 换了 preset 机制，而仓库里的开发器还在跑旧版 dsh。**
两套机制并存，于是出现"闸门全绿、app 却缺功能"。

---

## 1. 决定性事实：本机有两个 dsh，用的是两套 preset 机制

| | 你日常用的窗口 | 仓库的开发器（`node scripts/lh-dev.mjs`） |
|---|---|---|
| 实现 | Electron app.asar：`@deepseek-ai/dsh-desktop-runtime` **0.2.0-rc.2** | npm 全局：`@deepseek-ai/dsh` **0.1.1-rc.2** |
| preset 机制 | **declaration row**（`dsh-agent-preset` + `dsh-agent-preset-registry`） | **目录扫描**（`dsh-agent-presets` 读 `.agent-presets/<id>/`） |
| 读 `.agent-presets/lh/`？ | **不读** | **读** |
| 证据（实测） | asar 里有 `dsh-agent-preset`、无 `dsh-agent-presets` | npm 里有 `dsh-agent-presets`、无 `dsh-agent-preset` |

`scripts/lh-dev.mjs` 的 `resolveDsh()` 解析的是 `@deepseek-ai/dsh`（npm 全局那个）——
所以**仓库的自检、`check-preset-mount`、`compare-homes` 验的是旧机制**，而 app 跑的是新机制。
这正是"改了没生效"的第五层：**不只是家不对、profile 不对，连 dsh 的版本都不是同一个。**

## 2. Cordis 插件结构（只讲 LH 用到的那部分）

### 2.1 一个插件 = 一个模块

服务端插件导出一条两种形态之一（**不要混用**）：

- `export function apply(ctx, config) {}`，可选 `export const inject = ['tools']`、`export const Config = ...`
- **默认导出**一个 Service 类（`class X extends Service`），宿主用 `ctx.plugin(X)` 装载

规则：**一切注册动作都放在 `apply` 里，用 `ctx.effect` / `ctx.on` 做，并返回清理函数。**
声明了 `Config` 的行，`config` 会在激活时被校验。

LH 的插件全是第一种形态；`@lh/event-store` 额外用 `ctx.plugin(...)` 挂了一个子插件（`lhEvents`）。

### 2.2 Loader 的一行（entry）

组合文件就是**一组 entry**。每行的字段：

| 字段 | 含义 |
|---|---|
| `id` | 行的稳定标识（patch 用 `id` 定向覆盖；`preset-<id>` 是惯例） |
| `name` | 插件包名（或 `cordis:group` / `cordis:include`；插入的相对路径锚在 patch 文件旁） |
| `config` | 传给 `apply(ctx, config)` 的配置；**id 定向覆盖会整体替换它，不深合并** |
| `disabled` | bool / null / `!!js` 表达式；被禁用的行省略必需 config |
| `inject` | 行级额外注入 |
| `isolate` | 服务名 → `true` 或 realm 标签：给该插件（及其消费者）**新开一个服务实例** |
| `group: true` | 该行的 `config` 是一段**嵌套 entry 列表** |

### 2.3 作用域与 service（决定 pending 的那一层）

- **host / process 面**：提供共享服务——`tools`、`sessions`、`llm`、`systemPrompt`、`sessionProjections`、`subagents`、`webServer`、`jobs`、`settings`……
- **preset / agent 面**：插件向这些注册表**贡献**工具、prompt 段落、策略、persona；**够不着 `webServer`**。
- **`inject` 是门禁**：声明了、但提供者不在同一层 → 该行 fiber 停在 **pending（界面写「等待依赖」）**，
  `apply` 永不执行、**能力静默消失、不报错**。这就是 §5 要盯的东西。
- **`isolate` 是实例**：谁 provide 服务，谁和它的消费者就得在同一个 realm；
  host 面的进程单例服务（如 `subagents`）**必须**留在 host 面。

LH 的对应：界面插件 inject `webServer` → 只能在 host 面；能力插件 inject `tools`/`llm`/`sessions`/`systemPrompt`/`subagents` → 在 preset 面。

### 2.4 组合层与 bundle

一个 profile 是**有序的 patch 层**叠出来的：

`每个 bundle 的 patch → profile 的 cordis.patch.yml → $DSH_HOME/cordis.patch.yml → --patch`

- patch 条目：`- insert: [rows]` 追加行；`- id: X` + 无 insert 定向覆盖已有行。
- **bundle** = 一个包，`package.json` 里有 `dsh: { bundle: { patch: "./cordis.patch.yml" } }`。
- 安装方式：`plugin_manager` 的 `install_bundle`（它自己跑 pnpm 与 bundle 选择，**不要用 shell 复现**）。
- **随 dsh 发行的包从安装目录解析；profile 装的 bundle 从 profile 解析**。
  → LH 的包不是随 dsh 发行的，所以 **LH bundle 必须在自己的 `dependencies` 里声明它们**。

### 2.5 preset = 一条 declaration row

preset 不再是目录，而是**一条普通 entry**：

```yaml
- insert:
    - id: preset-lh
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: lh              # 必填，小写字母数字连字符
        name: LH 学习模式     # 可选，选择器里显示
        description: ...     # 可选
        order: 10            # 可选，roster 位置
        plugins: [ ... ]     # 必填，一段嵌套 entry 列表
```

语义：**定义被急切加载一次、被选它的 Agent 共享**；改定义只影响**之后新建**的会话；
**声明激活失败会让该行带着诊断留在 roster 上，且任何会话都无法用它**。
`@deepseek-ai/dsh-agent-preset` 的实现只有 30 行：inject `agentPresets`，把 config 交给 `ctx.agentPresets.register`。

### 2.6 客户端半

- 包在 `package.json` 里声明 `dsh.client`（`platform`、`inject`、可选 `immediately`、`external`），并导出 `exports["./client"]`。
- 宿主扫**已启用的 Loader entry**，找到这些包，把 `client.js` 呈到 `/plugins/<pkg>/client.js` 并注入 boot 图。
- 因此：**没有 host 行 → 客户端半不会被投放**（包装在 node_modules 里也没用）。
- LH 的界面包（theme / practice / course-ui / workspace-ui / schedule-ui）都正确声明了 `dsh.client` 与 `./client`，**格式与模板一致**。

### 2.7 生命周期（fiber 状态）

`pending` / `loading` / `active` / `failed` / `unloading` / `null`。
`list_plugins` 报每行的 `enabled` 与 `fiberPhase`；`set_plugin`/`set_bundle` 报 `overridden`（更高优先层赢）。
装新 bundle 可能通过 HMR 生效；**替换已装包要重启才能载入新的 JS 模块代**。

## 3. LH 的 13 个插件怎么映射

| 平面 | 插件 | 为什么 |
|---|---|---|
| **host 面**（profile/bundle 行） | `theme` `practice` `course-ui`(disabled) `workspace-ui` `schedule-ui` | inject `webServer`，preset 面够不着；且客户端半靠 host 行投放 |
| **preset 面**（declaration 的 `plugins`） | `event-store` `recorder-trace` `resource-indexer` `model-tier` `question-bank` `course-tree` `asserter`(disabled) `schedule` | 向 `tools`/`systemPrompt` 贡献；只该属于 LH 会话 |

⚠ 现在 `course-tree` 与 `schedule` 是**被放在 host 面**（因为 preset 死了）——
迁移时必须把它们从 host 行里**删掉**，否则同一插件被注册两次、`tools.register` 撞名。

## 4. 兼容性结论：不是代码不兼容，是部署方式被移除

### 4.1 合格的部分（实测）

- LH 插件是标准 Cordis 形态（`apply` + `inject`），manifest 合法（`type: module` + `exports`）。
- 界面包的 `dsh.client` 声明与 `exports["./client"]` 与官方模板同形；当前 `dsh-client-modules` 解析的正是 `exports["./client"]`，**根目录的 `client.js` 完全 OK**。
- **4 个已挂到 host 面的插件在 0.2.0-rc.2 上确实活着**：`create_course` 等 5 个工具、`create_schedule` 等 4 个工具、`lh:course`/`lh:agenda` 上下文都在。
  → 它们用到的 `ctx.tools.register` / `systemPrompt.context` / `webServer.register` 在新版**仍然可用**。

### 4.2 不合格的部分

| 问题 | 性质 | 处置 |
|---|---|---|
| 挂载点（`.agent-presets/lh/`）在新版不再被读 | **部署**，不是代码 | 做 bundle + declaration（§6） |
| `question-bank`、`model-tier` 带着**硬** `inject: ['systemPrompt']` | 代码脆弱性 | 照 `course-tree`/`schedule` 的改法改成 `ctx.inject(['systemPrompt'], ...)` 可选；否则哪一层拿不到就整行 pending |
| `question-bank` 的 `inject: ['subagents']` | 待判 | `subagents` 是 **host 面**的进程单例（`dsh-subagent` 在 dsh-base 提供），preset 面能拿到；web patch 的 HMR 对照实验还没结论 |
| 5 个插件（question-bank / resource-indexer / recorder-trace / model-tier / asserter）**最后一次运行是 2026-09-22** | **未在新版上验证** | 迁移后必须在**新会话**做一次冒烟：工具出现、事件能写 |
| 缺 `meta.title/description`、`icon` | 体验 | 可选，缺了会退回包名/描述 |

### 4.3 顺带发现的两处旧账（与 LH 无关但会误导）

- desktop 的 `cordis.patch.yml` 里 `llm-deepseek` 行**名字不匹配**（`@deepseek-ai/dsh-llm-deepseek-api-key` ≠ 期望的 `@deepseek-ai/dsh-llm-deepseek`）→ **该行被跳过**；
  `ui-chat`、`ui-settings-account` 两行 **entry 不存在** → 也被跳过。
- 仓库的 `lh-dev.mjs` 解析到旧版 CLI——**要么升级全局 dsh，要么别再用它当"app 的等价物"**。

## 5. 走正路之后会是什么状态

装好一个 LH bundle（同时含 host 行与 `preset-lh` 声明）之后：

1. **设置 → 插件**里出现这个 bundle；`list_plugins` 里出现 `preset-lh` 行，`fiberPhase: active`（失败则带诊断）。
2. **"LH 学习模式"重新出现在 agent preset 选择器里**（名字/描述/顺序取自 declaration）。
3. **新建会话选 LH 模式**，拿到 20 个 LH 工具（题库 10 + 课程 5 + 日程 4 + 索引 1）与 4 个上下文
   （`lh:course` `lh:agenda` `lh:model-tiers` `lh:practice-routing`）。
4. `lh/trace/observed` 记录恢复；`import_questions` / `record_attempt` / `start_practice` 回来。
5. 界面面板不变（仍在 host 面，所有会话可见）。
6. 必须**同时**做的两件事：
   - 删掉 host 面重复的 `lh-course-tree` / `lh-schedule` 行（否则撞名）；
   - 验证通过后删掉 `.agent-presets/lh/`（它已经不生效）。
7. 代价与注意：
   - **安装需要 Full access 或审批**；本会话审批被关掉、且没有 `plugin_manager` 工具 → **这一步得你来触发**。
   - **已存在的会话保持它启动时的插件代**；必须在**新会话**里验。
   - 非 LH 会话将**不再**看到课程/日程工具（现在能看到只是因为它们挂在 host 面）——这是 scope 的取舍。

## 6. 迁移步骤（草案，尚未落盘）

一个 bundle 目录（例如 `D:/LearningHarnessv0.1/bundle/`），**两个文件**：

```json
{
  "name": "@lh/bundle",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "dependencies": {
    "@lh/event-store": "file:../plugins/lh-event-store",
    "@lh/recorder-trace": "file:../plugins/lh-recorder-trace",
    "@lh/resource-indexer": "file:../plugins/lh-resource-indexer",
    "@lh/model-tier": "file:../plugins/lh-model-tier",
    "@lh/question-bank": "file:../plugins/lh-question-bank",
    "@lh/course-tree": "file:../plugins/lh-course-tree",
    "@lh/asserter": "file:../plugins/lh-asserter",
    "@lh/schedule": "file:../plugins/lh-schedule",
    "@lh/theme": "file:../plugins/lh-theme",
    "@lh/practice": "file:../plugins/lh-practice",
    "@lh/course-ui": "file:../plugins/lh-course-ui",
    "@lh/workspace-ui": "file:../plugins/lh-workspace-ui",
    "@lh/schedule-ui": "file:../plugins/lh-schedule-ui"
  }
}
```

`cordis.patch.yml` 两段：host 行（界面 5 个）+ `preset-lh` 声明（基础能力 8 行 + LH 能力 8 行，
其中 `lh-asserter` 保持 `disabled: true`；`tool-bash`/`tool-pwsh` 用 `!!js` 按平台二选一）。

顺序：**先改硬 inject → 再建 bundle → 装 → 新会话冒烟 → 删 host 重复行 → 删旧目录**。
（包名要逐条核，宿主文档警告：preset 写完之后被改过名的包**会在激活时失败**。）

## 7. 什么时候可以开始正式的学习任务

**门槛只有一个：题库工具在新会话里可见。**

| 能力 | 现在（app 里） | 迁移完成后 |
|---|---|---|
| 建课程 / 绑会话 / 看课程树 | ✅ | ✅ |
| 日程 / 待办 / 验收期倒计时 | ✅ | ✅ |
| **出题 → 作答 → 判分 → 解析 → 错题统计** | ❌ 题库工具 0/10 | ✅ |
| 资料索引 | ❌ | ✅ |
| 轨迹记录（`lh/trace/observed`） | ❌（9-22 起停） | ✅ |
| 模型档位上下文 `lh:model-tiers` | ❌ | ✅ |
| L3 断言 / 学习者建模 | ❌（且作者要求暂缓） | 仍然 `disabled`（开它 = 绑课即花 token） |

**内容侧已就绪**（实测工作区 `D:/learning Harness test/lh-questions/`）：
`考公刷题-片段阅读-第1册.json`（39 题）+ `考公刷题-片段阅读与逻辑判断.json`（49 题），
共 **88 题**，题干/选项/答案/解析/知识点都在。**不缺内容，只缺那一个挂载点。**

所以：**迁移一完成、且新会话里 `start_practice`/`import_questions` 等工具可见，就可以开始正式的刷题学习。**
在那之前你可以做的是**计划与结构**（课程树、日程、验收期），这些现在就能用。

### 迁移后的冒烟清单（5 条）

1. 新会话选「LH 学习模式」→ 工具目录里有 20 个 LH 工具。
2. `list_question_banks` 能看到那 2 个题库。
3. `start_practice` 出一次题 → `submit_answer` 判分 → `get_solution` 拿解析。
4. `list_schedule` 能读到今天的日程与验收期倒计时。
5. 事件日志新增一条 `lh/user/attempt` 与 `lh/trace/observed`（证明写盘链路通）。
