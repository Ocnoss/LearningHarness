## 0. 结论

**你的怀疑方向对，但归因错了一格——而跑完闸门之后，这一格变得更清楚了。**

先把最要紧的更正说在前面：**闸门是真的，而且全绿。** 24 项（11 道闸门 + 13 个自测）里
23 绿、1 项"应然红"、0 项不该红。宿主级硬约束**确实被机制化了**，且做得比多数项目好：
`check-plugin-imports` 真去 import **profile 里的生产副本**；`check-profile-apply` 用记账式假 ctx 真跑一遍 `apply()`；
`check-installed-copies` 逐文件 sha256 比对源码与副本；`check-client-slot-timing` 先用故意写坏的 bundle 自证判据可靠。
这不是"把判断写成散文"，这是工程。

所以真正的问题收窄成一句：**有机制的那一层（宿主硬约束）是健康的；没有机制的那一层（治理、协作、决策记录）
恰好是失败半径为零的那一层，而它占了全部反复阅读成本。**

具体是三件事：

1. **治理层完全没有机制，只有散文。** 仓库无 `README.md`、无 `AGENTS.md`、无 `SKILL.md`；
   `agent.cordis.yml` 是 159 行注释 + 插件行，**没有一行行为提示词**；全仓只有两段真正进上下文的规则文本，
   且都写死在插件 JS 里（`lh:model-tiers` order 116、`lh:practice-routing` order 117）。
   项目自己早已写下正确诊断（`.workbuddy/memory/MEMORY.md:13-15`）："行为规则目前**没有任何机制在管**……
   必须把它放到'每次组装都会出现的位置'"。**诊断在，动作没做。**
2. **这些散文里很大一部分不是你的决定，是上一代模型写的。** `MEMORY.md:10-12` 自己写着：
   文档"性质上是 **agent 对作者决定的断言**，必然含偏差，且作者没有时间逐一核对"。
   **你现在是被自己的 agent 写下的规矩约束着**，而新模型又被要求把那些规矩当前提。
3. **文档描述的系统比代码大一个数量级，并且被标成"已冻结/宪法"。** 契约 358 行里的四元组×三轴、
   策略-预测-回顾、L0–L4 抽象梯子、handoff、导师模型，在 1,035 条真实事件里对应 **0 条**。
   ADR-011 已经诊断过"规则保证了'未完成'是一个稳定状态"——然后同一份文档又写了一条
   "不许为内核机制写设计文档"的配额令。诊断是对的，药方是错的：问题不是文档多，
   是**文档描述的东西不跑**，而它仍然是新模型唯一的读物。

## 2. 真正在限制发挥的五件事（按动手优先级）

### 2.1 治理层没有机制，于是"生效的只有代价最高的那部分"

- **该生效的不生效**：6 处活文档引用指向不存在的 `docs/PLUGIN_CONTRACT.md`；
  工具数在三个地方分别是 9 / 12 / 10；两份 debloat 决议互相矛盾
  （一份要"CM 并入 WORKFLOW 并删原文件"，另一份要"三份并存重写"），后者执行、前者成废纸；
  `MEMORY.md` 写"在 workbuddy 里只做功能与思路交流，不做代码开发"，
  而记录这条的记忆目录本身就在记录同一会话里建插件、改配置。
- **不该生效的生效了**：新模型要重建上下文得先读约 12,000 行 `.md`（83 个文件）；
  读得越全，留给真正工作的预算越少。

**建议**：唯一入口一份 `AGENTS.md`（≤100 行），其余降级为按需查阅。

### 2.2 大量约定是上一代模型的散文，被当成作者的决定继承

`MEMORY.md:10-12` 与 `COLLABORATOR_MODEL.md` 的 11 条断言、`pre-debloat` 版 `COLLABORATOR_MODEL.md`
的 18 条 `§E` 行为准则（"改文本文件只用 edit、绝不用 shell"这类），都是这条路径的产物，
却以"约定"身份出现在后续每个模型面前。

**建议**：把"你亲口说过的"与"模型的解释"物理分开。`MEMORY.md:19-26` 的七条偏好
（如实反馈含坏消息、选项要带后果与推荐、破坏性操作白名单、把选择权交给用户、先想组合再想退避、
文档直接写、短指令含顺序）——那才是你的决定，进 `AGENTS.md`；其余标"agent 推断，可推翻"。

### 2.3 把"对你这个人的模型"喂给模型，会变成自我实现的预言

`COLLABORATOR_MODEL.md` 里三条最危险的：A1"不写代码"、A3"对 agent 编排的了解停留在原理层"、
A8"认知带宽是真实约束"。任何读到这三条的模型，理性反应都是**少讲深、少挑战、替你决定**；
而 A8 同一段又写"也不用完全把我保护起来"——文档自带矛盾，模型只能猜，猜错的代价你承担。

**建议**：A1/A3 删除或改写为可执行要求（"实践层必须给足：改哪个文件、跑什么命令、看到什么算成功"）；
A8 的矛盾显式裁决一次。**这份文件不该作为对模型的输入存在。**

### 2.4 "已冻结 / 只做加法 / 架构宪法"锁住的是还没建的东西

契约自称"架构宪法"、"冻结优先级最高"；信封规定"改语义、删字段不行"；34 份 ADR 标"已冻结"。

**而现实已经和契约不一致**（实测事件）：
- `actor` 实际取 `agent` 与 **`human`**（契约写 user / agent / system / 插件）；
- `scope` 实际三种形态：`root`、`session/session-<uuid>`、`course/course-<id>`（契约写"节点路径"）；
- `derived_from`/`supersedes` 落在 `data` 里（`store.js` 自己注释"信封是冻结的，所以塞进 data"）。

**冻结没挡住漂移，只是让漂移不被看见**，同时给想改进的人加了一道文书税。
注意 `ADR-025` 自己有一条极好的反治理判断——"**总是被绕过的闸门比没有闸门更坏**"——用在冻结上同样成立。

**建议**：把"冻结"降级为"**有数据在里面的接口才冻结**"。当前单用户、v0.x、1,035 条事件、无外部消费者：
允许破坏性变更，只要求"一处变更 + 一个迁移脚本 + 读端双读"。

### 2.5 文档描述的系统比代码大一个数量级，而它是新模型唯一的读物

这不是"还没做完"，这是"**读它的人会去做那件事**"。
**建议**：契约每节加"状态：已跑 / 未跑"；未跑的部分移进 `docs/vision/`，开头写明"这是愿景，不是约束"。

## 4. 不该动的（防止矫正过度）

- **`apply()` 绝不抛错**（ADR-025）、**哨兵必须在进程之外**（ADR-023）、**客户端 `apply()` 不许抛错**（ADR-022）、
  **旁路观测绝不冒泡进宿主事件管线**（ADR-034）。失败半径都是"产品完全不可用"，项目踩过四次"dsh 起不来"。
- **用接口形状防误用，而不是在提示词里请求模型自觉**（ADR-019/031/033）。这是**反**压制的做法，
  应该继续用，并且用到 §3 那六处去。
- **ADR-026 的决定 5/6**：`ignored` 如实回报、"描述从实现生成"。
  同一份文档还写着"**让自由档安全，就不需要在自由度和安全之间选**"——全仓最好的设计立场。
- **ADR-016**：建议而非要求、不设硬拒绝、不隐藏工具、中间件绝不弹框。
- **ADR-029**："交叉验证必须逐条列出，不能合成一个分数盖过去"——保护模型独立判断不被指标抹平。
- 数据完整性：append-only、原子写、读端容忍 BOM、判分红线（LLM 答案绝不进判分路径）、
  不往宿主会话日志写自定义类型、破坏性操作白名单。
- 宿主对接：跨插件用包名 + `file:` 依赖、`files` 清单、`sync-lh-deps`、多加载位置答案一致
  （这一组是本次唯一跑过的、且全绿的那组机制）。

## 5. 工具链自己的三处硬伤（已实测确认，好修）

### 5.1 有一道闸门是"假绿"：它在验另一个家的、且落后两个插件的 preset ★


实测两份并不相同（`Compare-Object` 差 10 行，sha256 不同）：

| | 家目录那份（闸门验的） | 仓库那份（`lh-dev.mjs` 真正加载的） |
|---|---|---|
| 最后修改 | 2026-09-20 01:57 | 2026-09-21 15:43 |

   **提供的保证是假的**。这正是 `PLUGIN_CONTRACT.md` §八 自己写下的那句话的实例：
   "**闸门指着错的目录比闸门红更糟**——它会让人去修一个没坏的东西。"
   （`selftest-preset-mount.mjs:35` 的 `REAL_PRESET` 同样指向家目录那份。）

修法：`PRESET` 改走 `scripts/lib/dsh-home.mjs`（该文件已经是其它 5 道闸门共用的家在哪儿判据），
