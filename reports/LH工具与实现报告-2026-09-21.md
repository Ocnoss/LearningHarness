# LH 现有工具全景报告 —— 功能、实现方法、实现细节与原文件索引

- 日期：2026-09-21
- 证据基线：本报告全部结论来自对 `plugins/` 下 10 个插件源码的通读（含每个 `index.js`、全部支撑模块、两端 UI 的 client.js 文件头），并交叉核对了 `docs/ARCHITECTURE.md` §0.1、`docs/PLUGIN_CONTRACT.md`、各插件 `package.json` 的 `lh` 自描述字段与 `ctx.tools.register` 的实际注册点。
- 口径说明：本报告所称"工具"取最广口径 —— ①模型可调用工具（`ctx.tools.register`，共 **12 个**）；②非工具能力（事件存储内核服务、HTTP 路由、客户端插槽组件、后台记录器/断言引擎、模型档位调用器）。两类都覆盖，并逐条指向原文件。

## 一、架构背景（读工具细节前必须知道的五件事）

1. **一切皆插件，内核由宿主 dsh 提供**（ADR-001/011）。LH 不再自研内核，只产出 Cordis 插件；"内核拥有语法，插件拥有判断"（ADR-002）。
2. **两级装载作用域**：`loads_at: preset` 的插件跑在 agent 作用域（可访问 `ctx.tools` / `sessions` / `llm` / `systemPrompt`，**够不着** `webServer` 等 host 面服务）；`loads_at: profile` 的插件跑在 host 作用域（可注册 HTTP 路由）。这解释了一个表面矛盾：同样是"给界面取数"，question-bank 走工具、practice/course-ui 走路由。
3. **事件溯源**：LH 状态不存数据库，全部是 `data/events.jsonl`（append-only JSONL）的投影。题库=资源记录、作答=事件、课程树=`lh/course/*` 事件的投影、断言=`lh/assertion/made` 的链。宿主会话日志词汇表对外部插件封闭，所以 LH 事件必须自持（ADR-011/012）。
4. **坐标不抄内容**（ADR-014）：记录器只把宿主会话事件索引进 LH 日志为 `(sessionId, seq)` 坐标，原文取回靠 `trace-reader.js`。
5. **每种错都有固定形状**（PLUGIN_CONTRACT §2）：①dsh 起不来（apply 抛错 / 相对导入断链）；②preset 会话全废（工具 schema 含动态正则）；③浏览器启动屏（客户端不导出 `exports.inject` / 直接 register 未声明插槽）；④功能静默缺失（宿主扫描器不递归子目录、缺 `exports` 子路径）。四种失败都被写成闸门脚本（§八）。

### 贯穿性纪律（多个工具共有，写一次即可，后文只标出处）

| 纪律 | 内容 | 出处 |
|---|---|---|
| apply() 绝不抛错 | 装载期不校验配置；配置缺失表达成"用的时候 503 + fix + why" | 契约 §五之二；`lh-practice/index.js` L106-141、`lh-course-ui/index.js` L21-23 |
| 环境变量惰性求值 | `process.env.*` 只在调用点读，不写模块级常量 | `lh-asserter/index.js` L295-296；`store.js` eventLogPath() |
| 跨包引用 = 包名 + `file:` 依赖 | 相对路径只在源码目录成立，装进 node_modules 即 ERR_MODULE_NOT_FOUND → 整棵插件树加载失败 | `lh-practice/index.js` L35-58 血泪注释；契约 §3 |
| 原子写 | tmp + rename | `bank.js` saveBank、`signal.js` |
| BOM 容忍读 | 首字符 `0xFEFF` 剥除 | `store.js` readEvents、`index.js` readQuestionSource |
| 如实回报、不静默 | 无法识别的值收进 `ignored` / `unmapped_topics` 返回给调用方纠错，不静默丢、不抛 | `start_practice`、`import_questions`、`get_questions` |
| 单处实现 | 判分只有 `submitAnswer`、树投影只有 `buildTree`、词表只有 `topics.js`（工具描述由 `describe*Vocabulary()` 渲染注入，杜绝手抄漂移） | `lh-practice`、`lh-course-ui`、`style.js` |
| 结构性防misuse | 答案只在判分后出现（`/bank` 与 `get_questions` 结构上无答案）；历史字段只在 submit 返回里 | ADR-019 决定 3；`buildPracticeView` |

## 三、lh-question-bank（`@lh/question-bank`，preset，8 工具，gates✅ live✅）

**插件体**：`inject=['tools','systemPrompt']`；除 8 个工具外还注入运行时上下文 `lh:practice-routing`（order 117）。文件：`plugins/lh-question-bank/index.js`（1676 行）+ 9 个支撑模块。

### 3.1 `import_questions(bank_name, file_path?|questions?, title?, source_root?, source_file?, provenance_model?)`

- **功能**：把一批题（内联数组或从文件读）归一化后合并进工作区题库 `lh-questions/<bank_name>.json`，并写 `lh/resource/questions-imported` 事件。
- **实现流程**（L573-712）：
  1. `readQuestionSource`：读文件、剥 BOM、接受三种形态（数组 / `{questions}` / `{题库名:[…]}`）；
  2. `normalizeQuestionList`：**逐题收集错误**（不 fail-fast），错题进 `errors[]`，未映射知识点聚合进 `unmapped_topics`；
  3. `mergeIntoBank`（bank.js）：同 id 覆盖、报 `added/replaced` 计数；已存在但非法的库**拒绝覆盖**；
  4. `saveBank`：tmp+rename 原子写；
  5. 事件：`supersedes` 链指向同 `bank_path` 的旧导入事件，content 记计数（含 `with_topics_count`）与 `unmapped_topics`。
- **细节**：工作区取自 `exec.agent.session.header.cwd`；`bank_name` 经 `safeBankName` 白名单校验；id 派生是确定性的（见 3.9 question.js），重复导入同一来源幂等。

### 3.2 `record_attempt(bank_name, question_id, response, source∈[human,llm,imported], duration_ms?)`（L713）

判分（`judgeAttempt`）→ 构造事件体（`buildAttempt`）→ 写 `lh/user/attempt`。`actor=source`；`context.seq=null` 是**故意的**（工具调用上下文里拿不到可靠宿主 seq，宁缺毋假坐标）。与 `submit_answer` 共享同一判分实现。

### 3.3 `list_question_banks()`（L851）

- 枚举工作区 `lh-questions/*.json`；**排除伴生文件**（`BANK_COMPANION_SUFFIXES`：`.option-notes` / `.extract-report` / `.preview` / `.预览`）；坏库不隐藏，以 `ok:false + errors` 如实列出。
- **输出 schema 血泪教训**：`source_root` / `generated_at` 必须声明为 `oneOf:[{type:'string'},{type:'null'}]` —— 真机上宿主以"值与 schema 不符"拒过含 null 的输出（契约 §1.3）。

### 3.4 `get_questions(bank_name, count?, order?, topic?, ids?, exclude_ids?)`（L915）

- 返回**不含答案**的题面（`toPresentableQuestion` 剥离 answer/analysis）。
- `topic` 经 `sanitizeSelection → canonicalTopic` 单一来源归一；不在词表时返回**明确提示**"不在词表里"而非静默空集。
- `requireBank` 精确匹配题库名，错误信息附可用清单 + 近似名 —— 设计立场："名称错误可恢复，选错题库不可恢复"。
- description 与 render 双通道引导"进入刷题请走 `start_practice`"。

### 3.5 `submit_answer(bank_name, question_id, response, source='human', duration_ms?)`（L1026）

- **功能**：`record_attempt` + `toRevealedQuestion` 合并为一步 —— 结构上不存在"先看答案再作答"和"作答不留下记录"的分支。
- **关键顺序**：`priorHistoryOf({events: readEvents(), questionId})` 必须在 `store.append` **之前**求值 —— 否则"上一次作答"就是刚提交的这一次（有专项测试把守）。
- 返回：`correct(true/false/null)`、`answer`、`accept`、`analysis`、`analysis_kind`（原文 / 原文（OCR 可能串行）/ 选项标注拼成 / 无 —— 解析出处的诚实分级）、`history_*` 字段（**只在此工具返回中出现**）。

### 3.6 `get_solution(bank_name, ids)`（L1188）

供"AI 深解"链路取"题面+答案+解析"。**只读、不写事件**（有测试）。曾经修过的 bug：内部调 `getQuestions` 忘传 `includeAnswer:true`，解析被剥离后**静默返回空**且不报错 —— 教训记录在函数注释里。

### 3.7 `get_practice_stats(bank_name)`（L1319）

`summarizeProgress`：覆盖率、正确率（**只统计 human+已判分**，llm/imported 分桶不混入）、`missed_recent`（错题本数据源）。判分数为 0 时正确率返回 null 而非 0。

### 3.8 `start_practice(bank_name?, count?, order?, topic?, ids?, style?)`（L1433）

- **不打开面板**：通过 lh-practice 注册的 toolview 渲染器在对话里放一张**可点击卡片**（由学习者点开，不自动弹 —— 迭代掉的两版设计记录在 client.js 文件头）。
- 实现：写信号文件 `requestPracticePanel`（seq++ 单调递增）；`sanitizeCardStyle` + `sanitizeSelection(args, ignoreKeys=['bank_name','count','style'])` → 返回 `style_applied/style_ignored/selection_applied/selection_ignored`；`ids` 给了但 `count` 没给 → `count=ids.length`；render 里带"卡片没出现时怎么办"的兜底话术。
- **上下文注入**（`context.js`）：`lh:practice-routing` 写"答→判→揭解析"的两条路径路由规则 —— 放 systemPrompt 而非工具 description，因为工具描述里的同类规则**实测被无视过两次**。

## 四、lh-course-tree（`@lh/course-tree`，preset，3 工具，gates⏳ live⏳）

### 4.1 `create_course(title, parent_course?)`（index.js L112）

父课程经 `resolveCourseRef` 解析（歧义 → 报错并建议改用 node_id）；`newNodeId='course-<uuid8>'`；写 `lh/course/created`（含 `node_id,parent_id,title,level,asserter:null`）；返回重建后的树路径。

### 4.2 `list_courses()`（L180）

### 4.3 `enter_course(course)`（L243）

### 4.4 `tree.js`（285 行）—— 全系统唯一树投影

- 纯函数、零依赖，重放 4 类事件：created / renamed / reparented（带 `isDescendant` 防环守卫）/ session-bound（latest-wins）；孤儿自动升为根；全部用普通对象（可 JSON 序列化）。
- API：`scopeOf(id)='course/<id>'`、`nodeIdOfScope`、`levelOf/parentOf/nodeChain/childrenOf`、`resolveNodeOfSession`、`resolveCourseRef`（id 精确 → title 精确 → 大小写不敏感；多命中返回 `{ambiguous}`）、`flattenTreeLines`。
- 断言器与课程界面都 import 它 —— **不允许第二处推树**（否则面板画的树与断言传递路径不一致，肉眼难查）。

## 五、lh-asserter（`@lh/asserter`，preset，无工具，gates⏳ live⏳）

**功能**：断言的产生与向上传递 —— 已绑定课程的学习会话里出现学习者输入时，按节点选断言器、真调模型产出断言、写 `lh/assertion/made`，并沿树递归上抛（`derived_from` 成链）。文件：`plugins/lh-asserter/index.js`（342 行）。

- **触发**：`ctx.on('session/event', …, {global:true})`（唯一不漏学习会话的订阅方式）；触发类型 `user/message`（仅真人：`source.kind` 判据，排除插件注入/续写的合成消息）与 `tool/result`（仅 `SUBMIT_TOOLS={submit_answer, record_attempt}`，避免每个工具结果都烧一次模型）。
- **三重护栏**：① `isLearningSession`（照抄 recorder-trace 的 `presetOfSession`：反扫最后一条 `agent-preset/selected`、退回 header —— header 创建即冻结不可靠；`surface.replaceGeneration` 作 WeakMap 缓存失效锚）；② 必须 `resolveNodeOfSession` 命中节点；③ `LH_ASSERTER=off` 惰性总开关。
- **异步旁路**：`void (async()=>{try/catch})()` —— 模型调用/写事件任何失败只 trace 到 `trace.log`，绝不冒泡进宿主事件管线（断言是旁路观测，坏了也不能弄坏会话）。
- **propagate 递归**（L200-287）：`selectAsserter`（节点声明 else 'virtual'，未知断言器静默回退不报错）→ `resolvePropagateTarget`（modes: `parent` / `node:{target:'root'|level|id}` / `stop`）→ `descriptor.assert({input,node,tree,target,evidence,llm,call:callModel})` → append 事件（`scope=节点`、`evidence=触发坐标`、`derived_from=[子断言id]`、`propagate_to`、`confidence`、`model`）→ 对目标再跑一次；`MAX_PROPAGATE_DEPTH=32` + `visited` 集合防环；断言器返回值里的 `propagate_to` 可**覆盖声明**。
- **asserters.js**（125 行）：注册表 + 传递路径解析（纯函数，可离线自测）。
- **asserters/virtual.js**（127 行）：测试期唯一断言器（ADR-034）。tier='flash'；让模型**原样复述**一句固定模板（「本次断言是在 {time}，位于第 N 级子课程「X」（路径：…），依据「…」做出的断言，传递给第 M 层断言器。」）；模型不可用时本地按同一模板 fallback（`confidence` 0.5/模型、0.2/fallback、`model:null` —— 审计一眼可辨）；`assert` 接受可替换 `call` 参数，离线自测不碰真模型。

## 六、lh-practice（`@lh/practice`，profile，UI 双半，gates✅ live✅）

### 6.1 服务端半（index.js 482 行）—— `/lh/practice` 前缀三条路由

`inject=['webServer']`；一次 prefix 注册 + 单 handler 分发（避免多 exact 路由撞名）。

| 路由 | 功能 | 实现细节 |
|---|---|---|
| `GET /pending` | 透传 `readPracticeSignal()`（seq/at/bank/count/style/selection） | **校验只发生在服务端**（style.js/practice.js），路由不重复校验 |
| `GET /bank?bank=&count=&order=&exclude_ids=&topic=&ids=` | 组界面题视图 | `buildPracticeView`：默认 order='unseen'（默认 sequential 曾致"点了没反应"的同题重复 bug）；给了 ids 就显式清空 exclude/order（"就做这几道"不容重排）；**只回题面不回答案**（ADR-019 决定 3：结构上不可能先见答案）；带 `number/source_path` 供"AI 深解"；附 `getPracticeStats`；工作区未配置 → **503 + fix[] + why**（装载期不抛） |
| `POST /attempt {bank,questionId,response,durationMs?}` | 人类作答判分 | **直接复用 `submitAnswer`** —— 判分口径全系统一处实现，界面只是另一个调用者；`source:'human'`、`sessionRef` 为 undefined（HTTP 无会话上下文，已知局限 = 开放问题 #6）；返回 correct/answer/accept/analysis/analysis_kind/history（只有这里有）/eventId/刷新后 stats |

工作区解析 `resolveWorkspace()`：只经 `@lh/event-store/paths` 的 `workspaceDir()`（配置唯一读口）；曾经硬编码作者自己的工作区默认值 → 在别人机器上表现为"题库是空的"的**静默错误**，现在没有配置就返回 null 转 503。多工作区不可用是记录在案的限制。

### 6.2 客户端半（client.js 2124 行，手工 bundle）

- 注册两个插槽：`tool.call.toolview`（keyed `#start_practice`）→ 对话入口卡片；`shell.overlay`（list）→ 面板本体（宿主文档明说浮层要注册这里，`root` 单值插槽会遮掉 AppFrame）。

- 面板/收起是**两个独立状态**：关闭=状态清空，最小化=收成胶囊、进度不丢（跨会话总在最前的窗口会挡对话）。
