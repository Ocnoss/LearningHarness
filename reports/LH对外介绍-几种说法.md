# Learning Harness 对外介绍（几种说法）

> 用途：跟别人聊这个项目时，按对象和场合挑一个用。
> 一条总原则：**先讲他能感觉到的痛，再讲你做了什么。不要从架构讲起。**
>
> **先说清楚三层关系**（后面所有版本都建立在这上面）：
> **目的** = 因材施教（关注你是谁：你想学什么、你手头有什么、你是什么样的人）
> **手段** = 记住你（跨周、跨课程、可追溯）
> **仪器** = 可反驳的证据（不然你无法知道"材"是不是真的看清了）
>
> 记忆不是主题，记忆是入场券——**不了解你，就无从因材施教。**

---

## 十秒版

> 现在的学习产品问的是"我有什么资料、我有什么老师、我怎么给你排课"；
> Learning Harness 问的是"**你想学什么、你手头有什么、你是什么样的人**"。

## 十秒版（备选，更具体）

> 一个记得你学了几个月、并且你可以当面反驳它的 AI 家教——
> 它关心的不是它有什么资料，是你是什么样的人。

---

## 三十秒版（可以直接念出来）

> 你在用 AI 学东西吧？有没有这种感觉：学的时候挺顺，过一个月回头看，说不清自己到底进步在哪；
> 换个话题再聊，它完全不记得你卡在哪儿、更不记得它上次是不是讲错过。
>
> 问题不在它讲得不好。问题是现在这些产品问的都是"**我有什么资料、我有什么老师、我怎么给你排课**"——
> 全是供给方的视角。它不知道你是什么样的人，所以只能对所有人说同样的话。
>
> 我想反过来问：你想学什么、你手头有什么、你是什么样的人。
> 而要做到这一点，它得先记住你——不是记住最近几十条消息，是记住几个月。
> 而且它对你说的话，你得能反驳，因为"我不服，我不是这样"本身也是最值钱的学习证据。

---

## 一段话版（写给看得下去、会追问的人）

> 现在所有的 AI 学习产品，入口都是同一个问题："我有什么资料、我有什么老师、我怎么帮你排课程和计划。"
> 这是供给方的视角——于是它对你说的每一句话，都是对一群人说的。
>
> Learning Harness 反过来问三个问题：**你想学什么、你手头有什么、你是什么样的人。**
> 这三个问题里，最难的是第三个。要回答它，系统得先记住你——不是记住最近几十条对话，
> 是记住跨周、跨课程、几个月的过程；而且每条结论都得能追回到具体哪一次、哪一道题。
> 它还必须是**能被反驳**的：不给"掌握度 72%"这种假精确，给的是
> "我认为你在 X 上薄弱，依据是这几件事，置信度中"——你可以说它错了。
> 这种反驳不会被记成顶嘴，会被记成证据。
>
> 再往上一层是我们真正想撬的东西：**学习不该只有对话这一种形态。**
> 对话是 LLM 时代的默认，但一个会做事的 agent 可以提供别的形态——
> 它去翻你三个月前那份资料、它给你安排一次诊断性的小测、它把你的教材和你的错题对上。
> 这些东西不在对话里发生，但它们才是"因材施教"真正的样子。
>
> 顺带还有一件：教学方法本身是可以替换的数据，懂教学但不懂编程的人也能改，不用改代码。

## 「供给视角 → 学习者视角」这张对照表（最值得单独讲）

| 现在所有学习产品的问法 | Learning Harness 的问法 |
|---|---|
| 我有什么资料 | 你手头有什么资料 |
| 我有什么老师 / 我讲得对不对 | 你想要什么 / 你卡在哪 |
| 我如何编排课程和学习计划 | 你是什么样的人，该用什么方式教 |
| 你学会了吗，模考拿了多少分 | 什么证据能证明你真的学会了 |

**这张表本身就是整个项目的说明书。** 左边任何一行，你都能找到现成产品；
右边每一行，都必须先解决"它是怎么知道这些的"——而那正是记忆机制要做的事。

---

## 从「LLM 学习」到「Agent 学习」

| | LLM 学习 | Agent 学习 |
|---|---|---|
| 形态 | 你问，它答 | 它有身份、有记忆、有工具、有跨时间的连续性 |
| 学习的载体 | 对话 | 对话只是其中一种交互 |
| 上下文 | 一段会话 | 几个月的过程 |
| 它能做的事 | 解释、出题、总结 | 去翻你的资料、安排一次诊断、把教材和错题对上 |

一句话：**"超越对话的形式"不是要取消对话，是不让对话成为唯一形态。**

而且这件事你已经做过一次了——**C22 那次事故的本质就是这个**：
agent 把题目念在对话里，你要的是一张卡片。把刷题从"对话内容"变成"界面入口"，
就是一次实实在在的"超越对话"。这条可以当例证用，因为它不是设想，是做过的。

## 两个延伸场景

### 场景 A：资源匮乏地区的孩子（一台 AI 学习设备 + Learning Harness）

**为什么这个场景在逻辑上是对的**（不是煽情）：匮乏地区最缺的从来不是题，是**有人了解你、盯着你、对你有期待**。
一个班六十个人，老师没有条件因人而异。而"一个记得你三个月、并且你随时可以反驳它的私人教师"，
恰好是那里最缺的东西——而且 LH 的定位（非编程专业、自学者、目标高度异构）本来就是这批人。

**它给出的一条硬设计约束**（这才是它真正的价值）：
> 如果做出来的东西只有会用命令行的人能用，那它就不是为匮乏地区做的。

**它顺便回答了你一个悬而未决的问题**：ADR-030 里"LH 会话带 shell"那条风险，
当时写的是*"给学习者会话一个 shell 在别处是否可接受是一个产品决策——本 ADR 记的是
'在这一步上选了要'，不是'这件事永远对'"*。**场景 A 就是这个"别处"。** 答案看起来是分层：
作者/开发者那一层可以有 shell，学习者那一层不能有。

**不要对外承诺的部分**（内部清单，说出去会翻车）：

| 难点 | 实情 |
|---|---|
| 硬件与网络 | 现在跑在 dsh 上：要装 Node、要配模型凭据、要能打开终端。离"一台设备开箱即用"很远 |
| 谁付 token 钱 | **开源解决的是"谁能改"，不解决"谁付得起电费和推理费"。** 持续几个月的私人教师是持续成本 |
| 终端形态 | 目标人群手里是手机，不是电脑。壳级前端你已推迟（ADR-013），移动端是另一个量级 |
| 首次可用性 | 留守儿童旁边没有家长辅导"怎么配置"。要求必须一次打开就会用，这反过来会决定一大批设计 |

**可以说的**：这是我们做设计的尺子——**凡是需要用户先学会用命令行才能用的设计，就不算完成。**

### 场景 B：作为模型后训练的框架（大模型教小模型）

**这个映射不是比喻，是结构对应。** 把"学生"换成"小模型"，你现有的东西几乎不用改语义：

| Learning Harness 里已有的 | 后训练里对应什么 |
|---|---|
| 事件流记录"它实际做了什么" | 训练/推理过程的行为日志 |
| 四元组的**证据阶梯** | 从"能不能做对"到"是不是真会"的分级评估 |
| **spontaneity 轴**（被提示 vs 自发） | **蒸馏有没有变成真能力**——需要提示才做对 ≠ 学会了 |
| **depth 轴**（recall / restructure / transfer） | 泛化的层级：会复述 vs 会迁移 |
| 策略作为**人可编辑的数据** | 评估标准（rubric）本身就是数据，不是硬编码的 loss |
| 策略评估 = 假设检验（动作携带预测） | 训练干预携带预期结果，用后续行为流对账 |
| 断言带出处、可重放 | 抗 benchmark 污染、抗 reward hacking 的评估协议 |

**最有意思的一条**：你契约里那个"理解假象"的检测——
*"消费行为激增而生成行为停滞 → harness 显式警示"*——
在后训练语境里就是**"分数上去了但能力没上去"**，而你现在就有判别它的维度。

**价值落点要说准**：它不在"训练算法"这一侧（那里的话语权在算力和数据，框架不是瓶颈），
而在**环境与评估协议**这一侧——而这一侧恰好正在变成稀缺品。
一句话：**"把训练循环的评估锚在一份带出处的行为日志上，且评估标准是人可编辑的数据。"**

**必须处理的问题**（不解决就不能说成立）：

| 问题 | 实情 |
|---|---|
| **spontaneity 对模型定义不清** | 模型的每次输出都是被 prompt 驱动的，"自发"需要重新定义——可行的做法是 hint-conditioned（有/无提示两组），这也正是 agentic 评估在用的 |
| **机制无头，实现全是给人用的** | 契约层没有把"学习者是人"写死（§1.4 内核无知、§4.2 分域建模、四元组测的是生成性行为——模型也是生成器）；但今天的实现（工具注册表、插槽、Web 面板、题库）一个都用不上。**这是缺口，也是好消息：护城河在机制，实现是可换的** |

**两个场景其实是同一件事**：它们能同时成立，恰恰因为这套机制里**没有把"学习者是人"写死**。
这是它相对其他 AI 教育产品的结构性差异，而且是可验证的——
去看代码和契约里有没有"学生必须是人"的硬假设。

## 对方追问"具体怎么实现"时的三层展开

从外往内，一层一层给，不要一次全倒出来：

1. **它记得你。** 跨周、跨课程；每条结论都能追回到具体哪一次对话、哪一道题。
2. **它对你有判断，但判断是"可反驳的"。** 不给假精确，给带出处的判断；你可以说它错了。
3. **它的教学方法是数据，不是代码。** 想换一套教法，改的是可读的文本，不是重写程序。

到这里如果他还在听，再讲底层：这三件事都要求一份"不可篡改、可重放"的记录作为事实源。
**这是"怎么做"，只在被追问时讲。**

## 两个好用的类比

| 类比 | 一句话 | 好在哪 |
|---|---|---|
| **病历 vs 聊天记录** | "现在的 AI 学习产品给你的是聊天记录，你需要的是病历。" | 自带全部要点：长期、结构化、可被第三方查看、可以被质疑、跨科 |
| **体检报告 vs 体重秤** | "体重秤给你一个数，体检报告给你指标、参考值和医生的话——而且你可以换个医生再看一次。" | 讲清"带出处的判断"和"可反驳"为什么重要 |

## 不要这么开头

| 别这么说 | 为什么 | 换成 |
|---|---|---|
| "它是一个基于事件溯源的学习 harness" | 听众要先学会三个词才能听懂你 | "它像一个会记事的家教：记得你几个月，而且你随时能反驳它" |
| "一切皆插件，内核只管机制" | 这是实现，听众还在问"这是什么" | 先讲学习者的痛，再讲处方 |
| "支持多模型接入、多模态输入" | 这是功能清单，谁都能写 | 讲一个只有你能讲的具体场景 |
| "L0 到 L4 的抽象梯子" | 听起来像论文 | "越往上是结论，越往下是原话，要证据时可以一路翻回去" |
| "重复造轮子审查：我们只自造四件" | **这其实是你最好的材料**，但它是回答质疑的武器，不是开场 | 留到别人问"这跟 XX 有什么不同"时再打出去，杀伤力最大 |
| 一上来就讲留守儿童 | 情感冲击会盖过你想讲的技术判断，也会让人以为你在讲故事 | 等对方问"这有什么用"再讲，并且要能同时说出上表那几个难点 |

## 一件必须主动说清楚的事

**别把想做的说成已经做成的。** 现在真正跑通的只有最无趣的那一层：
记录、题库、刷题循环；因材施教那部分——它是怎么知道"你是什么样的人"的——还没跑起来。

主动说出来反而加分：

> "现在跑通的是最无聊的那一层：记录 + 题库 + 刷题。
> 我拿它把记录机制和插件机制跑顺了，但真正想做的那层——它怎么了解一个学习者——还没跑起来。
> 所以你要问我有没有用，我自己也还在验证。"

理由很实在：**这一层是谁都能做的，主动承认它，别人才会信你后面讲的那两层是真的。**
而且一旦你藏了，第一个追问就能戳穿，那比不吹更难收拾。
