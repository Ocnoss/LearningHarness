## 摘要

LH（Learning Harness）是一个面向自学者的开源 AI 学习辅助框架。程序形态是**基于 Cordis 插件框架、由宿主 dsh 提供内核机制、由一组 LH 插件编排而成**的 Harness。

| 指标 | 数量 |
|---|---|
| 在运行的 LH 插件 | 7（1 内核 / 1 记录器 / 3 能力 / 2 界面） |
| 模型可调用工具 | 9（题库 8 + 资源索引 1） |
| LH 事件日志条数 | 240 |
| 架构决策记录（ADR） | 30（001–030） |
| 自动闸门脚本 | 8（另有各自的自检） |
| 题库离线断言 | 238 项 |

**一句话结论**：架构与契约层已经冻结并落成可执行约束，运行时已经有一条真实闭环在跑——**「导入题目 → 题库出题 → 作答判分 → 解析与错题统计 → 事件落盘」**。当前瓶颈不在设计，而在两条链路：① 学习者建模（四元组证据 / 断言层 / context compiler）**尚未运行**；② 材料到题库的抽取链还只是"人按记忆跑的手艺"，**不是系统能力**。

## 1. 项目定位与理念层

理念层与架构层已冻结；实现层进行中。

### 要解决的两个核心痛点

1. **上下文管理**——一次学习短则数周、长则数月。学习产品的上下文观是「一段跨越数月的、有结构的成长史」，而不是「一段对话」。
2. **因材施教**——「材」有双面：作为学生的用户（学习者模型）与用户持有的学习资源（资源模型）。匹配是双向的。

### 明确拒绝的两条路线

- **百万上下文力大砖飞**：成本拒绝广大学习者；且 lost-in-the-middle、注意力稀释意味着质量本身随上下文规模退化。
- **硬编码 skills 覆盖教学法**：把教学法知识冻进代码，无法生长、无法被懂教学的人编辑。

### 服务对象与差异化

服务对象是初高中之外的广大自学者（备考 / 技能掌握 / 自我提升），目标高度异构。

> **核心判断**：学习者的异构性（目的、资料、方法、节奏）是问题域的本体，因此教学策略本身必须可插拔——这是采用 Harness 架构的根本原因。
>
> **差异化不在工具，而在编排与约束**：什么时机注入什么信息、允许/禁止模型做什么、记忆怎么沉淀。

### 分层法律（四条）

| 法律 | 内容 | 状态 |
|---|---|---|
| 第一条 | 一切皆插件：内核只负责机制，不含任何教学判断与领域逻辑 | 已冻结 |
| 第二条 | 事实归内核，解释归插件；派生资源必须带血缘回流 | 已冻结 |
| 第三条 | 第 N 层未书面冻结前，禁止讨论第 N+1 层 | 有效但已被第四条约束 |
| **第四条（产品法律）** | **任何时刻，必须存在一条用户可感知的完整闭环在运行。允许被冻结的层次，只能是这条闭环已经走过的层次。** | ADR-011 新增 |

第四条法律是项目的一次自我修正：它把「冻结」的度量方式从"文档想清楚"改成"闭环跑通过"，直接推翻了导致项目停滞的旧规则。

```
┌──────────────────────────────────────────────────────────────┐
│ 宿主 dsh 0.1.1-rc.2（MIT，开发者预览版）· 内核机制            │

├──────────────────────────────────────────────────────────────┤
│ Cordis（依赖注入 / 服务定位容器）· 插件框架                   │
│ 服务定位 + 声明式 inject + 生命周期 + 可逆副作用 ctx.effect    │
├──────────────────────────────────────────────────────────────┤
│ LH 层 = 事件词汇表 + 插件 + 契约                              │

└──────────────────────────────────────────────────────────────┘
```

Cordis 换来三件事：可替换性（换 LLM 实现不改消费插件）、加载顺序自动解析、**测试替身免费**（golden scenario 中换假 LLM 服务、内存事件存储 → 系统确定性化）。

### 插件编排的两个作用域（决定一切写法）

| 作用域 | 位置与能拿到什么 | 成员 |
|---|---|---|
| **agent preset 作用域** | `$DSH_HOME/.agent-presets/lh/agent.cordis.yml`。能拿到 `ctx.llm` / `ctx.systemPrompt` / `ctx.tools` / `ctx.sessions`；**够不着** host 面发布的服务（如 `webServer`） | event-store、recorder-trace、resource-indexer、model-tier、question-bank |
| **profile 作用域** | `$DSH_HOME/profiles/<名>/`。能用 `webServer` 注册 HTTP 路由；改服务端插件**必须重启 dsh** | practice、theme |

> **最容易致命的一条**：插件加载失败会让**整棵插件树加载失败、dsh 完全无法启动**——学习者面对的是一个加载失败的界面，连"该配什么"这句话都看不到。因此纪律是：**先证明"不会起不来"，再证明"逻辑对"。顺序不能反。**

### 宿主约束（16 条实测行为，写下来省得重查）

架构宪章 `§0.1` 记录了一批"实测行为"而非"公开 API"。最具决定性的几条：

| # | 约束 | 后果 |
|---|---|---|
| 1 | 宿主会话日志的词汇表对外部插件**封闭**——写自定义事件类型会让会话重载失败 | LH 事件必须自持 |

| 15 | profile 插件的 `apply()` 抛错 = dsh 起不来 | 装载期不许抛错，配置缺失改成"用的时候拒绝" |

## 3. 内核契约（`LH内核契约-v0.1.md`）

定位：内核语法 + 不变量 + 验证方法。一切需要"判断"的事物不归它管——它们属于插件。

### 总原则

- **内核拥有语法，插件拥有判断。**试金石：它做的是格式约定还是内容裁决？
- **事件溯源为基座。**append-only 事件日志是唯一事实源；一切状态是日志的投影。
- **写细读粗。**写入端往细记（"没记"不可逆），读取端由投影定义粗粒度。
- **内核连「什么值得记」都不知道。**记录器是插件；发行版有立场，内核保持无知。

### 内核五概念（其余皆是插件）

| 概念 | 一句话 |
|---|---|
| **节点（课程树）** | 课程节点 = 作用域 + 自己的事件日志 + 自己的 agent + 自己的建模插件 + 自己的策略集；节点间只有父子关系。深度纪律：先冻结三层（元课程 / 课程 / 会话） |
| **事件** | 统一信封：`id` / `timestamp` / `schema_version` / `actor` / `type` / `provenance` / `session_ref` / `scope` / `content_ref`。演进纪律：**只做加法** |
| **投影** | 投影是插件；原始的可重放，派生的可重算。抽象梯子 L0 操作 → L1 交互 → L2 证据 → L3 断言 → L4 决策 |
| **Handoff** | 一等事件 `HandoffInitiated`：父节点 agent → 子节点 agent，带交接上下文包。**导师递条子，不代课** |
| **Agent 注册表** | 区分持久 agent（有身份、有事件流）与一次性 function call（无身份）。默认任何插件只能读自己作用域的事件 |

### 三个承重的领域设计

**① 用户侧四元组：answer / ask / interpret / explain**

全部是**生成性行为**（generative acts）——测量的是生产而非暴露，理论支撑来自 self-explanation effect、generation effect、learning by teaching 与 ICAP 框架。证据强度阶梯：**explain > interpret > ask > answer**。进度条 / 清单测量暴露，落于最低级。

> **反奖惩立场**：生成行为停滞时**把数据显示给用户**（显化），而非扣分——因为奖惩挂生成行为会触发 Goodhart 定律且可被 AI 代写作弊。

**② L3 断言层：不做确定性画像**

不做「掌握度 72%」，做**带出处和置信度的断言集**：

> 「系统认为用户在极限计算上薄弱；依据：事件 #341、#389；置信度：中。」

两个性质：**可审计**（每条判断回溯到证据）、**可争议**（用户反驳本身是极高质量的学习事件）。信息沿树向上流动，且只以 L3 断言形式流动；原始事件永不跨作用域。

**③ L4 策略层：策略作为数据，教学动作强制携带预测**

策略 = 声明式片段（自然语言描述 + 适用条件 + 约束 + 预期产出），由模型在运行时解释执行。懂教学不懂代码的人可编辑策略；坏策略被数据淘汰。

每个教学动作事件**必须**携带：目标断言、预期证据、时间窗。策略评估 = 假设检验：动作是干预，学习者模型是测量仪器，后续事件流是观测数据。**测量仪器质量是策略评估的天花板。**

### 验证方法

**八条不变量（每条配可执行检查）**：两次重放结果一致 / 上下文组装不得超预算（超预算走降级，不得截断）/ 每个教学动作携带预测字段 / 插件只能追加不得直写投影 / 资料删除后派生状态无痕迹 / 原始事件不跨作用域 / 全部历史事件在新 schema 下仍可重放 / 事件永不迁移节点。

**五个黄金场景（端到端）**：中断回归（中断 18 天后"我们继续吧"）、跨课程调度（handoff）、资料生命周期、分类器升级重放、用户争议断言。

## 6. 数据与事件现状

### 事件日志 `data/events.jsonl`

| 事件类型 | 条数 | 含义 |
|---|---|---|
| `lh/trace/observed` | 218 | 宿主会话语义事件的坐标索引（记录器产出） |

| `lh/resource/indexed` | 4 | 资源索引产出 |
| **合计** | **240** | 自 2026-09-16 起；actor 分布：agent 222 / human 18 |

词汇表目前只有 3 个类型——四元组分类事件、断言事件、策略事件、handoff 事件都还没有生产者。

### 题库数据：必须知道的三处缺陷

工作区那份 49 题题库（`考公刷题-片段阅读与逻辑判断.json`）是**两份资料合并**的（片段阅读 20 题 + 逻辑判断 29 题），两份题号都从 `set1-q1` 开始，**跨资料会撞车**。另有三个具体缺陷（都还没修）：

1. 它**从未经过 `import_questions`**，所以事件流里没有它的 `lh/resource/questions-imported`；
2. 它的 provenance 指向 `@lh/extractor` —— **这个插件不存在**（是脚本直接落盘时写下的）；
3. 它的 `topics` 只有 **13/49** 道有值（试点产物缺文件出处，只能保守匹配）。

第 3 条背后是一次代价很高的教训（ADR-021 结论八）：**产物没有稳定标识，等于没产出。**试点产物只记 `set1-q1` 这种"资料内编号"，没有文件名、没有题干，于是按题号匹配会把片段阅读的知识点写到逻辑判断的题上——**不报错、只是全错，而且事后无法从产物里发现。**最终 49 道只有 13 道能安全写入，其余如实留在报告里。

### 抽取链成本实测（决定"2400 题入库"能否立项）

## 7. 工程治理体系

这套东西是项目最独特的部分：它把"开发过程本身"也当成要被建模的对象。

### 三类记录，各司其职

| 载体 | 回答什么 | 形态与数量 |
|---|---|---|

### ADR 六项必填

验收标准：**一个不具备本次对话完整上下文的读者——包括另一个模型——读完这条记录，应当能重建出合理的解释。**

1. 决定了什么（一句话，可执行）
2. 当时有哪些别的选择（至少两个，包括"什么都不做"）
3. 为什么排除别的（真实理由，不是事后合理化）
4. 依赖什么前提 / 假设（前提塌了，决策就要重审）
5. **怎么知道它错了**（可观察的信号）——最容易省也最重要：**没有失效信号的决策不是决策，是信念**
6. 证据在哪（文件路径、代码行、命令输出、外部链接）

### WORKFLOW v0.4：人做判断，AI 做其余

- 人的提问权**没有上限**；AI 不得因为"这会增加认知负担"而不回答。
- 一个工作单位最多一个目标；一次交付不超过 **3 个待回应项**（选项必须带后果与推荐，说不清后果就别端出来）。
- 分段依据是**任务的客观难度**，不是墙钟时间或对话轮数；可观察但不设时间上限。
- **破坏性操作一律白名单**——只允许"明确列出要删的东西"，不允许"删掉所有不匹配的"。
- **不阻塞记录**：未决是禁止状态，"临时答案"是合法状态。

### 协作者模型：把"AI 对这个人的感知"写成可反驳的断言

WORKFLOW §6 与内核契约 §4.1 是同一套规矩的自我应用——**LH 的学习者模型该怎么长，先在作者身上长一遍。**`COLLABORATOR_MODEL.md` 现有 A1–A9（能力与状态）、B1–B18（协作偏好）、C1–C22（AI 自己的错误，必须留痕供核对可靠性）、D1–D7（低置信度猜测）、E1–E18（行为准则）。每条带出处、置信度、可推翻条件。

> **其中一条被反复验证、也最能说明项目气质**：作者的纠正系统性地指向同一个问题——**「这个决定该由谁拥有？」**AI 的默认倾向是"系统替用户做安全选择"（工程习惯），作者的默认倾向是"**把选择权和后果交给用户，系统负责把后果说清楚**"。这与内核契约 §3.1 的反奖惩立场是同一个原则——**他的工程判断与他的教学理念是同源的。**

### 八道自动闸门（+ 各自的自检）

| 脚本 | 拦什么 | 关键设计 |
|---|---|---|
| `check-plugin-imports.mjs` | 安装后的包能否被 import | import 的是 profile 里的**副本** → 走生产路径 |
| `check-profile-apply.mjs` | 插件的 `apply()` 会不会抛错 | 记账式假 ctx 真跑一遍 |
| `check-client-inject.mjs` | 客户端 bundle 的 `ctx.<服务>` 是否都声明了 | 手写状态机剥注释与字符串 |
| `check-preset-mount.mjs` | preset 行能否加载、工具 schema 是否合规 | 用宿主的 `assertSupportedJsonSchema` |
| `check-installed-copies.mjs` | **副本是不是旧的**（"测过了"是不是真的） | 按 `files` 比对，**拒绝自动推断** |
| `check-paths-resolution.mjs` | 同一问题从每个加载位置问，答案一不一样 | 子进程 + 干净环境；**答案不一致比答案错更难发现** |
| `check-hardcoded-paths.mjs` | 写死的盘符 | 例外要带理由，且一处一个 |
| `check-plugin-contract.mjs` | 声明（`lh` 字段）与实现是否一致 | ADR-024 自我描述的可验证化 |

> **闸门的边界（必须知道，否则会变成假的安全感）**：它们证明的是"能 import / apply 不抛错 / 声明齐全 / 副本是新的 / 路径一致"，**不能证明宿主真的会这样调度，也不能证明逻辑对。最终仍需要一次真启动。**
>
> **而且：闸门自己要先对着"已知坏的状态"红一次，才算被验证过。**已有一条反直觉推论被写进契约：把"装载期抛错"改成"用的时候拒绝"会让某道闸门**变绿而底层仍然是坏的**——所以改掉一个错误行为时，要同时问"原来是谁在替我报警"，并把这个警报器补回来。

## 8. 决策时间线

11 次提交 / 30 份 ADR，六个开发日的密度。

**2026-09-15 · 宿主转向：内核自研终止（ADR-011）**
原路线（先写内核 loop/registry/context）的实践结果是"内核被写出来了，但没有任何面向学习者的可用功能，而 ADR 累积到十份"。根因是第三条法律让"未完成"成为稳定状态——**不是能力问题，是度量方式问题**。决定：内核机制采用宿主 dsh；LH 资产是词汇表 + 插件 + 契约；新增**第四条产品法律**；第一个用户是作者本人。同日建立协作者模型与反馈机制。

**2026-09-16 · 外观边界与模型档位**
ADR-013：壳级前端推迟，采用"只在 LH 会话内改外观"作为临时边界；客户端扩展一律走宿主正式接口，不用固定定位之类的旁门。ADR-016：档位建议而非要求——风险告知即可，不该让 agent 一直拒绝服务。

**2026-09-17 · 题库的对象与接口（ADR-017 / 018 / 019 / 020 / 021）**
作者给的是一条**顺序**而不只是目标："先搭起来行为的对象和接口再去对行为分类"。确立了"题目是资源、作答是事件"；题解带来源；**LLM 的答案绝不进判分路径**（红线）；"入库前的 LLM 预处理"——不把 LLM 当分块器，而当成预处理与独立第二意见。

**2026-09-18 · 四次"dsh 起不来"与随之而来的治理升级**
连续四次宿主完全无法启动（相对路径跨层引用、客户端 inject 未导出、list 插槽缺 id、dev 环境非隔离）。作者的反应不是"别再动了"，而是提出 `lh-plugin-develop` 要管这类问题、并提出"克隆一个 dsh 做开发/测试隔离"。同日产出 ADR-023（版本控制范围 + **启动包装器**代替哨兵插件——"一个和病人绑在一起的心脏除颤器，在病人心脏停跳时也一起停了"）、ADR-024（部署流程 + 每插件一份机器可读自我描述）、ADR-025（**装载期不许抛错**）、ADR-026（外观由 agent 声明意图）。

**2026-09-19 · 刷题循环闭环 + 知识点词表 + 视频证据源**
刷题循环落地（ADR-019/022）：卡片入口、面板取题、"刷题走哪条路"的运行时上下文（order 117）。知识点两轴封闭词表落地（题型 17 项 + 领域 5 项，认不出的标签如实回报为 `unmapped_topics`）。ADR-027：视频是**有时间索引的证据源**，不是一段待总结的素材——一期只做元数据/标签/字幕/评论，视觉与 ASR 推迟且须先证明"不用它也能用"。

**2026-09-20 · 抽取链两侧分工 + LH 会话带上基础能力**
ADR-028：题目 id 全局唯一（`练习题01-q1`），根治跨资料撞车。**ADR-029**：题本归模型（读 + 改错 + 独立作答），解析归规则（答案印在纸上，规则抽得准、可复现、零成本），模型作答只作交叉验证——实测证明它是当前**唯一**能抓到"答案块错位"的仪器。**ADR-030**：LH 会话带上 standard preset 的基础能力，**分两批**——第一批 8 行（shell / 文件 / 搜索 / web 等，不需 isolate realm）已落地待真会话验证；第二批（planning / compaction / delegation）需 isolate realm，因失败面不同而刻意分开，未做。

## 9. 已知风险与缺陷

| 类别 | 内容 |
|---|---|
| **宿主依赖风险** | dsh 是开发者预览版，README 明确将有破坏性变更，已有移除 SQLite 后端的先例。LH 的插件大量依赖 **16 条"实测行为"而非公开 API**；锁定 npm 版本防不了"升级时没意识到某条实测行为没了" |
| **题库数据缺陷** | 工作区那份 49 题从未经过 `import_questions`；provenance 指向不存在的 `@lh/extractor`；`topics` 只有 13/49 有值；两份资料题号撞车（已由 ADR-028 定下修法，未实施） |
| **界面作答缺坐标** | `lh/user/attempt` 的 `session_ref` 与 `context.seq` 都是 `null`——HTTP 路由没有会话上下文。日志里有"谁、何时、答了哪道题、对错如何"，但**没有**"这次作答属于哪场对话"。临时答案：显式留空，不编坐标 |
| **产品立场待决** | 第一批基础能力把 shell 交给了 LH 会话。**"给学习者会话一个 shell"在别处是否可接受是一个产品决策**——记的是"在这一步上选了要"，不是"这件事永远对"。且能力给了之后，如何隐藏 dsh 的开发表达方式尚未解决 |
| **手艺 vs 系统能力** | 抽取链（survey → pair → OCR → 旋转 → 对齐 → 抽答案 → 分块入库）**只有脚本，agent 调不到**，只能由人按记忆依次执行 |
| **词表扩张无纪律** | 两轴封闭词表已落地，但"加词"的判据与流程未定：新词必须在真实题目里出现过；谁有权加词、加了之后历史断言怎么处理，未决 |
| **学习者建模空白** | 四元组分类、断言层、context compiler 的真实注入内容、策略层——**全部尚未运行**。这是项目的技术护城河所在，也是当前最大的"零" |
